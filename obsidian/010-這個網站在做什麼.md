# 這個網站在做什麼

每天盤後在 GitHub Actions 自動抓免費合規的資料 → 算指標 → 產出一個靜態網站。
它只回答四個問題，而且**順序是刻意的**：

| # | 問題 | 誰回答 | 為什麼排在這個位置 |
|---|---|---|---|
| 1 | **錢往哪個族群跑？** | M1 資金面 | 先看錢往哪去，才知道要研究誰 |
| 2 | **那個族群現在貴不貴？** | M2 基本面 | 錢去了不代表可以追，要先看估值撐不撐得住 |
| 3 | **什麼時候進場？** | M3 技術面 | 方向對了才輪到談時機 |
| 4 | **有沒有理由不進場？** | M4 事件面 | 最後一道否決：減資、訴訟、財報更正、重大處分 |

**M1＋M2 決定方向 → M3 決定時機 → M4 否決。**
把順序倒過來（先看線型再找理由）就是這個網站刻意不做的事。

## 幾個貫穿全站的原則

- **紅漲綠跌**（台股慣例，跟國外套件預設相反）
- **查不到出處的關係一律不畫**，讓節點留一個「?」。畫錯一條線比留一個問號糟糕得多
- **樣本不足就留白**，不印一個看起來精確但其實是猜的數字（族群成員少於 3 檔就不算中位數）
- **推論要標明是推論**：供應鏈的每條關係都有 `confidence`
  —— `verified`（官方文件／重訊等級）、`reported`（兩個以上獨立媒體）、`estimated`（產業邏輯推論，一定附來源）
- **只用免費且合規的來源**。不爬使用條款禁止的端點，不爬券商分點

## 運作方式

```
GitHub Actions（雲端，每天自己跑）
  ├─ 每日盤後管線   台北 15:30 / 18:30 / 21:30（週一~五）
  │    15:30 那輪只抓價量；官方資料還沒出來就用即時報價暫代
  ├─ 歷史回補       每小時一輪，補齊就跳過
  └─ 部署網站       程式或資料有變動就重算 JSON 並重新部署
```

Andy 只要**重新整理網頁**就好，不需要在本機執行任何指令。
程式由 Claude 推上 main，資料由 Actions 自己 commit。
