## 2. 901～1100 要不要兩欄（量完才決定）

三種排法都做出來量（同一支 measure.py）：

| 寬 | 改前（單欄） | A：901～1100 兩欄、輪盤高＝欄寬 | B：單欄、排行限高 | C：兩欄、輪盤高 0.8 × 欄寬 |
|---|---|---|---|---|
| 1100 | 第一屏 37.8／整頁 25.7／頁高 3254 | **47.5**／24.9／**2746** | 37.8／26.0／3155 | 32.6／21.0／2627 |
| 1000 | 41.6／26.1／3254 | 41.2／21.7／2948 | **41.6／26.4**／3155 | 33.3／19.2／2847 |
| 901 | 46.2／26.5／3254 | 34.0／19.0／2940 | **46.2／26.7**／3210 | 34.0／19.0／2900 |

- C（第一批原型的做法）三個寬度都退步 → 不上，跟 02 文件量到的結論一致。
- A 在 1100 大贏（第一屏 +9.7、少半屏多），在 1000、901 退步。原因看得到：輪盤欄 < 560px 時切成「編號模式」
  （盤上只寫編號、名字列在盤下一整塊清單），清單把左欄撐高、排行跟著拉長，盤卻變小。
- 所以分界放在「輪盤欄還寫得下名字」的地方：輪盤欄＝(視窗 − 頁邊 32 − 卡片內距 32 − 欄距 12) × 1.4 ÷ 2.4 ≥ 560 → 視窗 ≥ 1036；
  再扣桌機捲軸 15px 還要站得住 → **1060**。1060～1100 兩欄、821～1059 用 B（單欄、排行限高）。

### 3.4 怎麼讀

1. **1280 是最大的贏家（第一屏 +12.5）**：輪盤高從 0.8 × 欄寬改成欄寬，盤半徑 267 → 318；頁高多 82px 是盤變大換來的（整頁繪圖區 22.8 → 28.1，換得值）。
2. **1100／1060 兩欄**：第一屏 +9.2／+5.0、頁高少 530～560px（少一屏多要捲）。代價：盤半徑 306 → 284／273，排行從 1034 寬變成 426／409 寬（族群名截斷、長條末端只寫佔比變化，期間報酬在提示框 —— 跟 1280 兩欄同一套規則）；
   整頁繪圖區比例 25.7 → 25.0、25.8 → 24.1（兩欄時排行的繪圖區變窄）。第一屏與頁高都進步、整頁比例小退，判斷上線（見 §5 第 1 點）。
3. **1440 第一屏 +2.5**：小標併行省 25px → 還給輪盤（上限 640 → 664），盤半徑 304 → 318，卡片總高 826 → 829 幾乎不變。
4. **資金去向右側空帶**：1440 沒滑過時 271 → 151px、滑過時 101 → 13px。**≤1100 反而多 4px**（改前那一段退路右緣只留 4px，規格是 8px），寫在這裡不藏。
5. **1040 以下第一屏持平**：單欄時輪盤本來就是 640 高的完整一屏，這一段只省頁高（-69～-99px）。800／390 沒動（手機歸 mobile-ui）。
