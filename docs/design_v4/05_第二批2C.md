## 2. 做法（為什麼這樣改）

1. **就地改值，不另寫覆寫**。另寫一份覆寫要複製選擇器，而且覆寫一律寫在最後 → 會蓋掉原本「同特異度、寫在後面所以贏」的規則，層疊順序整個亂掉。
   就地改值，層疊結構一條都不動。
2. **寫成 theme4.css 的尺度變數**：4→`var(--sp-1)`、8→`--sp-2`、12→`--sp-3`、16→`--sp-4`、24→`--sp-5`；同一條宣告裡原本就在尺度內的 px 一起寫成變數（一眼看得出是同一套）。
   `index.html` 的 `:root` 也放一份同值的 `--sp-*`，`<html>` 沒掛 `data-theme4` 也解得出值。
3. **手機一屏版（≤640）不動**：會涵蓋到 ≤640 的規則（沒有 @media、或 max-width ≥ 641 的），改完之後**緊接在那條規則後面**補一行
   `@media (max-width:640px){ 同一個選擇器{ 原值 } }`。緊接在後面＝層疊順序跟原本一樣，手機算出來的值逐字相同 —— 390 寬八頁像素比對 **0.00%** 證明了這件事。
   手機那一批（mobile-ui）要改用 v4 尺度時，把這些行刪掉就好（index.html 290 行、theme4.css 6 行，都是單獨一行、以 `@media (max-width:640px){` 開頭，緊接在它保護的那條規則後面）。
4. **對應規則**（每個值各自判斷；平手一律往密的方向 —— Andy 的痛點是「間隔太大導致圖被壓縮」）：
   - 4.5／5 → 4、7／9 → 8、11／13 → 12、15 → 16、22 → 24（最近的一階，±1～2px）
   - 6 → 4（padding／margin／row-gap）；**gap／column-gap 的 6 → 8**（01 §2.1「控制項之間 8」）；gap 兩個值時第一個（列距）→ 4
   - 10 → 8、14 → 12、18 → 16、20 → 16
5. 機械轉換：`docs/design_v4/tools/spacing_apply.py --src <改前 site> --dst site --values …`，可重跑；`--skip-lines` 可以把量出來退步的宣告排除（這一批沒有用到）。

### 3.3 怎麼讀

1. **沒有任何一格退步**（門檻：第一屏 -0.3 個百分點、頁高 +5px、空白帶 +0.3）。資金流向 1440／1100 第一屏 -0.1／-0.2：頁高各少 18／20px、卡頂→圖少 2／4px，
   輪盤高＝欄寬、欄寬沒變，所以盤本身不會變小；比例小退的原因**沒有追到**（`measure.py` 沒開減少動態，ECharts 還在動畫中量到也有可能），在門檻以內，照上。
2. **最大的進步在個股頁**：1440 第一屏 +0.8、800 +1.0，卡頂→圖 261 → 253（K 線卡標題區裡的資訊小標、工具列間距收小）。
3. **頁高全部變矮**：-2～-24px。間距收斂本來就不是「省一大塊」的改動（大塊的在第一批與 2A／2B），這一批的價值是「一套尺度」—— 之後新寫的樣式有規可循，不會又冒出第四種 6／10。
4. **390 全部 ±0**：手機一屏版刻意不動（見 §2 第 3 點）。
5. **第一批單獨上會退步**：只收 ±1px 那批時，半導體產業鏈 800 寬頁高 +13、剖析圖說明「先進節點（N3／N2／A16）台股只有 2330…」多換一行
