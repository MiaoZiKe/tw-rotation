## 1. 量法（改前、改後同一支）

工具：`docs/design_v4/tools/measure.py`（原始數字 `docs/design_v4/data/*.json`，表格由 `tools/report.py` 產生）。
視窗：桌機寬 × 900 高；390 用手機模式（390 × 844、觸控）。深色主題、預設狀態（沒點任何東西），等圖畫完 3.5 秒再量。

| 指標 | 怎麼量 | 為什麼選它 |
|---|---|---|
| **第一屏繪圖區 %** | 圖表**繪圖區**面積 ÷ 視窗面積。繪圖區＝ECharts 直角座標的 grid 矩形（不含軸字、圖例）、極座標取外接正方形、桑基／樹圖取 series 版面框、Lightweight Charts 取窗格（不含價格軸與時間軸）、大張 SVG 取整張；只算落在第一屏的部分，重疊的只算一次 | 「圖被壓縮」最直接的數字：打開頁面、還沒捲動時，眼睛看到的有多少是圖 |
| **整頁繪圖區 %** | 全部繪圖區 ÷（視窗寬 × 捲動高度） | 整頁的密度；捲很長但圖很少＝浪費 |
| 內容寬 | `main` 的實際寬度 | 扣掉右側「今日事件」欄之後剩多少 |
| 卡距 橫／直 | 相鄰卡片之間的水平／垂直距離（中位數） | |
| 卡片內距 | `.card` computed padding（上／左） | |
| **標題負擔** | 卡片頂端 → 卡片裡第一張圖的頂端（中位數） | 標題列＋篩選列＋說明吃掉的高度 |
| 空白帶 % | 在「目前這一頁」（`.view.on`）範圍內，整列沒有任何東西、連續 ≥ 24px 的橫帶總高 ÷ 頁高 | 卡片之間、區塊之間的純空白 |
| 空白格 % | 內容區切 16×16 方格，格內像素全部同色的比例 | ⚠ 會把實心色塊（熱力圖的一格、圖表底色）也算進去，只能**同一頁改前改後比**，不能跨頁比 |
| 最浪費的地方 | 空白格裡最大的一塊全空矩形 → 截圖畫紅框 | §4 |

⚠ 量不到的：互動之後才出現的東西（下拉、放大視窗、側欄面板、事件欄打開時）。只量了**初始畫面**。

### 5.2 讀法

- **1440 與 1100 是主戰場，改善最大**：第一屏繪圖區九頁平均從 35.3% → **50.2%**（1440）、30.6% → **47.6%**（1100）；800 是 44.7% → 45.5%、390 是 32.3% → 32.5%。
  單一頁最大的是資金流向 1440（21.3 → 45.9，**+24.6**）與熱力圖 1100（41.4 → 70.9，**+29.5**）。
  主因依序是：① 事件欄收成浮層（內容寬 1080 → 1440、740 → 1100）② 卡距 24 → 12、內距 20 → 12/16 ③ 標題負擔下降（資金流向 153 → 104、215 → 142）。
- **1100 的頁高大幅變短**：總覽 3404 → 2127（−37%）、資金流向 3352 → 2645、單一產業鏈 3395 → 1967 ——
  因為 901～1100 不再退成單欄（輪盤不再被撐到 700px 高），同一屏放得下兩欄。
- **單一產業鏈 1100 的 528px 空白尾巴消失了**（空白帶 20.2% → 0）：事件欄收成浮層後就不見 —— 推估是事件欄那一欄把格線列撐高，但**沒有逐元素查證**。
- **800 寬幾乎沒變，甚至略降**（總覽 −2.4、資金流向 −1.2）：800 本來就沒有事件欄，v4 在這個寬度只收了內距（16/18 → 12/14），
  而新增的「一句結論」每張卡多 28px（標題負擔 91 → 115）。**這是用 28px 換一句結論的取捨**，列在回報的「可能不同意」。
- **390 手機不變**（±1.4 以內）：手機一屏版刻意沒動（歸 `mobile-ui`，而且另一位 agent 正在改手機按鈕）。
- **週期統計 1440 第一屏沒變（31.1）**：它的月份格子是固定寬，內容區變寬只是右邊空帶變寬（§4 那一格），要到實作第 6 批改成 `1fr` 才會改善。
