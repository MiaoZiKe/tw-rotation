# 族群同業估值位階（P-1107-04）—— 口徑

Andy 2026-11-09 點頭「02 05 03 04 06」。提案：`docs/feature_proposals/weekly_2026-W45.md` P-1107-04。
程式：`pipeline/compute/peerval.py`（產 `site/data/peer_val.json`）、`site/peerval.js`（畫）、`tests/test_peerval.py`、`scripts/uitest_sections/20261109_族群估值位階.py`。

## 回答什麼
同一個族群裡，這一檔的估值落在同業哪個位置。**只陳述位置**（第 N 百分位、族群中位數），不寫「便宜可買」「高估」。

## 資料（不新增來源，全是 build_payload 已算好的）
| 欄 | 來源 | 定義 |
|---|---|---|
| 本益比 | fundamental.json `pe` | 收盤 ÷ 近四季 EPS（上市上櫃同口徑，自算） |
| 淨值比 | fundamental.json `pb` | 收盤 ÷ 每股淨值（≤0 不給） |
| 殖利率 | explore.json `dy` | 近四次現金股利 ÷ 收盤（＝個股頁「殖利率（近四次）」）；沒有配息資料給空，不當 0 |
| 營收 YoY | fundamental.json `rev_yoy` | 最新月營收年增（yoy_adj） |
| 自身歷史 | explore.json `pe_pct`／`pe_n` | 目前本益比在自己近 5 年各季本益比的中間名次百分位；少於 12 季（3 年）不給 |
| 族群 | groups.yaml（含疊加族群） | 不在任何族群的普通股 → 法定產業別桶 `ind_<產業>`（同業＝同產業別、也不在任何族群的普通股，跟 fundamental 的 ind_ 桶同一群；只給個股頁小卡） |

## 寫死的規則
1. **同業百分位＝同業有效樣本裡比它低的檔數 ÷ 有效檔數 × 100**（最低＝0；5 檔裡最高＝80）。跟個股頁基本面卡「同業分位 N%」（fundamental._pct_within）同一個公式。
2. **有效樣本 < 5 檔不算百分位**，畫面寫「同業樣本不足」。中位數同樣 < 5 檔不給。
3. **虧損（近四季 EPS ≤ 0）**：不給本益比、不排進同業，寫「本益比不適用（虧損）」。EPS 沒資料寫「—」。
4. **本益比 < 3 或 > 200 倍**（EPS 接近 0 的失真值，門檻＝fundamental.PE_MIN／PE_MAX）：照印數字、不排進同業，寫「失真不排名」。
5. **方向**：本益比、淨值比、營收 YoY 數值越大百分位越大；**殖利率反過來**（存「殖利率由高到低」的位置，殖利率最高＝0），所以四條估值條同一個方向：左＝同業估值最低、右＝最高。營收 YoY 不是估值，用中性色。
6. 表格預設**依代號排序**（提案法遵段：不預設依估值排，避免看起來像推薦清單）；使用者自己點欄名才排序。
7. 顏色不用紅綠（紅綠是漲跌）：估值青、自身歷史紫、營收 YoY 灰。

## 已知的不一致（刻意保留）
- 金融族群（`valuation_metric: pb_roe`，例如 bank）：個股頁基本面卡的「同業分位」是**淨值比**的分位，這張表的「本益比」欄是本益比分位；淨值比欄才對得上。
- 基本面卡的同業分位在 3～4 檔時也會給（標 *），這張表 < 5 檔一律不給。
- 自身歷史：這張表用**每季**本益比（explore），個股頁基本面卡的本益比條用**每日**本益比，兩個數字可能差幾個百分點；所以個股頁小卡不放自身歷史，只在族群表放。
