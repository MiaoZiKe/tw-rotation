1. **〔紅線一・最重要〕收費這件事，法律風險遠大於技術風險。**
   《證券投資信託及顧問法》§4＋§107：**以收取報酬的方式、對不特定人經常性提供
   證券分析意見或推介建議**，未經金管會許可即屬非法經營證顧業務，
   **五年以下有期徒刑、併科 100 萬～5,000 萬罰金**（信心：高）。
   我們的「今日候選」「技術評分」「進場時機」「事件否決」**正好落在這個定義的核心**。
   免費時風險低（缺「報酬」要件），**一旦收訂閱費，風險性質就變了**。
2. **〔紅線二〕GitHub Pages 的使用條款明文禁止**拿它當免費主機經營線上生意、電商或商業 SaaS；
   **但明確允許捐款按鈕與群眾募資連結**（信心：高）。
   → 收訂閱費就**必須搬家**；走贊助制則可以留在原地。
3. **〔紅線三〕資料授權是四個來源分開的結論，不能一概而論。**
   證交所 OpenAPI／櫃買 OpenAPI／集保股權分散表 ＝ **政府資料開放授權條款第 1 版，
   明文允許商業利用與再授權**（信心：高）→ 這三個**可以收錢**。
   **Yahoo 明文禁止商業用途**（信心：中高）→ **要收錢就得先把 Yahoo 拔掉**（我們拿它抓分 K）。
   FinMind 商用再散布條款、`mis.twse.com.tw` 即時報價的授權 ＝ **未確認**。
4. **對照表結論**：Tide 有 11 項功能、我們有 8 項；StockIntelli 有 14 項、我們有 6 項。
   我們**獨有**的有 5 項（四問判斷順序、27 張產業鏈剖析圖、19 個 3D 場景、
   供應鏈關聯圖、多週期 SMC）。
   **我們缺的 9 項**裡，6 項做得到，**3 項在現有架構下做不到**：
   推播通知、跨裝置同步的自選股／投資組合、券商分點籌碼。
5. **最大的弱勢不是功能，是「一個人 ＋ 沒有護城河 ＋ 公開原始碼」**。
   repo 是 public，**任何人可以整包 clone 走**（含我們的 `groups.yaml`／`supply_chain.yaml`／
   27 張剖析圖原始碼），這是我們投入最多、也最容易被搬走的東西。
6. **沒有品牌、沒有流量、沒有帳號**。Tide 三、四個月做到一萬多個註冊帳號（信心：中高），
   我們是 0 —— 因為我們根本沒有「註冊」這件事，也就沒有任何一個可以再次接觸到的使用者。

# ② 我們的優勢

**規則**：每一條都要回答「**別人要多久才追得上**」。追得上的時間短，就不是護城河，是暫時領先。

## 優勢一：四問的判斷順序，而且順序本身是產品

**〔事實〕** M1 資金面 ＋ M2 基本面決定方向 → M3 技術面決定時機 → M4 事件面否決。
這個順序寫進了 `pipeline/build_payload.py` 的流程、`compute/` 的模組切分、
以及前端的分頁結構（信心：高，讀原始碼）。

**〔事實〕** Tide 回答的是「錢往哪裡跑」（板塊分四區 ＋ 泡泡圖 ＋ 籌碼排行），
搜尋摘要裡**沒有出現任何「什麼時候進場」或「有沒有理由不進」的功能**（信心：中，
二手摘要，不排除有而摘要沒提）。

**〔判斷〕Andy 的判斷我驗證後**：**部分成立，但講法要改。**

- ✅ 成立的部分：**Tide 確實只回答第一問**（就我查到的資訊範圍內）。
- ⚠ **要修正的部分**：說「我們走完四問」會被打臉 ——
  **M4 事件面目前只做到「季節性」與「重大訊息入庫」**
  （`build_payload.py:258` 的 lap 名稱就叫「M4 季節性」，權重 0.05）。
  **我們沒有一個使用者看得到的「否決」動作**：畫面上沒有「這檔今天有理由不進」的紅字。
  → **這是一個空洞的優勢，除非我們把它做出來。**

**別人要多久追得上**：

# ④ 定價與功能分層

## 4-0 先回答三條紅線 —— **不先回答這三條，下面的價格都是空談**

### 紅線一：法規。**這條比資料授權更致命，而且 Andy 的題目裡沒有提到它。**

**〔事實〕《證券投資信託及顧問法》**（信心：高，來源：全國法規資料庫、立法院研究報告）

- **§4**：凡**提供他人買賣證券之建議而獲取報酬**者，屬證券投資顧問業務，
  **以收取報酬為前提要件**。
- 實務見解：「行為人以**招收會員、收取報酬**等方式，**對不特定人**…
  **經常性提供分析意見或推介建議**，即屬經營證券投資顧問業務。」
- **§107 第 1 款**：未經主管機關許可經營證券投資顧問業務者，
  **處五年以下有期徒刑，併科新臺幣 100 萬元以上 5,000 萬元以下罰金**。

**〔判斷〕我們踩在線上的功能**（照原始碼點名）：

| 功能 | 風險等級 | 為什麼 |
|---|---|---|
| `candidates.json`「**今日候選**」 | 🔴 **高** | 「候選」就是推介標的。這是最像「推薦買什麼」的一項 |
| `technical_score()` 技術評分 | 🟠 中高 | 給分 ＝ 排序 ＝ 隱含推介 |
| M3「決定時機」 | 🔴 **高** | 直接就是「什麼時候進場」 |
| M4「否決進場」 | 🟠 中高 | 「不要進」也是建議 |
| 原始資料呈現（法人買賣超、集保、營收） | 🟢 低 | 這是**呈現公開資料**，不是分析意見 |
| 產業鏈剖析圖 | 🟢 **低** | 這是**產業知識**，不是證券分析。**這也是為什麼剖析圖是最適合收費的東西** |

**〔判斷〕結論**：
1. **免費提供** ＝ 缺「報酬」要件，風險顯著較低（但仍建議加免責聲明）。
2. **一旦收訂閱費，「今日候選」與「進場時機」就是最危險的兩項。**
3. **如果要收錢，安全的順序是**：
   先收**產業知識**（剖析圖、供應鏈圖）與**工具便利性**（自選股、匯出、電子報），
   **絕對不要把「今日候選」放進付費包** —— 那等於「付費看推薦標的」，
   是實務見解點名的典型態樣。

**做得到的第一步（今天）**：
- 在網站每一頁加固定版位：「**本站為公開資料之整理與視覺化，不構成投資建議，

### 紅線二：技術前提 —— 付費內容要放在哪裡才擋得住？

# ⑥ 頭貼／視覺識別的方向

**只給方向與理由，不出圖。** 每個方向都回答四個問題：
核心圖形是什麼／為什麼符合定位／小尺寸還認不認得出來／深淺底色上會不會消失。

**共同的硬約束（〔事實〕，來自 App 圖示的實際使用情境）**：
- App 圖示在 iOS 主畫面上實際顯示約 **60×60 CSS px**，在設定列表裡只有 **29×29**。
  **29×29 只夠放「一個形狀」，放不下兩個。**
- 我們的網站有**深色（科技風）與淺色（閱讀模式）兩套主題**（信心：高，讀 repo），
  所以圖示**必須兩個底色都活得下來** —— 這排除了「純白線稿」與「純黑線稿」。
- ⚠ **不可以用紅綠**做主色：台股紅漲綠跌，紅綠在金融語境裡有既定語意，
  拿來當品牌色會製造誤讀（「這個 app 的 logo 是綠的，是看空的意思嗎」）。

## 方向 A：剖面線（Cutaway Line）

| 項目 | 內容 |
|---|---|
| **核心圖形** | 一個實心方塊，被一條斜線切開，切面露出**三條不同粗細的橫紋**（像地層／像 PCB 疊層） |
| **為什麼符合定位** | 直接視覺化「剖開來看裡面」—— 這是我們相對 Tide 的核心差異。**它同時暗示了 2D 剖析圖與產業鏈的分層** |
| **29×29 認得出來嗎** | ✅ **可以**，但三條橫紋要減到**兩條**。切開的斜線是主要輪廓，小尺寸下靠「被切開的缺口」辨識 |
| **深淺底色** | ✅ **安全**。方塊用品牌主色（建議**琥珀／橙金**，避開紅綠），切面用底色的補色。深底上方塊發亮，淺底上方塊是深色塊面 —— **兩邊都靠「形狀」而非「明度」辨識** |
| **風險** | ⚠ 「被切開的方塊」在科技類 logo 裡不算罕見，要靠切面紋路做出差異 |

## 方向 B：齒輪咬合的兩個弧（Mesh Arc）

| 項目 | 內容 |
|---|---|
| **核心圖形** | 兩段圓弧，齒紋互相咬進對方的缺口 —— **不是完整齒輪**，只取咬合的那一小段 |
| **為什麼符合定位** | 上下游真的接得上 ＝ 供應鏈關聯圖的核心主張。呼應我們 19 個機械 3D 場景的視覺語言 |
| **29×29 認得出來嗎** | ⚠ **危險**。齒紋在 29px 下會糊成鋸齒雜訊。**必須把齒數減到每段 3 齒以內**，並加大齒高 |
| **深淺底色** | ✅ 安全（兩段弧用不同明度的同一色系，深淺底都靠對比差活下來） |
| **風險** | ⚠ **「齒輪」是工業類 logo 的陳腔濫調**。必須做得非常抽象才不會像「設定」圖示 —— 這正是最大的問題：**齒輪 ≈ 系統設定，這個聯想很難擺脫** |

## 方向 C：四格關卡（Four Gates）

| 項目 | 內容 |
|---|---|
| **核心圖形** | 四個由小到大／由淺到深排成一列的方塊或門形，**第四個是實心的**（代表最後一關：否決） |
| **為什麼符合定位** | 把「四問的判斷順序」變成圖形。**它是唯一一個把產品骨架直接畫出來的方向** |
| **29×29 認得出來嗎** | ⚠ **危險**。四個元素在 29px 下每個只剩 6px，會變成四個小點。**必須減到三格，或改成「三格 ＋ 一個明顯不同的第四格」** |
| **深淺底色** | ⚠ **要小心**。如果靠「由淺到深」的漸層表達順序，**在淺底上第一格會消失**。解法：**用飽和度而不是明度做梯度**，或給每一格加上等粗的外框 |
| **風險** | 最容易被誤認為「進度條」或「訊號強度」圖示 |

## 方向 D：單一轉針（Tacho Needle）

| 項目 | 內容 |
|---|---|
| **核心圖形** | 一段圓弧刻度 ＋ **一根指針**，指針指在弧的偏右上（不是正中 —— 偏一點才有「正在動」的動感） |
| **為什麼符合定位** | 儀表板的最原型符號。我們本來就是「儀表板」，這是最誠實的表達。**同時，指針有方向，天然表達「輪動」** |
| **29×29 認得出來嗎** | ✅ **最好的一個**。指針是**單一高對比元素**，在任何尺寸下都認得出來 —— 這是儀表符號能活一百年的原因 |
| **深淺底色** | ✅ **最安全**。指針用品牌色（琥珀），弧用 50% 灰 —— **50% 灰在深淺兩個底色上的對比度幾乎相同** |
| **風險** | ⚠ **辨識度最低的一個**。儀表指針的 logo 太多（車用、效能監控、健康 app）。**要靠刻度的形狀做差異**：例如刻度不是均勻的，而是四段不同密度（呼應四問） |

## 〔判斷〕我的建議

| 用途 | 建議 | 理由 |
|---|---|---|
| **App 圖示／favicon（29px 要活）** | **方向 D（轉針）** 或 **方向 A（剖面線）** | 只有這兩個在 29×29 下還認得出來 |
| **網站主視覺／社群大圖（有空間）** | **方向 A（剖面線）** | 它講的故事最接近我們真正的優勢 |
| **不建議** | 方向 B（齒輪） | 「齒輪 ≈ 設定」的聯想成本太高 |
| **可以當輔助圖形，不要當主標** | 方向 C（四格） | 適合放在網站上解釋四問，不適合縮到 29px |

**做得到的第一步**：先只做 **favicon**（`site/icon.png` 已存在，2KB）。
把方向 A 與方向 D 各畫一版 32×32 的 PNG，**在深色與淺色兩個主題下各看一次**，選一個。
這是半天的工作，而且不需要任何設計工具（SVG 手寫就夠）。
