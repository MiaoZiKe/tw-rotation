## 3. 參考風格拆解

### 整體氣質

Creamy Tech Lab：奶油系 Q 版毛球 × 科技研究筆記 × 手繪資訊圖表。親切、圓潤、帶筆觸，但科技物件結構清楚。畫面不是只有可愛角色：讀者應能看懂晶片層次、傳輸方向與比較關係。

### 配色（觀察）

底色為暖白、奶油白；標題與輪廓用深咖啡近黑。珊瑚粉／蜜桃橘標關鍵字，奶油黃做螢光筆底、亮點與金屬接點；淺藍、薄荷綠、淡紫區分資訊卡。科技物件用石板灰、深藍灰、墨綠，伺服器的小面積冷藍燈號形成冷暖對比。沒有大面積霓虹或純黑背景。

### 建議色票（設計近似值，非原圖精準取色）

|用途|HEX|使用原則|
|---|---|---|
|紙底|#FFF9EF|全頁底色，可加很淡紙紋|
|比比奶白|#FEF8E8|身體主色，不被背景色污染|
|主文字／輪廓|#321A14|標題、本文、手繪線|
|次文字|#795B49|來源、註解；需保有對比|
|珊瑚|#F58C83|關鍵詞、問題、提醒|
|蜜桃|#FFD4BA|色帶、卡片與暖色輔助|
|淡黃|#FFE5A5|重點底、提示與星光|
|淺藍|#B9DFF0|資料傳輸、比較項目|
|薄荷|#B9DBCC|供應鏈、結構、第二組比較|
|淡紫|#DCCEF0|趨勢與延伸資訊|
|科技深灰|#525E6B|晶片、伺服器外殼|

建議紙底約占 60–70%，主要插畫與咖啡文字約 20–30%，強調色約 10%；依頁面調整。單頁重點色以 2–3 個為主，不能靠顏色單獨表達資料分類。

### 線條、光影與材質

外輪廓深咖啡、圓端、略不規則；內部結構線較細。插畫用 2–3 階柔和陰影、短筆觸高光、局部水彩感。物件用一致的斜俯視角或剖面角度，晶片接點、堆疊與基板有明確層次。貼紙式白色留邊可用於主角或標題，但不堆厚重投影。避免照片與卡通素材混搭、塑膠 3D 光澤、過量紙紋及細碎裝飾。

### 字體與文字層級

觀察：主標粗圓、略帶手寫感；關鍵英文 CoWoS／HBM 放大並用珊瑚色。本文較規整，維持溫暖圓潤。標題外有奶油黃或白色貼紙邊；重點句搭配不規則刷色底。

建議：標題選用可合法使用的繁體圓體／手寫黑體，本文選可讀的繁體黑體；最多兩套字型。不要假稱辨認出原圖字型。1080×1350 起始值：主標 88–120 px，頁標 56–72 px，本文 34–42 px，註解 24–28 px，泡泡字 30–36 px。以實際手機縮圖調整；資訊太多先減字，不持續縮小。中文詞、數值與單位、公司名與英文縮寫避免不自然斷行。所有正式文字後製排版，不依賴生成圖片內的中文字。

### 版面與閱讀順序

觀察：上方系列膠囊標籤／頁碼 → 超大問題標題 → 比比與主題物件 → 解說卡／比較／步驟 → 一句結論與滑動提示。023146 使用六宮格分類，023149 使用大主視覺加底部三卡；023155 更適合封面；023200 展現輪播的定義、比較、歷程、供應鏈、挑戰、總結與 CTA。

建議：正式輪播每頁單一訊息；海報六宮格只用於總覽，不能每頁塞滿六個概念。四邊安全距離 64–80 px，卡片內距 28–40 px，卡距 24–32 px。標題約占上方 20–25%，主圖與圖表約 45–55%，解說及來源占剩餘區域，比例可按內容調整。本文以左對齊為主；左右比較維持相同尺度與欄寬。頁碼、品牌名與來源位置固定。

### 圖形語彙

圓角手繪框、膠囊標籤、數字圓章、手繪箭頭、短底線、星光、問號、放射線、對話框。每個箭頭都要有真正的閱讀或因果用途；對話框尾端朝比比。裝飾不遮住物件接點、圖表軸或數值。每頁建議 2–5 組小裝飾，避免滿版散點。

## 4. 比比主持人規範

比比是帶讀者理解科技的主持人。每頁指定「正在說什麼、看哪裡、做什麼、為什麼出現在這裡」。姿勢不可只是複製同一張笑臉貼角落。

保留原創阿比天竺鼠奶白毛球、深咖啡粗描邊、黑點眼及白高光、小耳、小圓掌、短腳與無尾巴；不拉長手臂、不加人類手指、不任意換臉或換毛量、不用金錢圖示。依目前已知較新品牌限制，粉色限耳／掌／腳；附件粉腮、舌與身體蜜桃陰影視為參考風格，不自動覆蓋既有角色限制。

現有 GitHub 規範有互相衝突的舊段落（尾巴、擬人捧物）及後續四腳規則。這次使用者明確要求社群主持人並提供拿物／引導示例，因此社群可採短前掌貼身指示或接觸道具的主持姿勢；不延伸為長手臂或長時間人形站立，也不藉此修改網站寵物的四腳互動規則。無尾巴、禁止金錢圖示優先於舊目錄範例。

|內容任務|主持表情與動作|主題物件|對白用途|
|---|---|---|---|
|封面／開場|好奇歪頭、探頭，眼神朝標題或讀者|主題晶片／設備|提出一個問題|
|名詞定義|認真解說、短掌靠近圖示|剖面模型、提示板|一句白話翻譯|
|結構拆解|湊近觀察、跟著箭頭看|放大鏡、分層晶片|指出關鍵零件|
|兩者比較|思考、左右視線|雙欄樣品、比較板|提示比較基準|
|數據亮點|驚喜但不誇張|數字卡、長條圖|解釋數字意義|
|風險／限制|擔心、皺眉、少量汗滴|溫度計、警示卡|補充條件與代價|
|供應鏈|帶路、目光沿節點移動|晶圓、封裝、伺服器|說明合作順序|
|總結／CTA|理解後點頭、朝讀者看|重點筆記、收藏星號|總結並邀請討論|

每頁通常一隻主持比比；封面可一大一小但不搶主題。建議內頁身寬約畫面 18–28%，封面約 28–40%，依資訊密度調整。連續頁至少變換表情、視線、動作、道具中的兩項。台詞每泡泡優先 12–28 個中文字；不能把唯一的重要數據藏在泡泡裡。道具須接觸或放置合理，不能無故漂浮。

## 6. IG 與 Threads 產出

IG 預設 1080×1350、十頁、封面標題不超過 14 字。以下為可調整骨架，不為湊頁數塞內容：1 問題封面；2 名詞定義；3 為何重要；4 結構／運作；5 關鍵比較；6 應用；7 供應鏈；8 挑戰／限制；9 三點結論；10 討論 CTA、來源及免責。每頁都需寫出單一結論、圖表類型、主持台詞、比比表情／動作／道具。

比較用表格／長條，結構用剖面，關係用供應鏈，事件用時間軸；數據圖表用精確繪圖排版，不能讓生成圖片決定數值、刻度或比例。圓環僅用於有明確整體的占比。

Threads 依題材製作單篇或串文：第一則觀點／問題 → 解釋 → 證據 → 產業影響 → 限制與觀察指標 → 討論。用短段落，避免硬貼 IG 分頁文字；移除「如左圖」等依賴版面的語句。發布時核對當時平台限制，不在這份規範寫死未核實的字數上限。

發文包包含：逐頁 PNG、逐頁文字稿、IG 說明、Threads 稿、來源表、封面、素材來源清單；有動畫需求時另出 GIF／Reels。實際帳號發佈需可用的帳號連線與明確發布指令；本規範建立不代表已連接或已發布。

## 8. 製作與驗收順序

1. 收 Claude 交接單，核對時點、來源及事實／分析。
2. 文案先出逐頁單一結論，再定圖表與主持動作。
3. 從合格素材挑選；缺主題物件或姿勢才新增插畫。先做一頁風格校準，通過既有規範後延展。
4. 插圖、文字、圖表分層製作；正式文字與數據圖後製。
5. 手機尺寸檢查可讀性、留白、斷行、裁切與對比。
6. 檢查比比臉型、無尾巴、短掌、配色、視線與道具接觸；每頁主持功能明確。
7. 檢查公司、數字、幣別、單位、期間、財測與實際值；技術關係不能被可愛類比誤導。
8. 登記素材作者及版本，完成 IG／Threads 發文包，再依發布指令執行。
