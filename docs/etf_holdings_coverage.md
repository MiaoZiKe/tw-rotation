1. **投信沒接**：只接了 8 家（元大、國泰、中信、群益、復華、統一、凱基、野村）。這次補上 **富邦、台新（含原新光）、華南永昌、第一金、聯博** 5 家。

## 前端

成分股分頁（`site/industry.js` tabHoldings）沒有資料時：
- 投信沒接、而且 `etf_holdings.json` 的 `why` 有寫原因 → 顯示「此檔發行投信（X 投信）的每日持股目前抓不到。原因：…」（原因文字在 `etf_pcf.NOT_CONNECTED_WHY`）。

### 00918 為什麼變成「今天沒有公告」（根因）

1. 第三輪（10-07 19:14 UTC）接上大華銀、第四輪（20:19～21:17 UTC）接上永豐、玉山、安聯，但 `tests/test_etf_pcf.py::test_fetch_all_one_issuer_crash_does_not_kill_others`
   的 mock 清單沒有把這幾家加進去。
2. 本機容器出口被擋，這幾家一連就失敗、回空 → 測試照樣綠；**GitHub Actions 連得到官網、拿到真資料** → 斷言 `list(out["etf"]) == ["00935"]` 紅。
3. `daily.yml` 第一步「跑指標庫測試」失敗 → 抓取與回寫全部跳過。10-08 兩輪（00:36、06:52 UTC）都是這樣，傍晚那輪也沒排上。
4. 資料湖的 `etf_holdings` 停在 10-07 早上那份（只有 8 家投信、108 檔），**大華銀一次都沒進湖**；前端看到「大華銀已接上、但湖裡沒有 00918」→ 顯示「今天沒有公告」。
   （「第三輪實抓 00918 第一名台新新光金 7.82%」那次是探測工作流的自我測試，本來就不寫湖。）

修法：mock 補齊（含這輪新接的聯邦）＋測試裡把 `http.session`／`_req` 換成「一連外網就丟例外」——以後新接投信忘了加，本機與雲端也給同一個答案。
Actions 上跑整套 pytest 驗證：**1109 passed**（`probe-etf-pcf.yml mode=pytest` run 37780876670；修前同一支 run 37780366704 在這條紅）。

另外兩條防線（照 Andy 要求「任何一天官網抓不到都不會再變成空的」）：
- `compute/etf_holdings.build` 每檔取**資料湖裡自己最近一次**的持股基準日（不是全表同一天）；某天官網沒回應，畫面照樣顯示上一份並標「資料日 YYYY-MM-DD」。
  `tests/test_etf_holdings_cover_1008.py::test_每檔取資料湖裡自己最近一次_某天官網沒回也不會變空` 鎖住。
