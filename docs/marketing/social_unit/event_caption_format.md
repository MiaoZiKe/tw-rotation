# 事件貼文文案格式（法說／總經／ETF）2026-10-28 第 1 版

Andy 10-28 原話：「所有文案需要這樣的格式，但我覺得不夠好……需要看起來專業，但不會太過嚴肅」。參考結構：一句話導言（公司＋日期＋事件＋最關鍵數字），後接多段「▍」開頭的資料段，數字密集、句子完整。文字全部原創，只學結構。

**適用範圍**：法說、總經（FOMC、CPI、非農等）、ETF 每週一檔三類**事件貼文**。
**不適用**：盤前／盤中／盤後（含融資融券）自動文，**仍照 `auto_post.md`**（Andy 10-26 已確認，本規格不改它）。

## 一、結構（由上到下）

| 位置 | 內容 | 規則 |
|---|---|---|
| 1 導言 | 一句話：對象＋日期＋事件＋最關鍵 1～2 個數字 | 一行寫完（約 40～60 字）；數字用公司／官方公布值；不用形容詞（強勁、亮眼、利多） |
| 2 空一行 | | 導言與資料段之間固定空一行 |
| 3 資料段 | 每段以「▍段名」開頭，下接 1～2 行「・」條列 | 段名 ≤ 8 字；每行 ≤ 32 字；一行一個重點，數字帶單位與比較基準（季增／年增／上季） |
| 4 說明句（法遵句） | 一行：「以上為公開資料整理，非投資建議」 | 放在最後一個資料段之後、hashtag 之前；ETF 回測類改為「過去績效不代表未來，這是歷史情境說明，非投資建議」 |
| 5 hashtag | 3～4 個，一行 | 只放最後一串；順序：分類（#台股／#ETF／#總經）→ 主題 → 代號 |
| 6 網址 | 「👉 更多詳細資料可以點擊以下連結：」＋網址，**最後兩行** | 網址只放最後一串的最後一行；`?u=` 在 `#` 前（auto_post.md 規則 4） |

與 auto_post.md 的差異：資料段名多了「▍」前綴，導言多一句，另加一行法遵句。auto_post.md 的「標題一行、段名：」仍適用於自動文。

## 二、Threads 500 字限制與分串

1. **優先壓進單串 ≤ 480 字**（含 hashtag 與網址；留 20 字緩衝）。做法：資料段最多 5 段、每段最多 2 行；細節放網站、不放貼文。
2. 單串放不下才拆，**最多 2 串**：
   - 第 1 串：導言＋前 2～3 個資料段（講最重要的），結尾不放 hashtag、不放網址。
   - 第 2 串（回覆自己）：其餘資料段＋法遵句＋hashtag＋網址。
   - 兩串都要能單獨讀懂（第 2 串第一個資料段名就說明主題）。
3. 圖（IG 輪播／Threads 輪播）與文案同一組數字，圖上不放網址、來源、免責（auto_post.md 第二節）；**例外**：ETF 回測第 8 張圖就近放「過去績效不代表未來」（法遵要求，沿用 etf/plan.md 決定）。

## 三、法遵（不評價、不給買賣建議）

- 只寫：公司或官方公布的數字、管理層說法（標「報導摘述」）、歷史回測的算法與結果。
- 不寫：目標價、評等、「看好／受惠／強勁／利多利空」、對股價或指數的推論、「該買／該賣」。
- 動詞用「季增、年增、指引、減、上調」這類中性詞；方向判斷一律交給讀者。
- 數字都要有基準與日期（導言有日期；ETF 另寫資料日與「含息再投入、未扣費用稅」）。
- 發布前由 legal-compliance 過稿（樣張階段未過，見各 plan.md）。
