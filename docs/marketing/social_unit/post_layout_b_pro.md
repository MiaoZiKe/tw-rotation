**來源**：Andy 11-04 看 IG 實發畫面後的意見——「封面圖片改放中間」「字體有點大」「圓餅圖等等都要調整適當大小，圖都需要置中」。
**適用**：之後所有熱點文（頻道①）一律照這份做。IG 已發的期中選舉那組不換圖；這份是之後的標準版。
**v4 更新（11-04 Andy 看封面新舊對照）**：「舊版還是好點」→ 封面回到舊版配置（照片滿版在頁首下方、標題在照片下），沿用 v3 已下修的字級；內頁維持 v3。另新增第八節「大數字白話規則」。

## 四、內頁（圖表頁）垂直節奏

- 品牌條 → kicker（top 126）→ 標題（top 164，一行；兩行時規則線下移 58px）→ **深藍粗線 4px（一行標題 top 234；兩行 top 292）**
- 粗線下 28px 起放圖（圖區 856 寬）；圖與下方結論句間距 40px；結論句 → 圖例各 54～62px
- 結論句、圖例一律**置中**（`justify-content:center`），以圖區中線為軸，結論句前加 16px 銅紅方塊
- 整頁內容塊在「粗線 ↔ 頁尾」之間**上下留白相近**（生成器量出剩餘高度後位移一半，上限 100px），不擠也不留大片空白
- 一頁一個重點：標題 → 圖 → 說明，三段順序固定

## 六、檢查（交件前必做）

1. **重疊檢查程式**：逐一取所有文字的實際範圍，兩兩相交、超出安全邊界、壓到長條／徽章／照片、字級 < 21px 全部要 0 筆。
2. **置中量測**：取圖區的實際有墨範圍，左右空白差 ≤ 8px（量測值寫進回報）。
3. **人工**：每張全解析度打開看一次。
4. 回報寫一行：「重疊檢查：程式 N 張 0 筆；人工 M 張 0 筆」，沒這行不收件。

## 七、與舊規格不同之處（為什麼改）

- 照片從貼頂滿版改置中（Andy 11-04 要求；IG 畫面上滿版照片搶掉標題）。
- 字級整體下修約 15～30%（Andy：「字體有點大」）；封面標題保留較大，是為了仍當作首頁視覺重點。

- 每頁加頁碼、頁尾維持 21px，其餘沿用既有色票與 `docs/marketing/social_unit/auto_post.md` 的文案規則。

## 八、大數字白話規則（v4 新增）

Andy 11-04 原話：「以後注意 擬個的數字 6/6 觀眾第一時間不會知道你在說什麼」。

**規則**：任何大數字（封面、甜甜圈中心、重點句、小卡）都不可以單獨出現讓人猜；一眼看到就要懂它在講什麼。做法：數字本身帶單位或主語，旁邊小字補「哪一段期間、什麼樣本」。分數、比例、縮寫（如 6/6、5/6、3/4）一律改寫成白話；若單位太長放不進大字，就拆成「小字主語＋大數字＋小字單位」三行。

| 錯誤 | 正確 | 旁邊小字 |
|---|---|---|
| ✗「6/6」 | ✓「6 次全漲」 | 過去 6 次期中選舉，選後 3 個月加權指數 |
| ✗「5/6」 | ✓「6 次中 5 次上漲」 | （甜甜圈中心三行：6 次中／5 次／上漲） |
| ✗「−5.8%」單獨 | ✓「途中最深 −5.8%」 | 2002 年，選後 3 個月內 |
| ✗「3/4」 | ✓「4 次中 3 次收紅」 | 標普 500，選後 1 個月 |

自檢：把旁邊小字遮住，只看大字，陌生人能不能猜到在講什麼？猜不到就改。交件回報多寫一行「大數字白話：N 處，皆帶單位或主語」。

### 9.3 圖表選擇原則

1. **先問這頁要讓人看出什麼**：比大小用橫條、看路徑用折線、比兩個條件用分組表、看「有沒有」用圖示陣列，不拿圓餅或同一個統計重畫第二次。
2. **一個統計只出現一次圖**：數據表頁可以有全部數字，但其他頁換編碼（表格內嵌長條、橫條加平均列、圖示格、折線）。
3. **有時間次序用橫條由上到下，不用直條**：6～7 列的橫條可以做 50～56px 粗、數值放末端 32px，比直條更容易填滿版面；平均做成獨立一列（銅紅色、上方一條分隔線），不畫跨過所有標籤的平均虛線。
4. **折線**：突顯 2 條（銅紅、深藍），其餘灰線；加一條有意義的門檻線（本例 −5%，綠點線）；端點標籤互距 ≥ 34px；圖例放圖下方一行、不佔繪圖區。
5. **圖示陣列／數字卡**（本例「選後 1 個月」六格）：每格＝年份、箭頭圓（紅上綠下）、百分比 54px、文字「上漲／下跌」，不只靠顏色辨識。
6. **有/部分/無** 用實心、半實心、空心圓（SVG）加小圖例，不用 ●△○ 字元（字體不一致）。
7. **表格**：列高 96～100、數字欄置中、年份下方小字放起算日、斑馬改用淺銅底只標重點列；可在數字旁內嵌 28px 高橫條（共用同一個起點）。
8. 表格內文字手動換行（`<br>`），不讓瀏覽器在詞中間折行。

### 9.5 重疊檢查（v5 起的標準輸出）

生成器 `CHK` 逐張輸出：文字兩兩相交、文字壓到長條／圖示／照片、超出左右 40px 與下 40px、小於 22px（照片出處 20px 例外）、內容填充率、內容左右邊界。回報寫「重疊檢查：程式 9 張 0 筆；人工 9 張」「填充率：…」。

### 9.6 封面配置（v5，Andy 11-04：「封面圖下來點 讓標題上去 封面圖框度不變」）

**標題移到照片上方**，照片寬高不變（1080×560）。由上而下：品牌條（0～96）→ 分類小字「熱點解讀・日期」28px（top 120）→ 標題 58px 單行（top 158）→ 深藍粗線 4px（top 244）→ **照片 top 272～832** → （出處不再放照片下方：Andy 11-04「這備註在圖裡右下方」，見下）→ 大數字「6 次全漲」128px（top 874）與右側白話說明 32px → 細線（top 1060）→ 重點句 42px（top 1090）→「滑動看…→」28px（top 1164）→ 頁尾。填充率約 90%，標題區上下留白適中。取代第三節的「標題在照片下」配置。

**封面圖上不放出處（Andy 11-04：「拿掉來源好了 我們備註在文案就好」，取代前一版「出處放照片內右下角」與第三節、第五節的照片出處小字）**：照片下方與照片內都不放任何出處字或半透明底，照片下方騰出的空間平均分給大數字區（大數字 top 874、細線 1060、重點句 1090、「滑動看…→」1164），填充率約 91%。

出處一律寫在貼文文案：IG 文案最後一段、Threads 底下的留言，格式「封面圖：作者／授權（來源）」，例：「封面圖：Architect of the Capitol／公有領域（Wikimedia Commons）」。

法遵提醒：
- 公有領域照片可不署名，但仍照上述格式寫，方便查證。
- CC BY、CC BY-SA 照片**必須**在文案署名作者與授權，並附授權連結，不可省略。
- 每篇貼文資料夾的 `image_sources.md` 照舊留（圖檔來源、授權、取得日期）。

### 一、頁面結構（8 頁左右，每頁一個重點）

| 頁 | 內容 | 做法 |
|---|---|---|

### 二、版面規則

1. **封面人像**：中性、正式、不誇張表情；用 CC／公有領域真實照片，構圖不切額頭與下巴，不加濾鏡過頭（本篇用 CES 背板前那張，CC BY 2.0，署名寫在文案，圖上不放出處）。
2. **標題在上、白話大字在下**，大字不可單獨出現數字（沿用第八節）。
3. **內文至少 3～4 張合法實景照**（國會、公司、會議等），**公有領域／CC0 優先**；CC BY-SA 的照片圖上不加字、不疊色塊，署名與授權連結放文案。
4. **未證實一律虛線框＋「未證實」小標**；已知一律實線。圖例要寫在圖上（沿用 11-04 規則）。
5. **版面填充率 85～95%**（內容底到頁尾線的距離，由程式量；本篇 85～96%），字級不得小於 22px。
6. 稱讀者一律用「**您**」，全篇搜一次「你」；產出前必跑。

### 三、法遵（涉個人的事件）

1. 涉個人指控的對象：**未經本人公開承認、或只有單方說法者，不寫姓名、不放照片、不寫公司名**；用「某方」「報導指出」。本篇能寫出人名與照片，是因為事件由本人公開聲明、且各大媒體均實名報導；仍須在資料說明頁寫「本帳號不公開涉事個人的姓名與私人資訊」類的限制（本篇指第三方私人資訊）。**拿不準時不寫，先問法遵。**
2. 媒體說法一律帶出處（例：多家媒體歸因於…（Bloomberg、Yahoo Finance））；只取得轉述的原文要在說明頁寫「原文未直接取得，經其他媒體轉述」。
3. 不預測、不建議買賣；「不等於因果」「性質不同，不可類比」要寫成獨立的一行，不埋在段落裡。
4. 頁尾一行資料來源與「非投資建議」，字級約 21～22px。

### 四、交件前檢查（缺一不收）

1. 程式檢查：重疊、超出版心、卡片文字溢出、最小字級、填充率；每頁 0 筆。
2. 人工用 Read 看封面、最後一頁與有圖表的頁（全解析度）。
3. 回報一行：「重疊檢查：程式 N 頁 0 筆；人工 M 頁 0 筆；填充率 X～Y%」。
4. 照片來源、作者、授權、取得日期寫進貼文資料夾 `image_sources.md`。

### 五、11-10 Andy：網站圖優先、資料必須最新、垂直圖表

> Andy 11-10 原話：「方向有對，但外資的買賣超我的網站不是也有資訊？為何不使用上面的圖片？並且發這類最新數據的需確保數據是有更新到最新，還有盡量使用垂直圖表」

1. **圖表一律優先用網站上的真實圖表截圖**，不要自己另外重畫。外資、投信買賣超用「市場明細→三大法人」的「每日買賣超＋加權指數」；族群用資金流向頁、產業地圖的圖。截圖以 390 寬、deviceScaleFactor 3 拍，放大、裁切乾淨（隱藏比比浮動鈕、裁掉含 LOGO 的頁首），再加銅紅箭頭與編號。**只有網站上沒有的圖才准自己畫。**
2. **資料必須是最新交易日**：開工前先查 `site/data/meta.json` 的 `data_date`、`inst_market.json` 的 `latest`，以及資料湖 `data/inst_daily`、`data/inst_market_daily` 的最新日期。收盤後的資料還沒更新到當天，就 `git pull` 拿雲端最新資料湖並重建 `site/data`；官方還沒公布就等到公布，**不可以拿舊資料發**。每張圖、每段文都標明資料日期，封面寫「資料日 M/D」。
3. **自己畫的圖盡量用垂直圖表（直條圖）**，對照 `docs/chart_library.md` 的 C 款直條；正負值用中線上下分向的直條，不用橫條。
4. 範例與一鍵重產腳本：`restart_samples`（scratchpad）內 `gen/rebuild_all.sh`。
