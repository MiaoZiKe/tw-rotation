# 新聞貼文自動排程（2026-10-28 第 1 版）

> Andy 10-28：「可以，接上排程，單位改成億美元，CEO並安排人員持續優化，依據不同的內容後台紀錄，後續慢慢改善收斂成大家喜歡的主題、內容、版面、風格」。
> 版型以 `docs/marketing/posts/render_news_cards.py --pal D` 為定案；寫法規則見 `news_post_rules.md`；法遵標準見 `docs/marketing/posts/2026-10-28-news/legal_review.md`。

## 一、流程

| 步驟 | 做什麼 | 程式 |
|---|---|---|
| 1 觸發 | 「社群即時貼文」每一輪結束後（workflow_run），加上備援排程 | `.github/workflows/social_news.yml` |
| 2 判斷 | 讀 social-snaps 分支 `state/posted.json`：今天哪一段主貼文（premarket／intraday／close）已發、新聞文還沒排 | `scripts/social_news.py --slot auto` |
| 3 選題 | 資料湖 `data/news`（鉅亨、經濟日報、科技新報）時間窗內的新聞 → 排掉業配／活動 → 相似標題分群 → 熱度分數 × 每週權重 → 前 80% 依分數、20% 探索 | 同上 |
| 4 產稿 | 模板式口袋證券長文：兩行 hashtag 標題 → 導言（報導摘述）→ 📊 重點數字 → 🔎 數字怎麼看 → 👀 為什麼值得注意 → 法遵句 → 網址一行；Threads 依小節拆串（每串 ≤480 字，串尾 (k/n)） | 同上 |
| 5 法遵 | 誇飾字自動改寫（大漲→上漲、狂賣→賣超、飆→升至…），改寫後仍有禁用字眼（買賣建議、目標價、利多利空、傳聞、操作暗示、拿美股推台股開盤…）→ **該篇不排程** | `scripts/news_legal.py` |
| 6 出圖 | `render_news_cards.card_v4`（--pal D）每篇 1 張 1080×1350；程式重疊檢查 > 0 筆的那篇不排程 | 同上 |
| 7 排程 | 寫 `social/ig/queue/<日期>_news-<段>-<n>.md`（圖在 `social/ig/images/news/`）與 `social/threads/queue/` 同名檔，`status: approved`＋`publish_at`，推回 main | 同上 |
| 8 發文 | 既有 `ig_post.yml`／`threads_post.yml` 每 15 分鐘把到點的發出、回寫 `status: posted`＋`urls` | 既有 |
| 9 回收 | 每晚 23:10 `social_insights.yml` 更新 `posts_catalog.json` 後，依標籤聚合 → social-snaps `state/news_insights.json` | `scripts/news_insights.py` |
| 10 優化 | 每週一 09:30 `social_style_weekly.yml` 產週報 `docs/marketing/news_weekly/<日期>.md`、更新權重 `social/news/weights.json`（下一次選題自動讀） | 同上 |

選題紀錄（入選、被擋原因、重疊檢查結果）每段一份：`social/news/log/<日期>-<段>.json`。

## 二、時程（台北，週一到週五；休市日主貼文不發，新聞文也就不排）

| 段 | 新聞時間窗 | 發文時間 | 備援排程 |
|---|---|---|---|
| 盤前 | 前一天 13:30 起 | 主貼文發出 +30 分，不早於 08:50 | 08:35 |
| 盤中 | 當天 07:30 起 | 主貼文發出 +30 分，不早於 12:31 | 12:16 |
| 盤後 | 當天 11:30 起 | 主貼文（盤後法人＋融資）發出 +30 分 | 19:35、21:05、22:35 |

- 每段 3～5 篇，同段每篇錯開 5 分鐘。可發的不到 3 篇時照發能發的（寧可少發不湊數），0 篇就不發，下一次觸發再試。
- 主貼文已發超過 3 小時才輪到的段落不補排（新聞時效已過）。同一段同一天只排一次。

## 三、每篇的標籤（queue 檔頭 meta）

| 欄位 | 值 | 說明 |
|---|---|---|
| `topic_category` | 台股／財報／總經／科技／美股 | 關鍵字分類 |
| `content_type` | 財報數字／盤勢數字／總經數據／產業趨勢／公司動態 | 盤勢數字每段最多 1 篇（主貼文已涵蓋盤勢） |
| `layout` | `D-無圖大數字` | 之後加入已審 AI 圖版會是 `D-AI圖` |
| `style` | 口袋長文／精簡重點 | 精簡重點＝不放「數字怎麼看」 |
| `has_ai_image` | false | 見第六節 |
| `explore` | true／false | 是否為 20% 探索篇 |
| `heat` | 數字 | 選題分數（已乘權重） |
| `news_ids` | 資料湖 news_id | 回查原始新聞 |
| `u_code` | `news<段><序號>` | 網址 `?u=ig-…`／`?u=th-…` 的功能碼，漏斗「依功能」可分篇看 |

## 四、數字與查證規則（自動版的取捨）

- 數字只取自資料湖新聞內文（標題＋摘要），不自行推算；唯一的換算是毛利率「每 100 元剩幾元」，標「本站換算」。
- 同一數字在同群另一家媒體也出現 → 標「（兩家來源）」，上卡優先；只有一家 → 每條數字註明「（經濟日報報導）」這類出處。
  ⚠ 這比人工版「單一來源數字不入文」寬：自動流程拿不到第二來源時以「標出處」代替，列為人工覆核點。
- 導言是第一則報導的第一句（標「報導摘述」）；含禁用字眼的子句整段刪掉、不改寫；刪完不足 12 字改用標題。
- 至少要有 2 個可用數字的新聞群才進候選。

## 五、優化規則（每週一自動）

1. 指標：互動率＝互動數 ÷ 瀏覽數（IG：讚＋留言＋分享＋儲存；Threads：讚＋回覆＋轉發＋引用＋分享），另列平均瀏覽、分享、儲存、點擊。
2. 統計最近 14 天已發出的新聞貼文，依 主題／內容型態／版面／風格／AI 圖／時段 排名。
3. 權重＝1 +（該值互動率 ÷ 全體互動率 − 1）×（n ÷ (n+5)），夾在 0.6～1.6；樣本 < 3 篇維持 1.0。
4. 選題熱度 × 主題權重 × 內容型態權重；風格取權重最高者，探索篇隨機。
5. 探索比例固定 20%（每段至少 1 篇從還沒選到的主題挑），避免早期碰巧表現好的類別獨占。

## 六、AI 圖

規則（`ai_image_review.md`）：AI 圖未經 art-director 審核不得發布。自動流程預設 **無 AI 圖**（`D-無圖大數字`，上半部放大關鍵數字）。
之後若要用圖，只能從「已審核素材庫」挑（每張要有 ai_review 紀錄），並把 `layout` 標成 `D-AI圖`、`has_ai_image: true`，週報就能比較兩種版面。

## 七、人工覆核點

| 什麼時候 | 誰 | 看什麼 |
|---|---|---|
| 每段排程後（可選） | CEO／財經編輯 | `social/news/log/<日期>-<段>.json` 的入選與被擋原因；要撤下就把 queue 檔改 `status: draft` 並推 main（發文前 5 分鐘以上） |
| 每週一週報 | CEO | 權重變動 > ±0.3 的類別是否被單篇爆量拉動；第一名與最後一名各抽 1 篇看原文 |
| 每週 | legal-compliance | 抽 3 篇自動稿過稿，新增的禁用字眼補進 `scripts/news_legal.py` |
| 單一來源數字 | 財經編輯 | 第四節的寬鬆處；發現數字錯誤立即撤文並補規則 |

## 八、手動操作

- 演練（不寫 queue、不發）：Actions →「新聞貼文自動排程」→ Run workflow → dry_run 勾選（預設就是勾），產物在該輪的 artifact `news-dry-run`。
- 本機乾跑：`CHROMIUM=<chrome 路徑> python scripts/social_news.py --slot pre --date 2026-10-29 --now 2026-10-29T08:35+08:00 --posted <posted.json> --dry-run --out <資料夾>`。
- 本機樣本：`docs/marketing/posts/2026-10-29-news-auto-dryrun/`（盤前＝10/29 明日樣本；`replay-1028/` 為用 10/28 資料重播的盤中、盤後）。

## 九、已知限制

- 點擊（?u= 漏斗）數字在帳號 Worker 管理區，Actions 沒有管理者權限讀不到；週報點擊欄先顯示「—」。要接的話需新增一組唯讀的漏斗匯出端點與 Secret，或設 `FUNNEL_JSON`。
- `posts_catalog.json` 每晚只更新最近 30 則貼文的成效；新聞文一天最多 15 則，較早貼文的數字會停在最後一次更新。
- 模板文案沒有 LLM 改寫，語句較制式；標題沿用媒體標題清理後的版本（去掉「XX財報／」前綴與誇飾字）。
