# 兩個頻道的版面分析與版型（美術總監，2026-11-02）

Andy 原話：「幫我整理我接下來頻道要做哪些、比重多少、如何規劃發文、頻率、製作內容、版面分析，頻道二一樣」。
這份只管**版面**；內容比重、頻率、選題看 `content_restart_plan.md` 與內容企劃的 `channel_playbook.md`。
樣張全部在 `layouts/`，總覽圖：`/home/user/tw-rotation/docs/marketing/diagnosis_1102/layouts/overview.png`。
產生腳本：`layouts/render_layouts.py`（改文案或色票後重跑，會自動印重疊檢查）。

## 一、先講結論

1. **兩個頻道用兩套完全不同的視覺語言**，避免被看成同一個機器帳號：
   頻道一＝「財經儀表」：深海軍藍底、一個黃、大數字、比比當配角。
   頻道二＝「圈內人的筆記」：暖紙底、墨黑字、一支紅橘筆、點格紙、虛線填空框、藍原子筆旁註，**沒有吉祥物**。
   縮到手機 33% 時，兩邊一眼就分得出來（見 `layouts/check_33pct.png`）。
2. **兩邊都守同一組硬規則**（承接 `brand_visual_review.md` 第四節）：一張圖一個結論；標題 ≥ 64px、內文 ≥ 32px（樣張標題 66～150px、內文 34～60px）；一張圖只有一個主色；密圖只當附圖，結論用大字放在最前面；每則最後一張有一句話的行動邀請（階段 0 是「留言」「追蹤」，不放網址、不叫人註冊）。
3. **頻道二的第一張（封面）不是「好看」，是「搜得到、點得進」**：公司名＋「薪資行情」＋一個數字位。廣達爆文（68,947 觀看）是文字取勝，所以頻道二版型的設計目標是「不要搶走文字的力量」，圖卡只負責把欄位整理成可截圖保存的樣子。

## 二、視覺識別（兩套）

| 項目 | 頻道一　哩股哩股（liguligu0818） | 頻道二　科技業薪資透明（名稱待 Andy 決定，樣張暫用「科技圈薪水透明」） |
|---|---|---|
| 一句話氣質 | 儀表板的精密感：冷、準、有結論 | 同事在茶水間給你看的筆記：暖、直、有立場 |
| 底色 | 深海軍藍 `#0B1626`＋極淡方格（3% 白線） | 暖紙 `#F5EFE3`＋點格（`#D8CDB5` 圓點） |
| 卡片 | `#13233A` 圓角 20px、2px 線 `#2A3D57`，無陰影 | `#FFFBF2` 直角 6px、3px 墨黑框、8px 硬陰影 |
| 主字 | `#FFFFFF`（對底 18.2:1） | 墨黑 `#1F1C17`（對紙 14.8:1） |
| 次字／輔助字 | `#C3CFDD`（11.5）／`#8FA3BA`（7.0） | `#4A443A`（8.4）／`#6B6454`（5.1） |
| 唯一主色 | 重點黃 `#FFD23F`（對底 12.6）：只標「最重要的一個數字或詞」 | 紅橘筆 `#D9420F`（大字用，對紙 3.9）／`#B8340A`（小字用，5.2） |
| 輔助色 | 非重點直條 `#5B7391`；**漲 `#FF6B7A`（紅）、跌 `#34D399`（綠）**，台股慣例，且一律配 ▲▼ 箭頭，不只靠顏色 | 藍原子筆 `#1E3F8F`（旁註，8.5）；螢光底 `#FFD9C2`（標題下劃一道）；漲跌若出現用 `#C4142F`／`#07784E` |
| 標題字體 | Noto Sans CJK TC Black（900） | Noto Sans CJK TC Black（900） |
| 數字／標籤字體 | Inter ExtraBold（數字、百分比） | JetBrains Mono Bold（編號、標籤、公式） |
| 吉祥物 | 比比：封面或結尾當配角（≤ 250px）、左上角圓形頭像（只放臉） | **不放**。品牌記號是橘色 `[·]`（方括號裡一個點＝「待填」），貼在左上角 |
| 裝飾 | 無；只有黃色重點與紅綠數字 | 紅橘半透明膠帶（可選、不蓋字）、藍字旁註微傾 -2 度、虛線〔待填〕框 |
| 為什麼這樣分 | 延續網站與事件貼文 v2（黑底大字＋黃數字）＝讀者已經看過的「哩股哩股長相」 | 與頻道一在底色明暗、字體氣質、主色、有無吉祥物四件事上全部相反；〔待填〕虛線框本身就是「這裡填你的真實數字」的視覺語彙 |

**字體說明（重要）**：兩邊都只用 Noto Sans CJK TC＋Inter／JetBrains Mono，**不新增字型**（符合專案紅線）。「手寫風」我沒有另找手寫字型：repo 與出圖環境都沒有可商用的繁體手寫字，引入新字型要先過 Andy。頻道二的「手寫感」改用版面做出來（藍字微傾旁註、虛線填空、點格紙、硬陰影卡片），這比隨便套一個陌生手寫字型更不容易出錯。若 Andy 之後想要真手寫字，候選是開源 OFL 的粉圓體（open-huninn）一類，需要他同意並放進 repo。

**本機渲染的限制**：這台機器只有文泉驛正黑（單一字重、粗體是合成的），所以樣張的粗體比正式出圖機（有 Noto Sans CJK TC 真粗體）略糊、字寬略不同。版面都留了餘量（每行至少留 8% 空），正式出圖仍要重跑重疊檢查。

## 三、頻道一　哩股哩股：5 種版型

共同規則：1080×1350（4:5），Threads 與 IG 輪播同一張圖，不另做 Threads 版。限動不在範圍。
結構：左上角圓形比比頭像＋「哩股哩股」＋右上頁碼；底部細線＋欄目名（左）。**左上角不放彩色時段膠囊、不放 App 小圖**（承接審查：一天多則時才不會看起來是同一張圖反覆出現）。

### A　熱點解讀輪播（主力；樣張 A1、A3、A4、A5）

| 項目 | 規格 |
|---|---|
| 用途 | 台股大跌、大廠大跌、突發事件的「為什麼＋影響誰」。對應 Andy 的「Intel 大跌為什麼」 |
| 平台 | IG 輪播；Threads 發前 3 張＋長文（文字照 `content_restart_plan.md` 的格式，圖只當附圖） |
| 張數 | 5 張（最少 4、最多 6） |
| 1 封面 | 欄目＋日期（38px 灰）／事件主語 2 行（112px 白 900）／**黃色大數字 340px**／一句疑問（52px 灰藍）／「滑動看 3 個原因 →」（40px）。比比「嚇一跳」250px 放右上，不碰字 |
| 2 發生什麼 | 3 列事實，每列「編號＋一句」，款式同 3 |
| 3 因果鏈 | 3 張卡由上而下、中間三角箭頭；每卡 標題 52px＋一句 36px；最後一卡邊框變黃、關鍵詞黃字 |
| 4 台股影響 | 標題 84px；4 列「族群名 56px＋一句 34px＋▲▼漲跌 64px」，**紅漲綠跌**；最底一句結論 44px，關鍵詞黃字 |
| 5 結尾 | 比比思考 330px／「你怎麼看？」128px／留言邀請 52px（二選一的字黃色）／「追蹤，明天解讀下一個熱點」44px。**階段 0 不放網址、不放「前往網站」** |
| 字級 | 標題 ≥ 84（封面 112）、內文 ≥ 34、頁底 28（資訊性文字不放在這一級） |
| 配色 | 底 `#0B1626`，**全張只有黃色一個主色**；紅綠只出現在漲跌數字 |
| 第一張鉤子排法 | 「主語＋動詞（單日重挫）」→ 全張最大的黃色數字 → 一句讀者想知道答案的疑問。三樣由上到下遞進，3 秒內讀完 |

### B　單一數字大字卡（樣張 B）

| 項目 | 規格 |
|---|---|
| 用途 | 一個會讓人停下來的數字：ETF 配息率、某產業一週資金、某股一天成交。可當輪播封面，也可單張發 |
| 平台 | Threads、IG 皆可 |
| 張數 | 1 張 |
| 內容 | 欄目 38px／**黃色數字 380px**／數字是什麼 76px 白 900（2 行）／一句限定語 44px 灰藍（例如「是歷史配息率，不是保證」） |
| 配色／比例 | 同 A；1080×1350（若只發 Threads 也可裁 1080×1080，數字置中） |
| 注意 | 數字 ≥ 4 個字元時降到 340px 以內；數字旁一定有「它是什麼」，不准只有一個光禿禿的數字 |

### C　ETF 配息比較表卡（樣張 C）

| 項目 | 規格 |
|---|---|

| 平台 | IG 輪播（第 2 張起）、Threads 單張 |
| 張數 | 輪播 4～6 張：1 封面（用 B 的大數字）／2 比較表／3 配息頻率日曆／4 誰適合（文字卡）／5 結尾 |

### D　產業輪動圖卡（樣張 D）

| 項目 | 規格 |
|---|---|
| 用途 | 「錢這週停在哪一段」；產業輪動、下一個關注什麼產業 |
| 平台 | IG 輪播、Threads |
| 張數 | 輪播 4～5 張：1 結論封面／2 本週排名（本張）／3 這一段在產業鏈的位置／4 為什麼／5 結尾 |

### E　純文字串（樣張 E，規格圖，不是要發的圖）

| 項目 | 規格 |
|---|---|
| 用途 | 即時熱點、迷思澄清、一則一個重點；**不附圖**，靠排版讀完 |
| 平台 | Threads（一則 ≤ 500 字） |
| 結構 | ① 鉤子（第一行，≤ 25 字，含數字或疑問）② 一句結論 ③ 三點（用「・」條列）④ 提醒（非買賣建議）⑤ 一句問句收尾（引留言）。段與段之間空一行 |
| 為什麼放進版型 | Threads 有 63% 貼文不含圖（見 `brand_visual_review.md`），圖不是必要；而且純文字最像「有人在講話」，階段 0 建信任就靠這個 |
| 搭配 | 一週 3 則裡至少 1 則純文字，其餘才用 A～D（比例由內容企劃定，這裡只管版面） |

## 四、頻道二　科技業薪資透明：4 種版型

共同規則：1080×1350（4:5）；Threads 與 IG 同圖。**所有薪資數字在樣張一律是〔待填〕虛線框；正式發文由 Andy 提供真實數字、且標「朋友提供，有誤請指正」＋資料時間。** 結構：左上 `[·]`＋頻道名＋頁碼；底部墨黑粗線＋欄目名。

### F　薪資行情欄位卡（主力，爆文同款；樣張 F1～F3）

| 項目 | 規格 |
|---|---|
| 用途 | 一家公司一則：「〔公司名〕薪資行情」。對應唯一爆文類型（廣達 68,947 觀看） |
| 平台 | Threads 為主（文字照爆文公式：搜尋詞標題→圈內梗→朋友說→欄位清單→軟評語→面試加料→邀請補充）；圖卡給 IG 與 Threads 當「可截圖保存」的附圖 |
| 張數 | 3 張 |
| 1 封面 | 小標籤「公司行情 / 01」（32px mono）／**公司名 150px**（虛線填空框）／「薪資行情」150px，下劃螢光／職類 44px／藍字旁註「朋友提供，有誤請指正 ↓」44px／底部一張卡：「碩畢月薪〔待填〕K」72px。**鉤子＝公司名＋一個數字位**，讀者一看就知道是不是自己要找的公司 |
| 2 欄位一覽 | 7 個欄位（總部地點、碩畢月薪、年終・分紅、升等路徑、加班時數、繁忙程度、出差頻率）；每列：欄名 42px 墨黑／數值框 40px 紅橘虛線／**一句評語 36px 藍字**。列高 112px，列間虛線 |
| 3 結尾 | 「你那一組的**行情**呢？」120px／「同業朋友補一下，讓大家知道自己的價錢。」52px／留言格式卡「職類 / 年資 / 月薪區間」44px mono／藍字旁註「只填你願意公開的範圍就好」。**不放網址、不放「註冊」** |
| 字級／配色 | 標題 ≥ 80（封面 150）、內文 ≥ 36；全張只有紅橘一個主色，藍只用在旁註 |
| 注意 | 欄位數固定 7，不隨公司增減（要有可比性）；沒有資料的欄位寫「不確定」，不留空、不猜 |

### G　純文字手寫風（樣張 G，規格圖）

| 項目 | 規格 |
|---|---|
| 用途 | 薪資行情、業內知識、面試經驗的**主力形式**；爆文就是這個形式（約 480 字，無表情符號、無 hashtag、主文無網址） |
| 平台 | Threads |
| 結構 | 七段：搜尋詞標題／圈內梗／來源說明（「朋友分享，有誤麻煩告知」）／欄位清單（「・」條列）／軟評語（一句有立場的話）／面試加料／邀請補充 |
| 排版 | 每段之間空一行；欄位清單一欄一行；不用表情符號；第一行就是「〔公司名〕 行情分享」這種人會去搜的詞 |
| 說明 | 「手寫風」指的是**語氣與結構**（圈內黑話＋自嘲＋邀請更正），不是字型。這張規格圖用紙底＋藍字標籤把七段標出來，給寫稿人對照用 |

### H　面試題卡（樣張 H1、H2）

| 項目 | 規格 |
|---|---|
| 用途 | 面試與職涯：一題一張封面＋答題框架。例：「晶片面積放大 2 倍，良率會剛好剩一半嗎？」 |
| 平台 | IG 輪播、Threads |
| 張數 | 3 張：1 題目／2 答題框架／3 結尾（同 F3 的款式，改成「你被問過最怪的一題？」） |
| 1 題目 | 標籤「面試題 #〔編號〕・領域」32px／橘色大「Q.」240px mono／題目 84px 墨黑（最後一行下劃螢光）／藍字旁註「先想 10 秒，再滑動看答案 →」46px。**鉤子＝先給題目、不給答案** |
| 2 答題框架 | 3 個編號卡（01 先講結論、02 理由、03 一條公式收尾，最後一卡橘框）＋「常見踩雷」一句（44px）。每卡標題 50px＋說明 36px |
| 注意 | 答案要能站得住（樣張的良率公式 `Y = e^(−A·D)` 是標準的 Poisson 缺陷模型）；正式題目由 Andy 的專業把關 |

### I　知識圖解（樣張 I）

| 項目 | 規格 |
|---|---|
| 用途 | 業內知識：把一個概念畫成一張圖（良率、封裝、記憶體分層…）。給面試題卡的答案頁、或單張獨立發 |
| 平台 | IG 輪播（單張或接在 H 後面）、Threads |
| 張數 | 1～3 張 |
| 內容 | 標籤＋標題 70px（結論句，關鍵詞下劃螢光）／兩個並排的圖（各 420px）／圖下：名稱 42px＋數字 44px＋結果百分比 56px 橘／最底一張公式卡。**樣張的圖是程式算出來的**：同一組 8 顆缺陷隨機落在兩片晶圓上，小晶片 68 顆壞 8（良率 88%），面積 ×2 的 30 顆壞 7（良率 77%）；挑的是最接近期望值的一次模擬，不是挑最戲劇化的一次，圖上不寫它是「實測」 |
| 配色 | 好的方塊米色、壞的方塊紅橘、缺陷點墨黑；一張圖一個結論 |
| 注意 | 這類圖的數字一定要能重算；圖形改了就要重新數、不准手調 |

## 五、驗收（逐條過／不過）

對照 `brand_visual_review.md` 第四節五條規範，以及美術總監驗收清單：

| 條目 | 結果 | 備註 |
|---|---|---|
| 規範 1　大頭貼只放比比的臉、單色底 | 過（頻道一）／不適用（頻道二） | 頻道一頭像用 `face_cool` 圓形裁切，樣張左上角即是。頻道二暫無大頭貼，建議用橘色 `[·]` 字標＋紙色底，但頻道名未定，先不做 |
| 規範 2　一圖一結論、標題 ≥ 64、內文 ≥ 32 | 過 | 程式逐元素量字級：15 張 0 筆低於 32px（頁底資訊 28px 屬欄目標記，≥ 24 的門檻） |
| 規範 3　封面＝深色底大字＋一個黃色重點數字；同日不同貼文換構圖 | 過 | 頻道一封面（A1、B）依此；A、B、C、D 四種封面構圖不同；頻道二改用紙底，不是同一張換色 |
