# 冷啟動期的免費／付費安排評估（2026-11-09）

> Andy 11-09 原話：「這類軟體剛開始通常是要先引流吸引人，並且不要放上付費內容，所以幫我評估是否需要先將付費相關資訊遮蔽」「因為需要先吸引用戶，所以如何安排訪客、註冊會員在功能上的觀看次數」。
> 本檔只產出建議，**不改任何程式、不動任何額度**（CLAUDE.md：體驗額度由 Andy 自己設）。
> 信心度：高＝直接讀到程式碼或官方頁；中＝兩個以上獨立摘要一致；低＝單一摘要、或各來源數字互相矛盾。

## 〇、結論（先看這段）

1. **要遮，但遮的是「價格與結帳」，不是「功能」。** 冷啟動期把 #pricing 的價格、結帳入口、各處「升級 Plus／Pro」的文案換成「註冊免費」與「預約通知」。功能本身不藏、不鎖得更緊（藏功能＝讀者第一次來看不到價值）。
2. **這個網站本來就擋不住資料。** 純靜態站＋public repo，`site/data/*.json` 誰都能直接抓；`perm.js` 的鎖頭與模糊是畫面層，不是保護。所以「付費內容」現在根本不存在；能賣的只有「省時間」「商用授權」「匯出」這類（`docs/compliance_and_tiers.md` 387～389 行同樣結論）。冷啟動期不遮價格，只會讓讀者看到一堆自己買不到的東西。
3. **現行額度對「時事當鉤子」有三個洞**（第四節）：
   - 訪客點進個股頁，看不到三大法人、營收獲利、新聞、融資融券、大戶（全部對訪客關）。
   - 分享圖卡只給 3 次。
   - 搜尋只有 5 次。
   這三個正是社群導流最常用的路徑。
4. **註冊會員的額度牆現在是死路。** 牆上寫「Plus 以上可增加」，但 Plus 沒在賣。建議冷啟動期改成「試營運期額度」（註冊會員約 ×2），牆上改寫「明天 00:00 重置」。
5. **打開付費的前提是四道硬條件＋三個需求指標同時達標**（第五節）。其中「資料能不能收錢」我**查不到答案，標未確認**，在釐清前不收錢。

### 1-2 通用基準（不是這個產業）

- 免費轉付費：自助式 freemium 約 3～5% 算好，B2C 偏低；另一份彙整把「無限免費層」寫 2.6%、3.7%。來源多為 B2B 樣本，**不含訪客預覽或註冊牆**的比較。來源：[ChartMogul 轉換報告](https://chartmogul.com/reports/saas-conversion-report/)、[CrazyEgg 彙整](https://www.crazyegg.com/blog/free-to-paid-conversion-rate/)。信心：低（拿來估量級，不拿來當目標）。
- 估算：用 2～5% 推，要有 20 位付費者，需要約 400～1,000 位**活躍**註冊會員。這是算術，不是預測。

### 1-3 從現況看得出的共通做法（我的判斷，非事實）

- 免費層限制的是**工作量**（圖數、指標數、觀察清單數、財報年數、篩選條件），不是把核心畫面拿掉。TradingView、Koyfin、玩股網、財報狗都是這個形狀。
- 這跟 Andy 的分層原則（用「省時間／承擔風險」分，不用「資料多寡」分）一致。
- 我**沒有證據**說哪一家在冷啟動期藏了價格，也沒證據說沒藏。「冷啟動先藏價格」是我依本站狀況做的判斷（第三節理由），不是照抄競品。

## 四、(b) 訪客／註冊會員建議次數

**原則：**
1. 訪客**第一次**就能看到核心價值；第 2～3 次碰到需要登入的動作才請他註冊。
2. 冷啟動期付費沒在賣，額度牆唯一的功能是「促成註冊」與「養成每天回來」，不是「促成付費」。所以**註冊會員的額度應比現在寬**，並明講是「試營運期額度」，之後要收緊時才不會變成「被拿走」。
3. 不改「用工作量分層」的結構（Andy 既有原則）。
4. 次數依據只有我的判斷與一般原則，**沒有本站實際使用資料可驗證**（`quota.js` 有用量統計，但我讀不到線上資料）。上線後第一週用資料校正。
