## 三、建議的新風格方向（給 GPT 幫手照做；皆為假設，用下週資料驗證）

不改自動模板（Andy 10-26 已確認，照 `auto_post.md`）。新增一條「故事型貼文」欄目，依廣達那篇的特徵：

| 項目 | 規格 |
|---|---|
| 標題（第一行） | 「○○ 行情分享」或「○○ 是什麼」，14 字以內，不放 emoji、不放日期 |
| 開頭 | 第 2 行就給「代號＋綽號」與一句白話原因（結論先行，不用問句） |
| 字數 | 250～400 字；超過 480 字縮短 |
| 段落 | 3～4 段，每段 2～3 行，段與段空一行 |
| 條列 | 用「・」，每段 2～3 點；數字（職等、薪資級距）放條列 |
| emoji | 全篇 0～1 個，不放在開頭 |
| 結尾 | 一句邀請回覆的問題（回覆率是目前最缺的指標），再接 hashtag 一行 |
| 網址 | 整篇只在最底一行，帶 `?u=th-xx-yyyymmdd`；故事型貼文先做一組「不放網址」對照 |
| 圖卡 | Threads 輪播 1080×1350，第 1 張大標題＋公司名，第 2～4 張每張一個重點，末張結尾頁；元素不重疊、依 `post_design_system.md` |
| 發文時間 | 先沿用現行時段；時段樣本不足，不下結論 |
| 法遵 | 不喊單、不點名個股推薦、不保證獲利，發前過 legal-compliance；薪資類須是公開資訊並標示來源性質 |

驗證方式：未來 4 週至少發 5 篇故事型貼文與 5 篇功能介紹型貼文，比較觀看中位數、回覆率、分享率；5 篇以內仍標「樣本不足」。

## 四、每週自動更新

1. `social_insights.yml` 每日台北 23:10 自動更新最近 30 篇進 `state/posts_catalog.json`（單筆覆蓋、不刪舊資料）。
2. 全量回補：Actions 手動執行 social_insights，`full` 填 1。
3. 每週一（建議加進排程）：`git fetch origin social-snaps && git show FETCH_HEAD:state/posts_catalog.json > cat.json && python3 scripts/social_style_stats.py cat.json > 附錄`，貼進本文附錄並更新第一節結論。排程進 workflow 需要另排工，尚未做。
4. 樣本滿 5 篇的類別才會取消「樣本不足」標註。
