## 30．交件前四道驗證，四項全過＋審查 ≥7 分才准交件（11-22，全頻道）
Andy 原話：「請你務必確實檢查影片是否丟問題 我就用的問題非常大 為何沒有安排驗證 請重做」。根因：句中插的停頓太密、句子被剁碎；畫面有重疊與空白。
1. **句中 0 停頓**：不准在逗號或句中插靜音；只在換幕處、句號後的自然停頓。
2. **聽感驗證**：成品音訊交 Gemini 音訊理解逐句回報斷續／卡頓／字被切／停頓不自然＋時間點；再跑 ASR 與念稿逐字比對。任一處被標＝不合格。
3. **停頓密度**：句內 0 處；全片 ≥0.25 秒的停頓數 ≤ 句數＋2；`audio-check.py` 數位靜音／斷音／硬起音三項 0。
4. **畫面**：每 1 秒抽一格拼圖，逐格查重疊、空白區 >1 秒、下半部空洞、字太小。
不合格先重切、調版面；原則上不重送 TTS，切不出合格的音才送，送前先回報。交件附四項結果表、抽格拼圖與停頓圖路徑；頻道 CEO 自己再量一次才給 Andy。

## 32．速度快一點、起承轉合更明顯（11-22 晚，Andy 看完 11/27 外食、11/30 小一）
Andy 原話：「兩支都可以 但速度可以在快點 並且多點起承轉合」。
- 配音指令改「語速自然偏快、輕快，約 5.3 字／秒」；換幕不另補停頓，用原始錄音句號後的自然停頓；句中仍 0 停頓；畫面靜止段縮短（每鏡開頭 1 秒內要有動作）。TTS 沒加快就砍字重配，不准事後 atempo 拉伸或壓停頓。片長 ≥45.5、≤60 秒，不夠就補內容（事實與因果）重配。
- **速度上限**（主控定案）：不套「含停頓 ≤4.3」，只看純念稿 ≤5.5 字／秒、以聽感驗證為準；驗證報告寫出純念稿與含停頓兩個數字。
- **起承轉合**：起＝反直覺鉤子問句；承＝數字與出處；轉＝一個「但是／其實」的反轉（旁白裡要真的有這個字）；合＝答案＋跟觀眾有關的問題＋下一集預告。`video_review.md` 標出每鏡屬於起／承／轉／合。

## 33．聲音先定、畫面跟聲音（11-22，全頻道）
Andy 原話：「修正後的影片 要馬是影片正常 旁白斷續，或是影片斷續 旁白正常，幫我處理到好」。
1. **先配音、聲音定稿**：原始錄音只准裁頭（被念出的設定句）、裁尾（念完雜訊）、片頭 0.3 秒淡入；中間不插停頓、不拉伸、不剪句內靜音。工具鏈：`tts/cut_take_v8.py`（atempo 1.0，只用來找每鏡位置）→ `tts/raw_keep.py <原始 wav> <cut.json> queue/<名>/narration.wav` → `tts/make_segments.py`。語速不合或念錯，砍字重配。
2. **畫面依最終聲音的逐字時間戳排**：換幕放在句號後的自然停頓；畫面靜止 ≤1.2 秒、擦出動畫完整、不准空卡；鏡內動作觸發秒數依 narration.wav 的停頓位置訂。
3. **畫面做完不准再改聲音**：要改聲音就整個畫面依新時間戳重排，再跑四道驗證。
