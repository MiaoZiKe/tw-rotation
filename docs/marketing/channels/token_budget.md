## 三、怎麼省（全部照做）
1. **主聊天室只當指揮**：寫稿、渲染、配音、抽格檢查、改字重渲染、文章與貼文製作，各派一次性子 agent，做完就結束，回報 ≤10 行。主聊天室不自己跑渲染、不讀大檔、不看一堆截圖。
2. **子 agent 不准長時間等待**：要等渲染／TTS 超過 5 分鐘的，子 agent 先結束並把狀態寫進檔案，等完成再派新的接手（避免快取過期整段重寫）。批次工作拆成「一支一個子 agent」。
3. **模型分級**：子 agent 預設 sonnet；只有最後審片、看圖判斷、念稿邏輯審查、事實查證定稿用 opus。
4. **一次收齊再做**：改字／排版先收齊所有修改，再渲染一次。
5. **輸出截短**：指令輸出只留摘要（tail、grep），截圖縮小或拼成一張，不把大檔、整段 log、JSON 全文印進對話。
6. **進度寫檔**：決定與進度寫進 HANDOFF／交件紀錄／README，不靠聊天紀錄記憶。
7. **平均分散**：排程盡量平均在每天，不要某天集中重做一大批。

### 分級做法（品質不降：查證、念稿邏輯、重疊檢查、最後審片照舊）
1. **選題＋寫稿**：sonnet 子 agent，**一次寫一週的稿**（同一個 agent 連寫 5～7 支，共用背景，不要一支開一次）。
2. **套版型＋渲染＋重疊檢查**：**不用模型**。固定版型做成一支指令（讀稿 → 出片 → overlap_report → 抽格拼成一張圖），由程式跑；只有報錯時才派 **haiku** 看錯誤訊息修。
3. **數字查證**：sonnet＋WebSearch；只有爭議題、醫療／法律／財務數字才升 opus。
4. **配音**：TTS 一次念完整篇，事前檢查（無「欸」、AI 寫法、句首不是字母）用程式掃，不用模型。
5. **最後審片**：opus，只看「抽格拼圖一張＋字幕稿＋分數表」，**一次審一批**（例如一天的 2～8 支一起審），不逐支開。
6. **改版上限 2 輪**：第 3 輪才要改的，先回報主控找原因（通常是稿或版型規則沒寫清楚，修規則而不是一直重渲染）。
7. **備用稿**：只寫文字＋標題＋素材清單，排進佇列要用時才渲染。
8. **主聊天室不碰製作**：只派工、收 ≤10 行回報（第三節第 1 條），避免每一步重讀整段長對話。
