## 0. 一句話總結

原技能做的事：把一張「靜態設計稿」重建成像素一致的網頁，先從空畫面「柔和載入」，再讓每個視覺「演出自己的用途」並無縫循環，最後用固定時鐘逐格錄成 MP4 與 GIF。
我們的片子不是設計稿動畫，而是「錄網站真實操作＋比比解說」，所以大半（Figma 匯出、背景保護、dissolve 循環）用不到；真正能搬的是 **節奏語言（緩動、時長、錯開）、運鏡規矩、決定性錄製、成品檢查**。

我們現有流程（逐格錄影：`clock.run_for` 推進假時鐘＋`ANIM_JS`、ECharts `animation=false`、`crop_at` 用餘弦緩動推近、`overlap_report`／遮擋／模糊／切字檢查）其實已經踩在同一條路上，下面只列「還能補強」的點。

## 1. 各節重點（中文摘要）與我們可用的做法

### 1.1 情境與範圍（Scope／Two contexts）
- 重點：先分「展示片（整張畫面演）」與「網站內嵌（捲到才動、一次）」；文字區塊不套用。
- 對我們：我們永遠是「展示片」。唯一可借的觀念是「文字（泡泡）不做花俏動畫，只做進出」。無需改腳本。

### 1.2 Part A 保真（A1–A7）
- 重點：重建後的「靜止畫面」要和來源比 PSNR；背景神聖不動；容器各自裁切自己的內容。
- 對我們：我們錄的是真網站，天生保真，不需要。可借的只有兩個觀念：
  1. 「各容器裁切自己的內容、不溢出到鄰居」＝我們的「框緣切字 0」，已有。
  2. 「背景永遠不動、不淡化」＝我們已禁止霧罩。已有。

### 1.3 B1 從空狀態開始
- 重點：每支輸出的第一格是「空狀態」，空變成滿，不要一開頭就是完成畫面。
- 對我們：我們開頭是比比＋需求泡泡，網站畫面「直接就在」。可做法：開頭 0.3～0.5 秒讓取景框內的網站內容先「已載入完畢」再開始（見 1.4），不要拍到載入中的半成品。這和下面「載入完成才開始動作」是同一條。

### 1.4 B2 載入編排（Loading choreography）★
- 重點：元素「從下方升起＋由糊變清」，依閱讀順序錯開 80～90ms；容器之間錯開、容器內依「標題→標籤→數值→視覺」；單組內項目錯開 30～80ms；絕不從 scale(0) 長出物件；整段入場約 2～2.5 秒。
- 對我們（**不採用模糊，見第 3 節**）可直接用的改法：
  1. `render8.py` 的比比進場、泡泡進場：加入「上升 10px＋透明度 0→1」的錯開入場（只用位移與透明度，不用 blur）。泡泡先出、比比動作 0.15 秒後接上，兩者不同時。改善：現在是硬出現，看起來生硬。
  2. 泡泡文字進場用 `translateY(10px)→0`＋透明度，0.7 秒，緩動見 1.6。
  3. 取景一開始前，先在 `capture_trio.py` 的 `run_d`／`run_m` 開頭加「就緒檢查」：字型載完（`document.fonts.ready`，已有）、圖表第一次繪製完成（等圖表容器非空白）、無進行中的網路請求，再開始 `start()`。改善：避免開頭幾格拍到圖表空白或字型跳動。
  4. 比比離場也用同一組曲線，不要瞬間消失。

### 1.5 B3 長條像進度條填滿
- 重點：資料長條用左到右 `clip-path` 揭示，0.7～1.1 秒；不准加原設計沒有的載入線。
- 對我們：我們的長條是網站自己畫的（ECharts 已關動畫）。**可選補強**：若要讓長條「看起來被讀出來」，只能在錄影端用 CSS `clip-path` 做左到右揭示，不改網站。優先度低，且「不造假、畫面是真實網站」仍要成立（揭示結束後與網站完全一致），故列為「可選」。

### 1.6 B4 故事循環（每個視覺演出自己的用途）★
- 重點：先用一句話寫出每個視覺的「故事」（例如：新項目落在最上，舊的後退一格；折線有刮鬍刀掃過，圓點騎在線上，提示框數字滾動）；每 1～2 秒要有一個明確動作，不然就是太膽小；各卡片的故事彼此錯開，注意力依閱讀順序移動；故事要從原樣出發、回到原樣；一個故事 3～8 秒。
- 對我們：我們的「故事」就是真人操作：滑過長條、點節點、換產業鏈。可直接用的做法：
  1. **分鏡表新增一欄「這一段的故事（一句話）」**：寫進每支 `storyboard_final.md`。例如「滑過長條，兩圖同步變」。改善：避免只有「泡泡＋游標點」而沒有因果。
  2. **每 1～2 秒必須有一個可見事件**（點擊、數字變、圖變、比比換表情）；`report8.py` 加一項檢查：把 `clicks`、`says`、`stages` 的時間排序，任意連續 2.0 秒內沒有事件就列警告。改善：抓出「乾等」的段落（Andy 10-19 嫌步調慢）。
  3. **多個連動處不要同時動**：錯開，注意力依閱讀順序（輪盤→排行）。我們已有，寫進準則即可。
  4. 「從原樣出發、回到原樣」：每次圖例隱藏後一定還原（08 已做：外資隱藏→還原）。列為通則。
  5. 數字滾動（counter）：網站本身若沒有，我們不加，不造假。

### 1.7 B5 循環週期
- 重點：展示循環 = 入場 2.4 秒＋故事 8.6 秒＋溶出＋空拍；首尾要接得上。
- 對我們：我們是單次影片，不循環。**不採用溶出到空狀態**。唯一借的是「首尾一致」：封面圖與片尾卡的畫面風格互相呼應（已有）。

### 1.8 B6 緩動與時長（Easing and duration）★
- 重點：入場不用預設 `ease` 或 `linear`。三條曲線：
  - 位移入場：`cubic-bezier(0.16, 1, 0.3, 1)`（快出慢收，約 1.05 秒）
  - 透明度：`cubic-bezier(0.33, 1, 0.68, 1)`（0.7～0.8 秒）
  - 掃過、填滿、運鏡：`cubic-bezier(0.65, 0, 0.35, 1)`（先慢後快再慢）
  - 只有「等速」才用 linear（閃爍、播放）
  展示用的節奏故意比產品介面慢。
- 對我們（可直接用）：
  1. `renderlib_v3.py` 目前只有 `ease(x)=0.5-0.5cos(πx)`（餘弦入出）與 `back_out`。**新增三個函式** `ease_out_expo_like`（對應 0.16,1,0.3,1）、`ease_out_soft`（0.33,1,0.68,1）、`ease_io`（0.65,0,0.35,1），用貝茲求解（牛頓法 4 次即可），全站統一用。改善：現在每個動作都同一條餘弦曲線，沒有「入場快出、運鏡慢入慢出」的分別。
  2. 規則：**入場（比比、泡泡、卡片）= 快出慢收曲線；運鏡 = 入出曲線；不准線性做入場**。
  3. 時長標準表見第 2 節。

### 1.9 B7 運鏡（Camera）★
- 重點：預設不推近不平移，使用者要才做；要做時，只有「畫面主體」縮放，背景不動；運鏡一律用入出曲線；結束前要回到原位。
- 對我們：Andy 的圖二要求「只留需要畫面」，所以我們一定要推近（裁切放大）。可直接用：
  1. `render8.py` 的 `crop_at` 推近：把預設時長 `dur=0.4`、延遲 `lag=0.3` 改成「依移動距離」：小幅（取景框變化 <15%）0.45 秒、中幅 0.6 秒、大幅 0.8 秒；曲線用 `ease_io`。改善：現在固定 0.4 秒，大幅推近太猛、小幅又拖。
  2. 推近和「游標移動／點擊」不同時進行：先推近停穩（≥0.2 秒）再點，點完再動鏡頭。改善：避免點擊瞬間畫面還在漂，觀眾看不清。
  3. 同一時間只動一個鏡頭、單向；不來回抖（08 分鏡已寫「單向推近」）。
  4. 推近只改裁切框，不改畫面內容尺寸以外的任何東西，維持「零模糊、零遮擋」。

### 1.10 B8 效能與無障礙
- 重點：只動 transform／opacity／filter／clip-path；模糊 ≤14px；尊重 reduced-motion。
- 對我們：只借第一點——**錄影端自己加的任何效果只用 transform／opacity／clip-path**。filter 與 blur 依 Andy 規定禁用。

### 1.11 B9 動態檢查 ★
- 重點：錄完編碼前，對逐幀圖做檢查：
  - 溢出檢查：容器以外的像素每一幀都要和空白首幀完全一致；
  - 接縫檢查：循環首尾一致；
  - 空拍檢查、休止檢查（故事結束後的畫面要等於靜止稿）；
  - 接觸表（contact sheet）：把關鍵時刻縮圖拼一張看有無溢出、殘影、突跳、太膽小。
- 對我們（可直接用）：
  1. **「休止檢查」改寫為「還原檢查」**：每個互動（換產業鏈、隱藏圖例）結束後，目標區域的像素應與互動前一致（或與網站該狀態一致）；`report8.py` 新增一項。改善：抓到「還原不完全」的殘留。
  2. **「溢出檢查」改寫為「取景框外不變檢查」**：我們不做此項（取景框外本來就被裁掉），但「比比、泡泡之外的像素等於網站原樣」可用在抓「錄影端 CSS 意外改了版面」。
  3. **接觸表**：`report8.py` 另輸出 `contact_sheet.png`（每 2 秒一格＋每個點擊前後各一格，縮成 6 欄），交件時附給 Andy 與監察委員一眼看全片。改善：目前只有 overlap_report，沒有「整片一眼看」。
  4. 「突跳／殘影」檢查：相鄰兩格像素差超過門檻且該刻沒有登記的事件（點擊、鏡頭、泡泡進出）→ 列警告。
  5. 接縫檢查用在「片尾卡 0.2 秒交疊接上」：交疊前後一格的畫面差要在門檻內。

### 1.12 C1 決定性錄製 ★
- 重點：不即時螢幕錄影。用假時鐘一格一格推進，每格截圖：
  1. 每格的毫秒數用整數且平均剛好等於 1000/60（17,17,16…），不要每格 `runFor(1000/60)`，會漂移；
  2. 「開始」與「seek」寫在同一個 evaluate 裡；
  3. 頁面時鐘只經 `__tick` 推進，不依賴 requestAnimationFrame；
  4. CSS 過渡也用 `getAnimations()` 暫停＋手動設 `currentTime`，才會跟假時鐘走；
  5. 無窮動畫（閃爍、跑馬燈）改由 JS 時鐘驅動，不用無限 CSS keyframes；
  6. 先錄約 15 格「預熱」讓頁面穩定；窗口之後多錄 10 格供接縫檢查。
- 對我們：我們已有大半（`flowlib.Rec.frame` 用 `clock.run_for`、`self.acc` 累加取整已等同第 1 點；`ctx.clock.install` 固定時間；ECharts `animation=false`）。**仍可補強**：
  1. 確認 `Rec.frame` 對「CSS 過渡／動畫」有走 `getAnimations()` 同步（`C.ANIM_JS` 看起來負責這件事；請 motion-designer 對照技能第 4 點核對，未同步者補上）。
  2. 錄影端 init script 加固定亂數：`Math.random` 換成種子化版本（固定種子），網站若有隨機動畫（輪播、粒子）每次錄結果一致。改善：重錄不會因為隨機差異而讓分鏡秒數對不上。
  3. 預熱格數固定為 15 格（約 0.5 秒），不計入成片。
  4. 關掉網站會自己動的東西（輪播、跑馬燈）：我們已在 `EXTRA_CSS` 隱藏部分；把清單寫進準則。
  5. 輸出解析度取偶數（技能的 `crop=trunc(iw/2)*2`）：我們已是 1920×1080／1080×1920，無需改。

### 1.13 C2 輸出格式
- 重點：MP4 H.264 yuv420p、`+faststart`、CRF 14–15、preset slow；GIF 用調色盤兩段式（palettegen／paletteuse）、有照片用 bayer 抖色；太大先降幀率與色數，再降尺寸。
- 對我們：已用 MP4。若之後要出 GIF（客服鈕或貼文貼圖），照這個兩段式指令；影片建議 `-crf 15 -preset slow -movflags +faststart`（若 `render8.py` 現在不是這組，對齊它）。

### 1.14 Make it yours（參數總表）
- 技能把所有時長、距離、曲線集中在一張表，要求「不要臨時發明數值」。對我們：把第 2 節那張表放進 `renderlib_v3.py` 頂端當常數（`T_BUBBLE_IN` 等），腳本只引用常數。改善：數值一致、好調整。

## 3. 跟我們規則衝突、不採用的部分（以 Andy 規定為準）

| 技能做法 | 不採用原因 |
|---|---|
| 入場「由糊變清」（blur 4～14px）、照片 blur 14px | Andy 10-22：模糊也算遮擋，全片零模糊（含網站毛玻璃）。入場只用位移＋透明度 |
| 載入時淡入（opacity 0）網站內容 | 取景框內網站內容不准被淡掉（10-21 禁止淡化遮罩）。只有比比與泡泡可淡入，網站畫面不淡入 |
| 從空狀態重建、整片溶出再重來（B1、B5） | 我們拍真實網站、單次播放、一鏡到底、片尾是免責卡，不循環不溶出 |
| 把設計稿重建成 HTML、用 Figma 匯出圖層、PSNR 對照（Part A） | 我們錄的就是真網站，沒有設計稿；也禁止用假畫面取代真實畫面 |
| 計數器「滾動數字」、故事裡加的複製項目、假游標、額外脈衝 | Andy：不造假資料、訪客真實畫面。網站沒有的動態不加 |
| 脈衝光環、心跳、掃光（sheen）、閃爍類強調 | Andy 歷史偏好：不閃爍、不脈動、不跑馬燈 |
| 長條「填滿」揭示、加載入線 | 網站長條是真資料；只當可選，揭示結束必須與網站原樣一致；不加任何網站沒有的線 |
| 技能預設「不推近」 | 我們要「只留需要畫面」（Andy 圖二），一定推近；僅借其曲線與規矩 |
| 展示節奏偏慢（1 秒以上入場、故事 3～8 秒） | Andy 10-19／10-21：步調要快，成片 ≤40 秒；入場時長取下限、泡泡每則 ≤14 字，慢的地方一律砍 |
| 60fps、1920×1200 上限、GIF 960 寬 | 我們現行 30fps、1920×1080／1080×1920 已夠，不改；60fps 檔案大且收益小 |
| 網站內嵌（IntersectionObserver、捲到才動） | 不是我們的場景 |
| Figma 令牌、`?still`／`?loop`／`?capture` 頁面模式 | 不是我們的場景；唯一借的是「不依賴 requestAnimationFrame」的觀念（我們已用假時鐘） |

另：技能開頭寫「使用者明確指示優先於技能規則」，與我們一致；本筆記的優先序已寫在最上方。

## 4. 下一支影片怎麼改（落地順序，由易到難）

1. `renderlib_v3.py`：加三條貝茲曲線＋時長常數表（上面第 2 節），全站引用。
2. `render8.py`：推近時長依距離分三級、曲線換入出；泡泡與比比進離場換位移＋透明度（零模糊）。
