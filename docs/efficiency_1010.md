## 二、桌機守門1008：更快、更不容易假紅

### 現況拆解（origin/main 的 `t_desk_guard_1008`）

| 段 | 走幾頁 | 每頁固定等 | 固定等待合計（推算，機器閒時） |
|---|---|---|---|
| ① 結構指紋 | 72 頁（含 22 題材、17 個個股分頁） | `wait_for_timeout(1800)`＋捲動＋500（個股分頁再 +900） | ~185 秒 |
| ② 說明卡在左右 | 剖析圖 ~31 張＋22 題材（推算 ~53 頁） | 1600 | ~85 秒 |
| ②-b 孤兒編號 | 同上 53 頁 × 1440／1920 兩種寬 | 1500 | ~160 秒 |
| ②-c 先進封裝 | 4 次（2 寬 × 2 主題） | reload＋1600 | ~10 秒 |
| ③④⑤ 收合／關聯圖 | ~10 頁 | 2200～2600＋多次 300～1200 | ~50 秒 |
| **合計** | | | **~490 秒**（閒時實測綠燈 554～580 秒，其餘是頁面本身與量測） |

結論：**守門有八成以上時間在睡固定秒數**。機器忙的時候固定秒數不夠 → 假紅；機器閒的時候固定秒數太多 → 白等。兩個問題同一個根因。

### 建議做法

| 代號 | 做法 | 省多少（推算） | 代價／會漏抓什麼 |
|---|---|---|---|
| **A** | **固定等待改成條件等待**：`desk_open` 改成 `wait_until(pg, 指紋連續兩次一樣, 8000, 250)`（量 `DESK_FP_JS` 兩次、間隔 250ms，相同才收）；個股分頁先 `wait_for_selector('#stockTabs button[data-t="<tab>"]')` 再點，點完等「該按鈕帶 `.on`」；先進封裝等 `#prodDiagram svg.dg.icp` 出現（上限 15 秒）；關聯圖收合後等 `REL().under === 0`（上限 5 秒）而不是固定 700ms | 閒時每頁 2.3 秒 → ~0.6 秒，**① 省 ~120 秒、②＋②-b 省 ~150 秒**；忙時不會再因為「還沒畫完」而紅 → 上面 25～28 次假紅中，分頁沒切過去（10）、找不到 svg（5）、關聯圖計時（~12）這三型全部消失 | 不漏抓。唯一差別：真的「一直在變」的頁（例如有動畫的版面）會等到上限 8 秒才收 —— 這種頁本來就該修 |

## 三、減少合併衝突

實測：95 個合併中，兩邊都改到的檔 —— `_uitest.py` 69、`mobile4.css` 22、`app.js` 22、`industry.js` 15、`mobile4.js` 12、`HANDOFF.md` 12、`desktop_1440.json` 6。

插入點也量了：10-09 這批改 `_uitest.py` 的 commit，新增位置集中在 **檔尾 66,300～67,000 行**（新測試函式）與 **32,555 行**（`SECTIONS = {` 的下一行，新段落一律插在字典最上面）；`mobile4.css` 集中在 **1,210～1,226 行（檔尾）**。兩個熱點，每支分支都往同一處塞。

| 檔 | 做法 | 為什麼有效 | 代價 |
|---|---|---|---|
| `scripts/_uitest.py` | **新段落一段一檔**：`scripts/uitest/sec_<名稱>.py`，檔尾自己寫 `SECTIONS["名稱"] = lambda pg, b, base, code: t_xxx(b, base)`。`_uitest.py` 在讀參數前加一個載入器：`for p in sorted((Path(__file__).parent / "uitest").glob("sec_*.py")): exec(compile(p.read_text("utf-8"), str(p), "exec"), globals())`，**之後再算一次 `SECTION_NAMES = list(SECTIONS)`** | 每支分支新增的是不同檔名，git 不會衝突；用 `exec` 進同一個 globals，`ok`、`J`、`wait_until` 這些共用工具照用，**舊的 338 段不用搬** | `--only`／`--sections` 的子字串比對不受影響；要注意新檔不能重複用到既有段落名（載入器發現重名就直接報錯） |
| `site/mobile4.css` | **按頁分檔**：一次性拆成 `site/m4/overview.css`、`flow.css`、`industry.css`、`stock.css`、`themes.css`、`etf.css`、`account.css`、`common.css`，`index.html` 一次全部掛好；每個檔整份包在 `@media (max-width:640px)` 裡 | 「一件事只派一人」＋「一頁一檔」→ 兩個人同時改同一頁的機率很低；不再全部擠檔尾 | 一次性搬家要跑一次「手機v2」＋桌機守門；`stamp_assets.py` 要確認會蓋到新檔；`index.html` 從此不用再加 link（除非新增頁面） |
| （拆檔前的過渡） | `mobile4.css` 檔尾預留具名區段：`/* §overview */ … /* §overview end */`，新規則寫進自己頁的區段，**不准寫在最後一個區段之後** | 不同頁的改動落在不同區段，就不會在同一行衝突 | 靠紀律，不是機器保證 |
| `tests/desktop_baseline/desktop_1440.json` | 寫檔改成**一頁一行**（`"\n".join(f'{json.dumps(k)}:{json.dumps(v)}' …)` 包成合法 JSON，或直接 `indent=1`） | 現在整份是**一行**（`separators=(",",":")`），任何兩次更新基準都必定衝突；改成一頁一行後只有改到同一頁才衝突 | 檔案變大一點（34 KB → 約 60 KB） |
| `HANDOFF.md`（70 萬字元，12 次兩邊都改） | 每批的紀錄寫成 `docs/handoff/<日期>-<分支>.md`，`HANDOFF.md` 只留「下一步」與索引 | 同上，新增檔不衝突 | 讀進度要多開一個檔 |

不建議：`.gitattributes` 的 `merge=union`。它會把兩邊都留下，CSS 還勉強，Python 字典或函式會被拼壞，而且**不會報錯**。

## 四、小修正快速通道（機器判斷）

判斷一律用這三個指令的輸出，不靠印象：

```
git diff --name-only origin/main...HEAD
git diff --numstat origin/main...HEAD
python scripts/m4_scope_check.py   # 待寫：檢查每一行改動所在的最外層 CSS 區塊
```

`m4_scope_check.py` 的判法（已手動驗證過可行）：把改動後的 `site/mobile4.css` 去掉註解、數大括號深度，找出每一條改動行所在的最外層區塊標頭；**全部都是 `@media (max-width:Npx)` 而且 N ≤ 640 才算過**。
現況：`mobile4.css` 25 個最外層區塊裡，22 個 `@media (max-width:640px)`、2 個 `@media (max-width:380px)`、1 個不在 media 裡的 `.m4sh{display:none}`（第 8 行，刻意的：桌機藏手機短標題）—— 改到第 8 行就不算 L1。

| 通道 | 機器條件（**全部**成立） | 要跑什麼 | 跳過什麼 |
|---|---|---|---|
| **L0 文件** | diff 只含 `docs/**`、`*.md`、`obsidian/**` | 不跑任何關卡 | 桌機守門、_preview、_uitest、監督 |
| **L1 手機純 CSS** | diff 只含 `site/mobile4.css`（拆檔後：`site/m4/*.css`）；`m4_scope_check.py` 過；新增＋刪除行數 ≤ 40 | 該頁對應的 1 段 `_uitest`（例如 `手機v2`）＋ 390／360 兩張截圖 | **桌機守門**（CSS 在 >640 物理上不生效）；**監督不重量**，只看截圖比對 |
| **L2 單頁 JS 小改** | diff 只含第二節 D 表裡「可以縮範圍」的檔；新增＋刪除行數 ≤ 30；沒碰 `app.js`、`index.html`、`layout4.css`、`chart.js` | 對應段落 ＋ 桌機守門 `--desk-routes auto`（只守那幾頁） | 監督只量 diff 碰到的路由 |
| **L3 完整** | 其他全部（含任何 `app.js`、共用 CSS、`pipeline/**`） | 照現行流程 | — |

估省（推算，信心低）：10-09 的 18 件帳本小修**還沒有逐件分類**有幾件會落在 L1（第六節第 6 項就是回頭分類）。符合 L1 的那幾件，每件從 ~50 分鐘（中位數）降到 ~15 分鐘，主要是省掉 10～18 分鐘的桌機守門、一次監督重量與一次快取過期重寫。

⚠ L1 唯一會漏的：手機版的 CSS 改壞了**同一頁的其他手機元件**（不是桌機）。那一段 `_uitest` 加截圖就是為了這個，所以 L1 不准連那一段都跳。
