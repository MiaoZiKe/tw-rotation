# 3D 精緻化規格：從「灰、透明、扁平」到半寫實科技產品展示

> Andy 2026-09-22 晚：「我希望達到『精緻的科技產品 3D 展示／半寫實資訊圖表』風格。
> 請從**配色、材質、燈光、陰影與後製**一起改善，**不要只提高飽和度或更換背景**。」
> 目標參考：`docs/diagram_refs/3d_rack_light_glass.webp`（＝他說的圖六，主要方向）、
> `docs/diagram_refs/3d_rack_dark_light_split.webp`（＝圖五，深／淺兩模式的參考）。

## 〇、先診斷：為什麼現在是灰的、透明的、扁的（機器查出來的，不是感覺）

| # | 根因 | 證據（`site/three3d.js`） | 造成的症狀 |
|---|---|---|---|
| **1** | **完全沒有環境貼圖（envMap）** | 1715 行 `new THREE.WebGLRenderer({antialias:true,alpha:true})` 之後沒有任何 `scene.environment`／PMREM；1130 行註解自己寫「這個場景**只有方向光、沒有環境貼圖**，所以 metalness 壓在 0.45 以下」 | **這是最大主因。** PBR 的金屬幾乎全靠環境反射，沒有 envMap 的 `metalness` 只會變暗灰 → 只好把金屬度壓低 → 銀灰機架、銅件、散熱片全都變成「霧面塑膠」。閱讀模式 `--dg-metal-k:.6` 再砍一刀，更塑膠 |
| **2** | **沒有真的陰影** | 1984–1989 行：接觸陰影是一片 `MeshBasicMaterial` ＋ radial sprite 貼在模型底下，`renderer.shadowMap` 從頭到尾沒開、沒有任何 `castShadow` | 托盤與托盤之間、晶片與板子之間**沒有投影**，所以看不出上下層關係 → 扁 |
| **3** | **透明疊了太多層** | 玻璃 `opacity .3`、外殼 `--dg-shell-a .55~.58`、ghost `.14`、引線 `.75`、光點 `.9`、AO 墊 `.4`，而且 `transparent:true` 的東西沒有統一排序 | 五六層半透明疊在一起 → 偏淡、偏雜亂、前後分不清 |
| **4** | **打光只有四盞平行光 ＋ 半球光** | 1754–1758：hemi .62／key 1.0／fill .34／bounce .16／rim 0（rim 預設關） | 平行光沒有距離衰減、沒有面積感；頂面／側面／底面的明暗差幾乎只靠法線方向 → 像色塊 |
| **5** | **顏色依「角色」而非「模組功能＋材質」** | `FAMILY` 對照表把零件映到 `--dg-pcb/--dg-metal/--dg-cer/--dg-si`，但 v9 又依 `role`（sig／pwr／cool／air）整片上色 | 整台被青藍色洗掉；關掉標籤就認不出哪塊是電源、哪塊是運算 |
| **6** | **色溫收斂把畫面洗灰** | `--dg-sat` 1.2／1.0、`--dg-mix` 往 `#dde6f5`（科技）或 `#f2ede3`（閱讀）收、`--dg-mix-k` 閱讀 .08 | 閱讀模式整體往奶油白霧化，對比掉下去 |
| 7 | 曝光與色調映射偏保守 | `ACESFilmicToneMapping`、`--dg-expo` 1.05／1.0 | ACES 會把高光壓下來，沒有 envMap 補高光的情況下中間調整片發灰 |

> 色彩空間本身沒問題：用的是 three 的新 API（`THREE.SRGBColorSpace` 出現在 1804 行），
> r152 以後 `outputColorSpace` 預設就是 sRGB，**不需要改**。問題全在上面 1～7。

## 一、要改什麼（依影響大小排序）

### 1. 加環境貼圖（改完金屬才會是金屬）
- `site/vendor/three.module.min.js` 裡有 `PMREMGenerator`（核心），**沒有** `RoomEnvironment`（那是 examples）。
  **不要新增 vendor 檔**（Andy 公司網路擋 CDN，repo 內建原則）——用**程序式環境**：
  建一個小 `THREE.Scene`，放 3～5 片發光面（上方大面積柔光板、左右兩片冷／暖補光板、下方暗板），
  用 `PMREMGenerator.fromScene()` 產生 `envMap`，指給 `scene.environment`。兩種模式各一份（顏色不同）。
- 有了 envMap 之後：**解除 metalness 上限**。銀灰機架 `metalness .85 / roughness .35`、
  銅件 `.9 / .3`、散熱鰭片 `.7 / .45`、晶片蓋 `.6 / .4`；PCB 是介電質 `metalness .05 / roughness .55`。
- `--dg-metal-k` 閱讀模式從 `.6` 拉回 `1.0`（那個 0.6 是為了掩飾沒有 envMap 的暗金屬，根因修掉就不必了）。
- `envMapIntensity` 給一個 token `--dg-env`（科技 .9、閱讀 1.15）。

### 2. 開真的陰影（但只給大件）
- `renderer.shadowMap.enabled = true`、`type = THREE.PCFSoftShadowMap`。
- **只有主光 `key` 投影**，`shadow.mapSize 1024`、`shadow.camera` 貼著模型外接盒收緊（不收緊會糊）。
- **只有「大件」castShadow**：機櫃框、托盤、PCB、PSU、電池、風扇框、冷板、上蓋。
  小零件（錫球、接口、電容、走線）一律 `castShadow=false`，不然 draw call 與陰影 pass 會爆。
- **接收面**：托盤上表面、機櫃底板 `receiveShadow=true`。現有的 radial sprite 墊片**留著**當軟接觸陰影，兩者疊加。
- 效能有疑慮就先只在 ≥960px 開陰影，手機關掉（`--dg-shadow` token 0/1）。

### 3. 把透明度收回來（Andy 第 2 點：降低整體透明感）
- **原則：主要零件一律不透明。** 只有這三種可以透明：
  1. 機櫃**外殼板**（要看見內部）→ `--dg-shell-a` 提到 `.28`（更透，但只有外殼）
  2. **液冷管線** → 青綠半透明 `opacity .62`、`roughness .15`、有厚度（雙層圓柱：外管半透明、內層水體較飽和）
  3. 被「爆炸拆解」隱藏的示意層
- `ghost`（.14）**只保留給真的是示意的殼**，其餘改實體。
- 所有 `transparent:true` 的材質補 `depthWrite`：實體透明件（管線、外殼）**要** `depthWrite:true`＋`alphaTest`，
  只有發光點／引線才 `depthWrite:false`，避免現在那種「前後疊成一片」。

### 4. 依「模組功能」分配顏色與材質（Andy 第 1 點，關掉標籤也要認得出）
| 模組 | 顏色 | 材質參數 | token |
|---|---|---|---|
| 機架／滑軌／鈑金 | **銀灰霧面金屬**（科技 `#B8C2CC`／閱讀 `#C9D1D9`） | metal .85 rough .35 | `--dg-m-rack` |
| PCB 板材 | **墨綠→青綠**（`#0E3B32`／閱讀 `#2E6B58`） | metal .05 rough .55 | `--dg-m-pcb` |
| PCB 走線／焊墊 | **金色**（`#E6B95C`） | metal .9 rough .28 | `--dg-m-trace` |
| 晶片本體（GPU／ASIC／CPU） | **深藍**（`#1E2E52`）／**石墨灰**（`#3A3F47`） | metal .35 rough .45 | `--dg-m-die` |
| 晶片散熱蓋／鰭片 | 銀灰金屬，比機架亮一階 | metal .7 rough .4 | `--dg-m-hs` |
| 銅件／接頭／快接頭 | **暖銅／香檳金**（`#C98A5E`／`#D9B48A`） | metal .9 rough .3 | `--dg-m-cu` |
| 液冷管線 | **青綠半透明**（`#2FB8A6`） | rough .15 op .62 厚度感 | `--dg-m-cool` |
| 風扇外框 | **藍灰**（`#5A7285`）或暖銅（依機種） | metal .5 rough .5 | `--dg-m-fanf` |
| 風扇葉片 | **實體**深灰藍（`#2E3A45`），**不准只剩透明輪廓** | metal .2 rough .6 op 1 | `--dg-m-blade` |
| 電源／BBU | 暖橘（`#E08A3C`）＋石墨灰 | metal .4 rough .5 | `--dg-m-pwr` |
- **冷暖對比是刻意的**：冷（銀灰／墨綠／青綠）佔七成，暖（銅／香檳金／橘）佔三成當點綴。
- `--dg-sat`／`--dg-mix-k` 的整體收斂**降到接近 0**（`sat 1.05`、`mix-k .02`），
  顏色差異交給上面這張表，不要再用全域色溫把它洗掉。

### 5. 打光重做（Andy 第 3 點）
- 主光 `key`：改成有方向、有陰影的暖白（`#FFF4E6`，科技 1.25／閱讀 1.05），從右上前 45°。
- 補光 `fill`：冷白（`#DCE9FF`，.4），從左下後，**不投影**。
- 輪廓光 `rim`：**兩種模式都要開**（科技 .8 冷青白、閱讀 .35 暖白），從後上方，把零件邊緣勾出來。
- 半球光 `hemi`：天空色／地面色分開（科技 `#1B2740`／`#05070C`；閱讀 `#E8EEF5`／`#B9C2CC`），強度降到 .35——
  envMap 進來之後半球光不需要那麼強，否則又會洗平。
- 曝光 `--dg-expo`：科技 1.0、閱讀 1.12；色調映射維持 `ACESFilmic`（它讓高光滾降自然，配 envMap 才看得出好處）。

### 6. 發光克制（Andy 第 4 點）
- 只有四種東西可以發光：**指示燈**、**資料流／光路**、**液冷流向**、**被點選的那一顆**。
- 發光一律用小面積 emissive ＋ 低強度（`--dg-led .7`／閱讀 `.3`），**不准整片 emissive**、不准大光暈。
- 暖橘發光只當點綴（電源指示燈），數量 ≤ 3 處。

### 7. 後製（Andy 說「適度後製」）
- **不引入 EffectComposer**（要多一支 vendor 檔、又多一次 render pass）。
  改用**零成本的等效做法**：
  - 背景改成**徑向漸層 canvas texture** 當 `scene.background`（科技深海軍藍 `#0A1428`→`#060B14`；
    閱讀淡藍灰 `#E8EDF2`→`#D6DEE6`）—— 這就是圖五／圖六的底。
  - 用 envMap 的上下色差 ＋ rim 光取代 bloom。
  - 真的要輝光就只給 ≤3 個發光小件加一層 additive sprite（現在流線已經是這個做法）。

## 二、驗收（Andy 自己訂的兩條）
1. **關掉文字標籤**（把 `.lbl3d` 全部 `display:none`）截圖，**仍能靠配色與材質認出**：機架／PCB／晶片／銅件／液冷／風扇／電源 七類。
2. **縮到 360px 寬**截圖，**仍看得出主體輪廓、前後層次、冷暖對比**。
3. 既有功能一個不能少：零件對應、旋轉縮放、爆炸拆解、標籤連線、點背景恢復、E4 動畫開關、localStorage、≤700 收合。
4. 效能：機櫃場景三角形 ≤ 40,000（目前 39,822，**加陰影前要先減面**）；draw call ≤ 680；1440 下 FPS ≥ 30。

## 三、所有 2D 圖都要有對應的 3D（Andy 同一則的第二件事）
> 「所有 2D 圖都要補上 3D 圖，且風格一樣，版面左右調整適當不浪費空白處。」

- 現況：17 張 2D 只有 3 張有 3D（`ai_server`／`semiconductor`／`mlcc`）。**要補 14 個 3D 場景。**
- 每一張的 3D 用**同一套**材質族與打光（上面那張表），差別只在零件組成。
- **版面**：3D 與 2D 共用 v2 版面（畫布在中、卡片左右欄、容器寬判欄數），
  3D 畫布高度吃到欄寬的 0.62，左右不留空白（現在 3D 在寬螢幕下四周留太多黑）。
- 排程：地基（本規格）先做完並上線，再分波補 14 個場景，每波 2～3 張。
