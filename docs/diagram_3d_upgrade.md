# 3D 剖析圖要補到 2D 那個細緻度 —— 計畫

> **Andy 2026-09-22**：「我覺得你後來做的 2D 都非常棒，細緻程度有符合我標準，
> **所以所有 3D 圖請都麻煩補上這樣程度的細緻程度**。」
>
> 同一天稍早他還講了判準：「**不能看起來只有像是一般的方塊，他是電路圖就是要有電路圖的樣貌。
> 有 IC 就有 IC 在上面**」（`DECISIONS #234`）。

## 1. 「2D 那個細緻度」到底是什麼 —— 先把標準寫死

他說「後來做的 2D」指的是這幾張：ABF 載板、PCB 硬板剖面、液冷、氣冷、PSU＋BBU、
面板疊層、交換器板卡、MLCC。它們共同做到、而現在的 3D **沒有**做到的事：

| # | 2D 有的 | 現在的 3D |
|---|---|---|
| D1 | **真的幾何**：層別有厚度差、孔有錐度、走線有線寬、圓角與倒角 | 一律 `box`／`tray`／`rack` 這種原始方塊 |
| D2 | **零件長得像那個零件**：電感有繞線、電容有端電極、連接器有金手指 | 同尺寸的色塊，靠標籤分辨 |
| D3 | **一眼看得出主角**：主角佔畫面 30% 上下，配角退到灰階剪影 | 每個零件一樣重，排成一列 |
| D4 | **逐件說明 ＋ 誰做的**：每個零件掛 `parts:`，點了就說是誰做的、料號是什麼 | 只有 `name` 與一行 `note` |
| D5 | **有數字**：層厚、線寬、節距、瓦數、溫度，而且標出可信度 | 幾乎沒有 |
| D6 | **誠實**：台股沒人做的明說、查不到的標查不到 | 沒有這一層 |

所以「補到 2D 的細緻度」＝ **D1～D6 六項逐一補齊**，不是「多加幾個方塊」。

## 2. 現況盤點（機器數的）

### A. `site/three3d.js` —— 3 個場景，1449 行

| 場景 | 目前長什麼樣 |
|---|---|
| `ai_server` | 機櫃／背板／托盤／GPU 模組，全部由 `kind: rack/backplane/tray/box` 這類原始形狀堆出來 |
| `semiconductor` | CoWoS 剖面的立體版（⚠ 依 `DECISIONS #234` 這張的 2D 要退掉、3D 搬到 `ai_adv_packaging`） |
| `mlcc` | 積層陶瓷電容 |

`SCENES` 是「宣告式」的：每個零件一行設定，交給共用的 `kind` 產生幾何。
**這個設計本身是對的**（好維護、好加新場景），問題出在 **`kind` 的字彙太貧乏** ——
只有方塊系。要補細緻度，該做的是**把 `kind` 的字彙擴充成真的零件**，
不是回頭一個一個手刻 mesh。

### B. `site/themes3d.js` —— 18 張題材產品圖，551 行

`cowos`／`hbm_memory`／`pcb_ccl`／`glass_substrate`／`asic_ip`／`ai_server`／`power_bbu`／
`thermal`／`silicon_photonics`／`semi_equipment`／`apple_chain`／`edge_ai_pc`／`robotics`／
`drone`／`satellite`／`ev_auto`／`defense`／`heavy_electric`

**18 張全部只走兩個通用樣板**（`chainScene()` 與 `explodeScene()`），
每張大約 14 行設定 —— 畫出來就是「排成一列的方塊」。
這 18 張是 Andy 這句話**最主要**的對象。

**總共 21 個 3D 場景要處理。**

## 3. 做法：擴充零件字彙，不是手刻 21 次

分三層做，每一層都可以單獨驗收、單獨上線：

### 第一層 —— 把 `kind` 的字彙補成真的零件（一次做完，21 張全部受益）
在 `three3d.js` 新增一組可重用的零件產生器，每一個都吃參數、回一個 `THREE.Group`：

- **板類**：`pcb`（有走線、焊墊、絲印、鍍通孔、金手指）、`substrate`（增層 + 微孔）、`interposer`（TSV 陣列）
- **晶片類**：`die`（有切割道與金屬層紋理）、`hbm`（顆粒堆疊 + TSV）、`bga`（錫球陣列）、`bump`（微凸塊陣列）
- **被動元件**：`mlcc`（端電極）、`inductor`（繞線／磁芯）、`resistor`、`ecap`（電解電容圓柱 + 防爆紋）
- **散熱**：`heatsink`（鰭片陣列）、`vc`（真空腔 + 毛細結構）、`heatpipe`、`fan`（葉片有攻角）、`coldplate`（水路）
- **連接**：`connector`（金手指／籠子）、`cable`、`busbar`
- **機構**：`rail`、`screw`、`bracket`、`chassis`（沖孔網）

判準照 `docs/diagram_purpose.md` 的 **R2**：
**再細下去會不會對到不同的公司／不同的原理？會才畫，不會就別畫。**
細節不是越多越好 —— 一顆螺絲畫出螺紋不會讓人更懂，但 PCB 上有沒有走線會。

#### ✅ 第一層已完成（2026-09-22，分支 `claude/dg-3d-parts`）

**新增 18 個 `kind`**（舊的 25 個一個都沒拿掉 —— 新字彙是「多出來的詞」，不是換掉）：

| 類別 | 新增的 `kind` | 畫出來的識別特徵 |
|---|---|---|
| 板類 | `interposer` | 貫穿整片的 TSV 陣列（77 根）＋ 表面重佈線 |
| 晶片類 | `bump` | 銅柱 ＋ 錫帽，14×10 一整片（micro-bump 跟錫球差一個數量級） |
| 晶片類 | `bga` | 載板 ＋ 模封 ＋ 第 1 腳圓點 ＋ 底下 9×7 錫球（腳全在肚子底下） |
| 被動 | `mlccchip` | 陶瓷本體 ＋ 端電極包住端部（Ni／Sn 兩層露出來） |
| 被動 | `inductor` | 鼓型磁芯 ＋ **看得見的繞線**（7 圈）＋ 兩端電極 |
| 被動 | `resistor` | 陶瓷基板 ＋ 電阻膜 ＋ **雷射調阻切口** ＋ 端電極 |
| 被動 | `ecap` | 鋁殼 ＋ **頂部防爆紋（十字刻痕）** ＋ 絕緣套 ＋ 負極條 |
| 散熱 | `heatsink` | 底板 ＋ 鰭片陣列（片數隨寬度自動算） |
| 散熱 | `vc` | 下銅板 ＋ 燒結毛細層 ＋ 蒸氣腔 ＋ **支撐柱陣列** ＋ 上蓋只蓋一半 |
| 散熱 | `heatpipe` | 壓扁的彎管 ＋ 切口露出「外銅管／毛細／蒸氣道」三層 |
| 散熱 | `coldplate` | 銅底板 ＋ 18 片微流道鰭片 ＋ 半開蓋板 ＋ 藍進紅出的接頭 |
| 連接 | `connector` | 屏蔽金屬籠 ＋ 塑膠舌片 ＋ 舌片上的金手指 ＋ 背面壓接針 |
| 連接 | `cable` | 四股絞線（TubeGeometry 沿曲線）＋ 束帶 ＋ 端子殼 |
| 連接 | `busbar` | 厚銅排 ＋ **穿過厚度的鎖固孔** ＋ 中段絕緣套 |
| 機構 | `rail` | ㄈ 型外軌 ＋ 抽出來的內軌 ＋ **兩排滾珠** |
| 機構 | `screw` | 六角頭 ＋ 墊圈 ＋ 桿（**刻意不畫螺紋**，見下面 R2） |
| 機構 | `bracket` | L 型折板 ＋ 補強肋 ＋ 鎖固孔 |
| 機構 | `chassis` | 面板 ＋ **112 孔的沖孔網** ＋ 折邊 ＋ 把手 |

**升級 3 個既有 `kind`**（外觀變的是「更細緻」，不是跑版；構圖與相機取景維持原樣）：

- `pcb` ＋ 焊墊陣列、絲印（零件外框＋第 1 腳記號）、鍍通孔、板面前緣的金手指
- `substrate` ＋ 第二層增層（階梯狀）、雷射盲孔（**錐形**，跟硬板的直筒通孔分家）
- `die` ＋ 切割道（四周一圈）、頂層金屬縱橫紋理

**效能（量出來的，不是憑感覺）** —— `stats()` 新增 `drawCalls` / `triangles`，讀的是
`renderer.info.render`（WebGL 真的送出去的東西）：

| 場景 | draw call（前 → 後） | 三角形（前 → 後） | mesh（前 → 後） |
|---|---|---|---|
| `ai_server` | 680 → **485** | 13,184 → **23,144** | 671 → **476** |
| `semiconductor` | 129 → **114** | 14,368 → **16,672** | 126 → **111** |
| `mlcc` | 93 → 93 | 1,476 → 1,476 | 93 → 93（沒動到它用的 kind） |

細節多了 76%，**draw call 反而少了 29%** —— 因為陣列類（錫球、凸塊、鰭片、TSV、沖孔、
滾珠、金手指、進氣孔、電芯、背板端子、探針）一律收成 `InstancedMesh`／合併幾何。
單一 `kind` 最貴的是 `bump`（8,400 個三角形／2 個 mesh）。

**R2 的實際應用**（`docs/diagram_purpose.md`）：螺絲**沒有**畫螺紋 ——
再細下去對到的還是同一批公司，畫了只多幾千個三角形。相對地 PCB 的走線、電感的繞線、
電容的防爆紋都畫了，因為那些各自對到不同的製程與不同的廠。

**驗收**：`scripts/_uitest.py --only 3D零件字彙`。它驗的是畫面真的改變：
三個場景各開一次、真的用滑鼠點零件（只亮那一個）、真的點背景（全部恢復全亮）、
四個配色各切一次（量材質色的指紋）、動畫開關真的停得住、每個 `kind` 單獨量三角形數
（下限＝不准只是一顆方塊，上限＝不准失控）。

### 第二層 —— 逐場景換零件並重排構圖（21 張，可並行）
每一張把原本的方塊換成第一層的真零件，並且照 **D3** 重排：主角放大、配角退成灰階剪影。
同時補 **D4**（`parts:` 的「誰做的」）與 **D5**（數字＋可信度）。

### 第三層 —— 動畫拉滿（Andy 同一批的另一條需求）
「所有動畫都需要再更生動，動畫效果要拉滿，讓讀者更明白運作原理」。
**動畫要說明原理，不是裝飾**：訊號沿走線跑、熱從晶片流進冷板、
風從鰭片穿過、電流從 PSU 走到 GPU、晶圓一層一層疊上去。
`prefers-reduced-motion` 與既有的「動畫：開／關」鈕都要照舊有效。

## 4. 排序（跟 2D 的 19 張交錯排，不要互相卡）

1. **第一層零件字彙** —— 一支 agent，做完 21 張都受益。**最優先，因為它是其他所有事的前置。**
2. `ai_adv_packaging` 的 3D（`DECISIONS #234` 要從 `semiconductor` 搬過來）＋ `ai_server`＋`mlcc`
   —— 這三張是產業鏈頁上會被點開的，優先。
3. 題材頁 18 張 —— 每支 agent 3～4 張，5～6 波。

## 5. 硬規則（跟 2D 完全一樣，不因為是 3D 就放寬）

- 顏色一律走 `--dg-*`，**JS 裡不准寫死色值**。四個配色（科技／柔和／沉穩／休閒）都要成立。
- 3D 的材質色與 2D 讀同一組變數 —— 這是 Andy「2D3D 都需要新增那樣的風格」的實作（`DECISIONS #230`）。
- 字級下限 12px。
- 點零件只亮不篩（`DECISIONS #73`）；**點背景恢復全亮**（2026-09-22 新增）。
- 每張都要在 `scripts/_uitest.py` 有一段**真人操作**驗收，而且驗「畫面真的因此改變」。
- 效能：21 張不可以讓頁面變卡。每張要量 draw call 與三角形數，訂上限。
