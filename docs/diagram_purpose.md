# 產業鏈剖析圖是幹嘛的 —— 這一頁的目的（所有圖的最高指導原則）

> **Andy 2026-09-21：**
> 「這整頁的目的是讓讀者透過模擬設備的樣貌，更詳細觀察且直觀了解產業關係及做的事情，
> 所以盡可能拆解解析公司負責項目及產品。」

這句話**位階高於每一份 `docs/diagram_specs/*.md`**。規格書講「這張圖怎麼畫」，
這份講「圖為什麼要存在」。兩者衝突時以這份為準。

## 1. 一句話：圖不是插圖，是「誰在做什麼」的入口

讀者看這一頁不是為了欣賞一張剖面圖，而是要回答一個很具體的問題：

> **「這個東西裡面有哪些零件？每一個零件是誰在做？他做的到底是什麼產品？」**

所以一張圖畫得再漂亮，只要**看完還是不知道哪一塊是誰做的**，它就沒有完成任務。

## 2. 由此推出的硬規則（每一張新圖都要過）

### R1 —— 每個畫出來的零件都要能回答三個問題
「這是什麼」「誰做的」「做的是什麼產品／料號」。
三個裡面有任何一個答不出來，那個零件要嘛補資料、要嘛**明說答不出來**（見 R4），
不可以畫一個沒有身分的形狀在那裡充版面。

### R2 —— 拆到「對得到公司」的粒度，不要停在籠統的方塊
判準不是「畫幾層比較好看」，是**「再拆下去會不會對到不同的公司」**：

- ✗ 畫一個方塊寫「PCB」→ 對到的是一整群公司，等於沒有資訊
- ✓ 拆成 核心層 / 增層 / 防焊 / 表面處理 / 銅箔 / 玻纖布 / 樹脂
  → 每一層對到的是**不同的環節、不同的公司**，這時候拆才有意義

反過來也成立：**再拆下去對到的還是同一批公司，就不要拆**，那只是讓圖變複雜。

### R3 —— 公司在這個零件上負責什麼，要用既有資料，不准自己編
`supply_chain.yaml` 裡已經有兩個欄位就是在講這件事，用它們：

- `companies[].tech` —— 這家公司做的項目（例：創意 3443 → 「ASIC 設計服務」）
- `edges[].item` —— 兩家公司之間流動的**料號**（例：味之素 → 欣興，item：「ABF 增層膜」）

**不准在圖上寫出這兩個欄位裡沒有的角色描述。** 想寫就先去查、查到了先補進 YAML
（而 YAML 的成分由 Andy 校訂，繪圖端不能自己加公司 —— 見 `AGENTS.md` §5）。

### R4 —— 台股沒有人做的零件，要明說，不可以留白
留白會讓讀者以為「這裡漏了」或「這裡不重要」，兩個都是錯的判斷。
正確做法是**寫出來是誰做的、並標明不是台股**：

> 「ABF 增層膜：味之素（日）全球 >95% 市占，近乎獨占。**台股沒有廠商做這一層。**」

這種「台股做不到的地方在哪裡」本身就是很有價值的資訊 —— 它就是整條鏈的卡點。

### R5 —— 查不到就標「查不到」，不准為了畫面完整而編一個對應
這條跟 `DECISIONS #201`（查不到具名客戶就不連邊）是同一件事。
圖上寧可出現一個誠實的「?」，也不要出現一個看起來很完整但其實是湊的對應關係。
`WebSearch` 的摘要特別會自己「補」出原文沒有的公司對應（見 `CLAUDE.md` 的兩個實際案例）。

### R6 —— 「模擬設備的樣貌」是手段，不是裝飾
Andy 要的是**看起來像那個東西**，因為只有像，讀者才把「圖上這一塊」跟
「現實中那個零件」對起來。所以：

- 比例要對（一片 12 吋晶圓上切出幾顆晶粒、一個機櫃塞幾台伺服器）
- 結構順序要對（燒結在端電極之前、背照式的光電二極體在佈線層上面）
- 但**不需要照片級寫實** —— 過度寫實反而會蓋掉標註。清楚 > 逼真。

## 3. 現況的缺口（機器確認過，不是印象）

我去讀了程式碼，現在的行為是：

| 使用者做的事 | 現在發生什麼 | 缺什麼 |
|---|---|---|
| 點圖上的一個零件 | 那個零件最亮、同環節的其他零件次亮、其餘變暗 | **不會告訴你這個零件是誰做的** |
| 點下面的環節色標 | 成分股清單篩成那個環節 | 是環節層級，不是零件層級 |
| 點個股小卡 | 右側展開「誰供給它、它供給誰」，有品項與可信度 | 要先知道要點誰 |

`site/industry.js` 裡 `segPick` 上方的註解自己就寫了
「使用者只是想知道『這個零件是誰做的』」—— **但程式碼沒有回答這個問題，只做了高亮。**
（刻意的，`DECISIONS #73` 決定點零件不篩選。那個決定沒有錯，錯的是**只高亮、不解釋**。）

這正好就是 Andy 這句話指出來的洞。

## 4. 要補的功能（尚未實作）

**點零件 → 出現一張小卡**，內容：

1. 這個零件是什麼（一兩句白話）
2. 它屬於哪個環節
3. **做這個的台股有誰** —— 公司名、代號，以及它在這裡負責什麼（`companies[].tech`）
4. **相關料號** —— 從 `edges[].item` 撈出來（例：ABF 增層膜、銅箔、玻纖布）
5. 台股沒有人做就照 R4 明說，並寫出實際上是誰做的

注意：**不改 `DECISIONS #73`** —— 點零件還是只高亮、不篩選成分股清單。
這張小卡是「多給資訊」，不是「改掉既有行為」。

零件 → 公司的對應寫在**各自的 `site/dg/<slot>.js` 裡**（繪圖端的事），
不進 `supply_chain.yaml`（那是 Andy 校訂的成分表）。
