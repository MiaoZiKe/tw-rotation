  - 授權條款：<https://data.gov.tw/license>
- 期交所下載頁「前 30 個交易日期貨每筆成交資料」（不含鉅額），*.rpt 與 *.csv 兩種格式。（信心：高）

- 同名資料集也在 data.twse.com.tw 目錄：<https://data.twse.com.tw/search/detail/Mjg5MGQ0YWEtZDQwNC00ODc4LWExNGEtNGQwNmQ0MzBjMWU0>（信心：中）

**網站條款會不會擋**
- 期交所自己的「使用條款」頁**讀不到內文**（搜尋只確認頁尾有這個連結）。這一點是缺口。

  **但經由政府資料開放平臺授權公眾使用之資料不在此限**」，引用時要標示出處、保持資料完整。（信心：中；摘要轉述）
  - <https://www.twse.com.tw/zh/terms/use.html>（這一頁是證交所的條款，**不是期交所的**；只當旁證）
- 判斷：我們抓的是**資料集 20668 的資源檔本身**（每日一個 zip），它以開放授權條款釋出，
  跟 openapi.twse 是同一類；開放授權條款明文允許「改作」與「以衍生物開發產品或服務」，合成 1 分 K 屬於改作。
  所以結論是「可用」；信心只給「中高」而不是「高」，是因為期交所自己的網站條款沒讀到原文。

**使用限制（寫進程式與頁面）**
1. **出處標示**：頁面上寫「台指期逐筆資料來源：臺灣期貨交易所（政府資料開放平臺 資料集 20668，政府資料開放授權條款第 1 版）」。
   已放進總覽大盤三張圖的「?」說明（`site/market3.js` 的 `srcNote()`）。
2. **只抓資源檔**：`config.TAIFEX_TICKS_CSV`（`Daily_YYYY_MM_DD.zip`），**不抓期交所其他網頁**。
3. **頻率**：一個檔只下載一次（`data/_state/taifex_ticks.json` 記進度）；404 的舊日期記成假日不再試；
   15:30 那輪不抓（當天的檔多半還沒出）。第一次跑會把窗內約 30 個檔一次補完，之後一天一個。
4. 期交所只保留前 30 個交易日，**窗外的補不回來** —— 所以要每天接著存（DECISIONS #155：會重複用到的就要進湖）。

**檔案格式（依期交所欄位名稱與社群文件描述，不是實抓；信心：中）**
- 下載網址樣式 `https://www.taifex.com.tw/file/taifex/Dailydownload/DailydownloadCSV/Daily_<yyyy>_<mm>_<dd>.zip`
  （社群教學與 GitHub 爬蟲專案都用這個樣式；信心：中）。
  - <https://medium.com/coding-learning-sharing/%E9%80%8F%E9%81%8Epython%E9%96%8B%E5%95%9F%E5%A4%96%E9%83%A8%E6%8C%87%E4%BB%A4%E9%80%B2%E8%A1%8C%E7%88%AC%E8%9F%B2-%E4%BB%A5%E4%B8%8B%E8%BC%89%E5%8F%B0%E7%81%A3%E6%9C%9F%E8%B2%A8%E4%BA%A4%E6%98%93%E6%89%80%E7%9A%84%E5%85%AC%E9%96%8B%E8%B3%87%E6%96%99%E7%82%BA%E4%BE%8B-c65be81b2f1f>
  - <https://github.com/andy010629/taifex-crawler>
- 欄位：成交日期、商品代號、到期月份(週別)、成交時間、成交價格、成交數量(B+S)、近月價格、遠月價格、開盤集合競價。
  ⚠ 這串欄名在搜尋時是**我自己放進查詢字串的**，摘要只是照著複述，不能算獨立證據；
  所以 parser **不寫死欄位順序**：找表頭關鍵字（成交日期／商品代號／到期月份／成交時間／成交價格／成交數量），
  找不到且第一欄也不像日期就整檔不收、把回應前 200 字印進 log。
- 「成交數量(B+S)」＝買賣雙邊合計，口數＝÷2（摘要一則；信心：中低）。所以程式**不靠記憶**：
  `taifex.vol_divisor()` 每次都拿日盤近月的加總跟資料湖 FinMind 日 K（`index_ohlc` FUT）比，
  比值 ≈2 → ÷2、≈1 → 不除、都不像 → 照 ÷2 並記 warning。

**夜盤歸屬（高信心）與逐筆檔的日期寫法（中信心）**
- 期交所規定：盤後交易時段（國內股價指數類 15:00～次日 05:00）之交易**屬於次一一般交易時段**，
  「每日交易及結算作業以一般交易時段收盤為劃分點」。（信心：高）
  - <https://www.taifex.com.tw/cht/4/aHIntroduction>
- 期交所查詢頁：「盤後交易時段之交易日期係指其交易量歸屬日期，例如標示交易日期 2017/7/4 之 TX 盤後資料，
  為 2017/7/3 下午 15:00 開始交易至 2017/7/4 凌晨 05:00」。（信心：高；但這句是**三大法人夜盤查詢頁**的註記，不是逐筆檔的說明）
  - <https://www.taifex.com.tw/cht/3/futContractsDateAh>
- **逐筆檔的「成交日期」到底寫歸屬日還是日曆日，沒有查到第一手說明。**一則摘要說「應以歸屬日期記錄」，
  但那像是從上面那句查詢頁註記推出來的，不算獨立證據。
- 所以程式不猜，由資料本身判斷（`taifex.detect_convention()`）：
  同一個檔裡夜盤晚上那段與凌晨那段日期相同 → 歸屬日；凌晨比晚上晚一個日曆日 → 日曆日；判斷不出來 → 跟同批其他檔，
  整批都判斷不出來才照期交所公告口徑當歸屬日。歸屬日寫法時，晚上那段的真正日期＝歸屬日的前一個交易日
  （交易日曆＝檔內日盤日期＋資料湖日 K 日期），找不到就不收那幾筆 —— 寫錯的時間進只增不改的湖就洗不掉。
- 存進湖的 `ts` 一律是真正的台北牆鐘時間；「這一晚是哪天開的盤」由 `intraday_bars.session_key()` 照牆鐘算
  （夜盤 4H 歸在開盤那天，跟前端 `sessKey()` 一致）。**注意：這跟期交所的「歸屬次一交易日」是兩件事**——
  前端畫圖用開盤那天當格子，官方結算用次一交易日，兩者不衝突。
