# 精選文章快速流程（省 Token／省時間版，2026-10-17）

Andy 10-17：「產文章這邊我不希望花費太多 Token 和時間，CEO 幫我看看有沒有優化空間」。
這張卡是**每小時排程與撰寫 agent 唯一要讀的文件**；`production_guide.md` 只在遇到卡上沒寫到的狀況時才去查那一節（用 grep 找，不要整份讀）。

## 實測花費（10-17 這幾篇，subagent 處理的 token 數）

| 環節 | 實測 | 目標 |
|---|---|---|
| 撰寫（查資料＋寫） | 16～21 萬 | ≤ 10 萬 |
| 插圖（草稿＋實作＋審） | 22 萬（第一版）＋ 42 萬（重畫，含新積木） | ≤ 10 萬（套現成積木）；新種類才走完整流程 |
| CEO 審稿＋上架 | 長對話裡每一步都很貴 | 每小時新對話，≤ 5 萬 |
| 一篇合計 | 約 60～90 萬、1.5～2.5 小時 | **約 20～30 萬、40～60 分鐘** |

## 一篇文章的流程（照順序，不要加步驟）

1. **CEO（排程對話）**：讀 `data/_state/article_jobs.json` 拿一筆 → 標 `stage=plan`。只派**一個** agent（`general-purpose`，**Agent 工具帶 `model: "sonnet"`**，較便宜的模型；Andy 10-17：「用便宜模型」），把這張卡的「撰寫 agent 規則」整段貼給它。CEO 自己審稿那一關照樣用排程對話本身的模型把關。
2. **撰寫 agent 一次做完文字＋插圖＋影片**（不要拆成寫手、動畫導演、網頁單位三個 agent，各自重讀文件最貴）：
   - 查資料：**WebSearch 最多 8 次**。每個關鍵數字兩個來源對上就停；查不到就不寫，不要換第三、四組關鍵字硬找。
   - 字數：快訊（news）內文 ≤ 600 字；介紹、知識 ≤ 900 字。
   - 圖：**最多 2 張**（含插圖、影片）。插圖只在文章講到**實體產品**時才畫，一律 `style:2`，**先套現成積木**（box／cyl／balls／pipe／wheel／hcyl／shell 與 detail），不新增渲染器積木；套不出來就不畫，改用表格或 steps。
   - 影片：有活動就 1 支（規則見 `production_guide.md` 影片區塊那幾行：可用轉載，內容要是真實現場畫面），**最多搜 2 次**，找不到就不放。
   - 截圖：只截 **2 張**（1440 淺色、390 深色）＋跑 `scripts/illus_audit.py`；量測沒過才截放大圖修。
   - 全文只存 scratchpad，不准進 repo。
3. **CEO 審**：只看那 2 張截圖＋量測結果＋來源清單。畫面不像、有重疊、數字沒來源 → 退一次，第二次還不行就**拿掉插圖照常上架**（不要第三輪）。
4. **上架**：`article_publish.py` → 推 `site/articles/index.json` → `deploy_wait.py` 印 ✅ → 標 `done`。
5. **只在新種類插圖**（渲染器畫不出來的新產品）才找動畫單位＋網頁單位走 `illus_style.md` 第 5 節完整流程；那是一次性的工程，做完之後同類文章都能直接套。

## 撰寫 agent 規則（CEO 派工時整段貼）

- 全程繁體中文；不給投資建議；不畫商標、logo。
- 格式照 `site/articles/posts/` 舊文章（只讀一篇當範本）；插圖欄位照 `production_guide.md` 的「illus 第 2 版欄位表」（grep 那一段，不要整份讀）。
- WebSearch ≤ 8 次；摘要裡的「中文名（英文名）」對應一律另外查證；數字要確認是誰的（母子公司）。
- 每篇最多 2 張圖；快訊 ≤ 600 字；截圖只 2 張；全文只寫在 scratchpad。
- 交件：全文 JSON 路徑、2 張截圖路徑、`illus_audit` 結果、來源清單、不確定的地方（5 行內）。

## 每小時空跑

佇列空的 → 觸發同步、讀檔、回「佇列空的」，**不讀任何其他文件、不派 agent**。
