## 花費（第 1 版實測 → 第 2 版目標）

| 環節 | 第 1 版實測 | 第 2 版目標 |
|---|---|---|
| 撰寫（企劃圖表＋本站數據＋查證＋寫＋截圖） | 16～21 萬，但只有 0～2 張圖 | ≤ 17 萬，數據圖 ≥ 3 張 |
| 插圖（只在講實體產品時） | 22～64 萬 | 套現成積木 ≤ 5 萬（算在撰寫裡）；新種類才走完整流程 |
| CEO 審稿＋上架 | 長對話裡每一步都很貴 | 每小時新對話，≤ 5 萬（評分表） |
| 退件重做（最多 1 次） | — | ≤ 5 萬 |
| 一篇合計 | 約 60～90 萬、1.5～2.5 小時 | **約 22～30 萬，上限 35 萬、50～70 分鐘** |

多出來的預算只花在兩件事：**用 Python 讀本站資料湖做圖**（便宜、競品沒有）與**把查證數字畫成圖**；不花在多開 agent、重讀文件、多截圖。

## 一篇文章的流程（照順序，不要加步驟）

1. **CEO（排程對話）**：讀 `data/_state/article_jobs.json` 拿一筆（`kind: "topics"` 的先照最下面「主題候選」那節做）→ 標 `stage=plan`。只派**一個** agent（`general-purpose`，**Agent 工具帶 `model: "sonnet"`**），把下面「撰寫 agent 規則」整段貼給它。
2. **撰寫 agent 一次做完**企劃＋數據＋文字＋圖＋（必要時）插圖、影片：
   - **先企劃**：照 playbook 第 1、2 節列「圖表企劃」4～6 列（圖 → 回答的問題 → 區塊 → 資料來源），再動手查；答不出問題的圖不做。
   - **本站資料優先**：開工 `git pull`，用 playbook 第 3 節的 Python 讀 `data/` 資料湖，只印要上圖的數字；**至少 1 張圖用本站資料**（族群漲跌、法人買賣超、營收、估值）。
   - **查證**：WebSearch **最多 10 次**；每個上圖數字兩個獨立來源對上（或本站資料）；查不到就換一張查得到的圖，不寫「本文未查到」當結論。
   - **字數**：快訊 ≤ 600 字；介紹、知識 ≤ 900 字（不含圖表內文字）。
   - **圖**：快訊數據圖（`chart`）≥ 3；介紹、知識 `chart` ≥ 2 ＋其他圖 ≥ 2；全篇 4～6 張（不含 `kpi`／`table`／`stocks`）。每個小節至少一個視覺；三句話重點後第一個區塊就是鉤子圖。
   - **插圖**：只在講實體產品時畫，一律 `style:2`，**只套現成積木**（box／cyl／balls／pipe／wheel／hcyl／shell 與 detail）；套不出來就改 `steps`／`compare`。
   - **影片**：有活動就 1 支（規則見 `production_guide.md` 影片區塊），**最多搜 2 次**（算在 10 次內），找不到就不放。
   - **截圖**：只截 **2 張**（1440 淺色、390 深色）；有插圖加跑 `scripts/illus_audit.py`。
   - **自評**：照 playbook 第 5 節評分表自己打一次分，< 75 先自己補到 ≥ 75 再交。
   - 全文只存 scratchpad，不准進 repo。
3. **CEO 審**（排程對話本身的模型，好模型花在這裡）：只看 2 張截圖＋數字清單＋自評分，照 playbook 第 5 節評分。
   - 一票否決（法遵用語、數字沒來源、圖與來源不符、畫面重疊）→ 退。
   - ≥ 75 上架；60～74 退一次附扣分項；< 60 退一次並要求換角度。
   - 第二次仍 < 75：刪掉扣分的圖或段落後重算，≥ 70 上架；否則標 `failed` 寫原因，**不跑第三輪**。插圖不過就拿掉插圖照常評分。
4. **上架**：`article_publish.py` → 推 `site/articles/index.json` → 標 `done` → **馬上做下一筆**（2026-10-19 Andy：「平均一篇文章要多久，為何這麼慢」——原本一輪只做一篇、還要乾等部署 20～30 分鐘，下一篇要等下一個整點）。
   - **一輪連做**：同一個排程對話做完一篇接著做佇列裡下一筆，最多連做 4 篇或做到 50 分鐘為止；下一篇的撰寫 agent 可以在上一篇審稿時就先派出去（同時最多 2 個撰寫 agent）。
   - `deploy_wait.py` **整輪最後只跑一次**（GitHub 會把連續幾次推送併成最後一次部署），印 ✅ 才回報；中途不等。
5. **只在新種類插圖**（渲染器畫不出來的新產品）才找動畫單位＋網頁單位走 `illus_style.md` 第 5 節完整流程；做完之後同類文章直接套。
6. 需要新圖表區塊（例如正負上色、參考線、甜甜圈）時，**不在產文那一輪改程式**：用現有區塊頂著，需求記進 playbook 第 7 節，CEO 另外派網頁單位。

## 撰寫 agent 規則（CEO 派工時整段貼）

- **類別內容要求**：知識必放 3D／2.5D 產品架構圖（查 `diagram_inventory.md`）、快訊挑熱門話題、產業鏈必有供應鏈圖，三類都盡量附影片 —— 見 `topic_gen.md`「類別定義與內容要求」。
- 全程繁體中文；不給投資建議、不寫目標價、不點名「值得關注」的個股；不畫商標、logo。
- 先讀 `docs/articles/visual_playbook.md`（整份，約 210 行）；格式照 `site/articles/posts/` 舊文章（只讀一篇當範本）；插圖欄位照 `production_guide.md` 的「illus 第 2 版欄位表」（grep 那一段）。
- 動筆前列「圖表企劃」4～6 列；至少 1 張圖用本站資料湖（`git pull` 後 `PYTHONPATH=. python3 <scratchpad 裡的程式>`，只印結果，不把整張表印出來）。
- 圖數：快訊 `chart` ≥ 3；介紹、知識 `chart` ≥ 2＋其他圖 ≥ 2；全篇 4～6 張。圖標題寫一句結論；`note` 寫口徑、`source` 寫來源與日期。
- 標題照 playbook 第 4 節公式、≤ 26 字；標題的數字要在第一屏看得到。
- WebSearch ≤ 10 次；摘要裡的「中文名（英文名）」對應一律另外查證；數字要確認是誰的（母子公司）；比較要同一把尺。
- 快訊 ≤ 600 字、介紹與知識 ≤ 900 字；截圖只 2 張；全文只寫在 scratchpad。
- 交件（10 行內）：全文 JSON 路徑、2 張截圖路徑、圖表企劃表、數字清單（數字 → 來源 1／來源 2 或本站資料表）、自評分一行、`illus_audit` 結果（有插圖才有）、不確定的地方。

## 主題候選：新增主題請求＋每日自動（2026-10-17）

Andy 10-17：「幫我每天都下午收盤後三個類別都會更新 3 個主題……並多新增一個新增主題 Btn……也可以我提供關鍵字你幫我生成主題」。

- **佇列裡 `kind` 是 `topics` 的請求**（`topic_id` 是 `gen-…`，管理區「＋ 新增主題」鈕送的）：照 **`docs/articles/topic_gen.md`** 處理 —— 解析 `note` 的 `cats=`／`n=`／`kw=` → 生成主題 → 只推 `site/articles/topics.json` → 標 `done`（`result`＝`topics+<題數>`）。
  - 用便宜模型 agent（`general-purpose`，`model: "sonnet"`，把 `topic_gen.md` 路徑交給它）或 CEO 自己做皆可；**token 上限 8 萬**、WebSearch ≤ 6 次。
  - 它不是文章：不走上面「一篇文章的流程」、不派撰寫 agent、不跑 `article_publish.py`；跟文章請求同時排隊時**先做它**（幾分鐘就好，做完 Andy 才有新題可選）。
- **每日自動**：台北週一～五 **14:00 之後的第一輪**排程，若 `site/articles/topics.json` 還沒有 `added`＝今天的主題 → 三類各生成 3 個（同一份 `topic_gen.md`，沒有請求要標）。已經有（例如 Andy 下午先按過新增主題）就不做。
- 這兩件事做完、佇列又沒有別的請求 → 照下面「每小時空跑」結束。

## 每小時空跑

佇列空的、而且不是「每日自動」該做的那一輪 → 觸發同步、讀檔、回「佇列空的」，**不讀任何其他文件、不派 agent**。
