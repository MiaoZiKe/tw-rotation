# 商業化上架規劃（App ＋ 電腦版 ＋ 付費方案）

> 建立：2026-09-24（台北）。參考對象：Tide 潮汐 <https://tide-tw.app/pricing>。
> 定價已拍板：**免費／399／799（每月）**。本文件是規劃，尚未動工。

## 0. 前置門檻（未解決前不收費）

1. **投顧法風險**：依《證券投資信託及顧問法》，「收費」＋「個股分析／建議／買賣點」同時成立即可能構成非法投顧（5 年以下有期徒刑）。
   - 付費層只賣「資料整理與視覺化」；「進場時機」「建議追蹤」「技術評分」等字樣改中性描述或只留在免費層。
   - 全站免責聲明：「非證券投資顧問事業，不構成投資建議」。
   - **上架前律師諮詢一次**（我們查得到法條，但不能代替法律意見）。
   - 來源：[全國法規資料庫](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=G0400121)、[陳全正律師整理](https://maxlawyer.tw/blog/business-investment/)
2. **證交所資料授權**：加值後提供他人使用需書面契約並付費；即時資訊須簽使用契約。
   `mis.twse.com.tw` 不可拿來轉售 → 399 方案的即時資料須改向授權資訊商（FinMind 付費、Fugle 等，逐一確認商用條款）或向證交所申請。
   - 來源：[交易資訊使用管理辦法](https://www.twse.com.tw/zh/products/information/use.html)
3. 成立公司／行號（金流商要統編）。

## 3. 實作步驟（依序）

1. 法規與授權（第 0 節）。
2. 會員與權限：Supabase（Auth ＋ Postgres ＋ Row Level Security）。
3. **付費資料搬離 public**：目前 `site/data/*.json` 在 GitHub Pages 任何人可下載 → 付費 JSON 改由後端（Cloudflare Worker）驗證 token 與方案後才發送。
4. 金流：藍新／綠界申請（1～3 週），付款完成的回呼（notify）寫入訂閱到期日；串電子發票。
5. 統計：PostHog 或 GA4 → DAU／MAU、次日／7 日留存、免費→付費轉換率、邀請轉換率；後端另存最後登入時間算回訪。
6. 邀請碼：三張表（invite_codes / referrals / rewards），綁付款或手機驗證防分身。
7. App 與電腦版：先 PWA；Android 用 TWA；iOS 用 Capacitor。App 內購抽 15～30%，付款導向網頁（依當時商店規範確認）。電腦版 PWA 即可。
8. 客服、條款、上線。

## 4. 維運

| 項目 | 做法 |
|---|---|
| 伺服器 | 不自架主機：Cloudflare Pages（靜態）＋ Workers（付費 API、即時報價快取）＋ Supabase。初期每月約 0～1,500 元 |
| 大量使用者 | 靜態檔走 CDN 無虞；**即時報價必須後端每分鐘抓一次、所有人共用快取**，不可讓使用者各自打來源 |
| Debug | Sentry 前端錯誤；Actions 失敗通知；公開狀態頁 |
| AI 客服 | Claude API ＋ FAQ／說明文件；退款、帳務、答不出 → 寄 support 信箱建工單。**禁止回答個股買賣建議** |
| 激勵 | 邀請送天數、年繳折扣、早鳥價、連續登入徽章、付費會員產業週報（產業資訊，非個股建議） |
| 其他 | 發票、個資法隱私權政策、退款政策、資料延遲補償說明、同時登入裝置數限制、資料湖備份（目前只有 GitHub）、一人維運的值班成本 |

## 5. 資安與資料外洩防護

### 5.1 我們會持有哪些敏感資料
| 資料 | 敏感度 | 原則 |
|---|---|---|
| 信用卡號 | 最高 | **永不經手**：一律用金流商代管頁面（藍新／綠界），我們只拿到訂單編號與結果 |
| Email、登入身分 | 高（個資） | 存 Supabase，RLS 限本人讀寫 |
| 自選股、觀察清單 | 中（可推測持股） | 同上；不寫入任何 log 與分析工具 |
| 訂閱狀態、付款紀錄 | 高 | 只有後端 service key 可寫 |
| API 金鑰（FinMind、金流 HashKey/HashIV、Supabase service key、Claude API key） | 最高 | 只放 GitHub Secrets／Cloudflare Secrets；**public repo 不得出現** |

### 5.2 必做清單
1. **Repo 仍是 public**：任何後端金鑰、會員資料、付費資料都不可進 repo；push 前的金鑰掃描照舊，並開啟 GitHub secret scanning。後端程式建議另開 **private repo**。
2. **付費牆在伺服器端**：前端隱藏按鈕不算保護；每一個付費 JSON 請求由 Worker 驗 JWT ＋ 方案 ＋ 到期日。
3. **金流回呼驗簽**：藍新／綠界的回呼一定要驗 CheckValue／TradeSha，金額與訂單比對，防偽造「已付款」。回呼要能重複送達而不重複加天數（冪等）。
4. **Supabase RLS 全表開啟**；前端只用 anon key；service key 只在 Worker。
5. **防爬與防共用帳號**：Worker 限流（每帳號／每 IP）、同時登入裝置上限、付費資料加使用者浮水印（外流時可追來源）。
6. **帳號安全**：GitHub、Cloudflare、Supabase、金流後台、網域商全部開 2FA；金流後台不共用帳號。
7. **前端**：Content-Security-Policy、只載入自家 vendor（已內建，不走 CDN）；使用者輸入（清單名稱等）一律跳脫防 XSS。
8. **AI 客服**：不給它讀其他使用者資料的權限；防提示注入（使用者輸入只當資料）；對話紀錄去識別化、設保存期限。
9. **依賴套件**：開 Dependabot；鎖版本。
10. **備份與還原**：Supabase 每日備份；資料湖另存一份到非 GitHub 的儲存（例如 Cloudflare R2）；每季實測還原一次。
11. **外洩應變**：寫一頁應變程序——撤換金鑰順序、通知受影響使用者（個資法要求）、公告模板。
12. **日誌**：記錄登入、付款、權限變更；日誌中不存卡號、token、完整 email。
13. **上線前**：自我檢查 OWASP Top 10；有預算時做一次外部弱點掃描。
