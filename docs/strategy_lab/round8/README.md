## 五、最終驗證怎麼跑（補齊後；每個凍結候選每池只准一次）

1. 確認旗標：`git fetch origin main`，`git show origin/main:data/_state/backfill_progress.json` 的 `balance+financial+revenue@2012-01-01` 必須 `done: true`（目前 false，剩 balance 274／financial 274／revenue 273）。
2. 取回補齊後的資料（只覆蓋 data/，不 commit）：`git checkout origin/main -- data`。
3. 執行：`python pipeline/compute/rev_lab8.py`。程式會自己再檢查旗標與「2013 年池內營收覆蓋 >= 50%」，不符就不執行；符合才對 `frozen_candidates.json` 的每個候選 x 前 200／前 100 檔池各跑一次 2013-02-01～2016-12-09（含 0050 同窗含息），寫入 `final_log.csv`、`final_2013_2016.csv`，**之後重跑只讀紀錄**。
4. 判定（沿用規則，淘汰：年化低於同窗含息 0050）：候選要在兩個池都贏 0050，才算通過；S2 原版是參照，不算新候選。
5. 這個窗口對 S2 與延伸變體都是乾淨的（凍結候選全部只用 2016-12～2018 決定）。

## 六、限制

- 訓練窗只有 2.05 年；2013–2016 資料補齊前，沒有任何乾淨驗證。
- 存活者偏誤（資料裡沒有下市股）會高估中小型營收動能；幅度無法量化。
- 營收公布日用法定日（次月 10 日），不是實際公告日；許多公司更早公告，換股時點可能偏晚（保守）。
- 候選名單門檻（鄰域 40%）是看過第一次結果後放寬的，已揭露；之後不得再調。
- 單軸變體 24 組＋疊加 5 組只是一小部分組合空間，疊加沒有網格搜尋。
