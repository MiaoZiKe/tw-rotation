# AI Office System 規劃書（第一版，2026-11-12）

狀態：**規劃完成、尚未開工**。等 Andy 回覆第七節的問題後從階段 0 開始。

## 一、要做的是什麼

一套線上的 3D 辦公室。CEO（主 Claude）與每一個子 Agent 都是一個角色，
Andy 用任何裝置打開網頁，就能看到誰在做什麼、做到哪、花多少 Token、績效如何，
也能在網頁上對 CEO 下指令。別人的 Claude 也能用簡單步驟接進來。

## 二、四組研究結論（2026-11-12）

| 組別 | 結論 |
|---|---|
| 3D 美術 | 用有骨架的現成角色（KayKit，CC0 可商用）當身體與動作來源，換頭、換裝、換色做出多種族；寵物用程式生成。已實測可下載、可播走／跑／坐／被打／慶祝／互動。缺「打字、講話」動作，要自己補。截圖：`research_kaykit.png`（現成骨架）、`research_procedural.png`（純程式生成，像積木玩偶，不採用為主方案） |
| Claude 串接 | 事件掛鉤（hooks）可自動送出「派了誰、開始、結束、回報摘要、Token 用量」；本機可包成外掛兩行安裝，雲端靠專案內設定檔 |
| 系統架構 | 獨立專案＋獨立子網域；後端用 Cloudflare Worker＋Durable Object（即時推送）；登入沿用現有會員系統；資料不走公開靜態檔 |
| 組織制度 | 45 個 Agent 分 12 個部門，各配種族與暱稱；S～F 績效用絕對門檻；三方稽核互相迴避 |

已知限制（如實寫）：
1. 子 Agent 之間不會真的互相對話，「會議內容」是用派工內容與回報摘要演出來的。
2. 現成角色是冒險者造型（頭盔、巫師帽有稜角），要換成辦公室服裝與圓潤的頭才合格。
3. 手機實際流暢度還沒實機量過。
4. 雲端對話送資料到新網址，可能要先放行網路白名單，開工第一天先測。
5. 目前沒有任何逐件派工的起訖時間與 Token 紀錄，績效要等紀錄機制上線後才有數字。

## 五、技術方案摘要

- 前端：three.js，角色用 glTF 骨架動畫，卡通漸層材質、柔和光、圓角家具；不使用 SVG 畫角色。
- 後端：Cloudflare Worker＋每個組織一個 Durable Object（SQLite＋WebSocket）。
- 資料進來：hooks 自動上報，逾時 2 秒就放棄、失敗先存本機稍後補送，不影響工作。
- 權限：寫入端每專案一把金鑰；觀看端 Google 登入，預設只有擁有者。
- 資料表：組織、專案、部門、角色、任務、事件、會議與發言、佈告、績效、Token 用量、佈局、寵物。

## 六、組織與績效（摘要，細節待 Andy 確認後另存 `org.md`）

- 12 部門：資料、量化研究、產業研究、前端工程、設計與繪圖、社群媒體、影音製作、比比動畫、商務與上架、法遵與資安、營運與部署、監察與稽核室（直屬 Andy）。

## 九、Andy 的追加方向（2026-11-12 晚）

### 1. 這是要對外開放、可販售的產品
Andy 原話：「之後會想要開放給大家免費使用，但是他們免費使用最多只能使用到兩到三個 agent，後面如果需要加的話就要付費。這功能是可以販售我的價值的。」

對設計的影響（從階段 2 起就照這個做，不事後重構）：
- **多租戶**：每個使用者一間自己的公司，資料互相隔離；Andy 的公司只是第一間。
- **方案額度由伺服器把關**：免費方案最多 3 個 Agent 角色（CEO 另計與否待定），超過的 Agent 事件照收但角色顯示為「待開通」，不在瀏覽器端判斷。
- **素材必須可商用**：角色全部自製原創；借用的骨架動作為 CC0；不得複製任何既有遊戲的角色與造型。
- **新增階段 6「開放與收費」**（階段 5 之後，約 5～7 天）：註冊流程、方案與額度、付款、使用條款與隱私權政策（別人的 Agent 對話內容會存在我們伺服器）、一行安裝的接入包、說明頁。
- 需要 Andy 本人處理（到階段 6 才需要，附逐格步驟）：金流商帳號、Cloudflare 付費方案（對外開放後免費額度不夠，約每月 5 美元起）、方案價格拍板。
- 定價與方案內容到階段 6 前由 `marketing-strategist`、`payments-billing`、`legal-compliance` 提案，Andy 點頭才定。

### 2. 會議要有「討論的感覺」
Andy 原話：「代理之間如果不會有這個討論的話，在開會上面就盡量把這種討論的感覺做出來，實際底下怎麼做是你這邊安排，我只是要一個效果。」

做法：
- 會議分幕演出：CEO 開場說明議題 → 逐一點名交代 → 被點名的人回應（確認、提問、說自己打算怎麼做）→ 有人做完回來報告 → 其他人接話（追問、補充、提醒風險）→ CEO 總結並貼上佈告欄。
- 台詞來源：CEO 的派工內容、各 Agent 回報裡的結論、疑慮、彼此矛盾或互相依賴的地方，改寫成口語對白；不同角色有各自的說話個性。
- 演出細節：轉頭看發言者、點頭、舉手、白板逐條出現重點、有分歧時出現爭論表情、達成結論時鼓掌。
- 底線：對白是改寫的，但**結論、數字、誰負責什麼一律照實**；每場會議旁邊可點開看原始派工與回報全文。
- 對白改寫由 CEO 在回報時順手產生（不另外花 API 費）；沒有產生時用規則自動排一版基本對白，確保每場會議都有畫面。

## 十、Andy 的追加要求（2026-11-12 深夜）

### 1. 角色要非常像人：表情、情緒、工作細節都要畫出來
Andy 原話大意：Agent 之間必須非常像人類，要有表情動作——生氣、討論、爭執，可以稍微浮誇一點；開會與執行任務的過程中，有人用電腦、有人查資料、有人做筆記，這些細節都要做進去。

列為驗收項目：
- **表情**：開心、生氣（皺眉、冒煙）、驚訝、難過、思考、尷尬、得意；浮誇卡通式（頭上符號：怒氣、汗滴、問號、燈泡、星星）。
- **討論與爭執**：比手畫腳、拍桌、站起來、搖頭、雙手抱胸、指白板、點頭附和、鼓掌。
- **工作狀態對應真實動作**（依 Agent 實際在用的工具決定）：
  | 實際在做什麼 | 畫面 |
  |---|---|
  | 寫程式、改檔案 | 坐著打電腦，螢幕有畫面在動 |
  | 上網搜尋、查資料 | 翻書、去資料櫃、用平板或放大鏡 |
  | 讀文件 | 拿著文件看、推眼鏡 |
  | 開會聽講 | 做筆記（拿筆寫本子） |
  | 等待、卡住 | 抓頭、看時鐘、去茶水間 |
  | 交件 | 拿文件走去主管或 CEO 桌前 |
- 階段 0 的樣張就要先示範：生氣、爭執、查資料、做筆記這四項。
