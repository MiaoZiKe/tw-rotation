# AI Office System 規劃書（第一版，2026-11-12）

狀態：**規劃完成、尚未開工**。等 Andy 回覆第七節的問題後從階段 0 開始。

## 一、要做的是什麼

一套線上的 3D 辦公室。CEO（主 Claude）與每一個子 Agent 都是一個角色，
Andy 用任何裝置打開網頁，就能看到誰在做什麼、做到哪、花多少 Token、績效如何，
也能在網頁上對 CEO 下指令。別人的 Claude 也能用簡單步驟接進來。

## 二、四組研究結論（2026-11-12）

| 組別 | 結論 |
|---|---|
| 3D 美術 | 用有骨架的現成角色（KayKit，CC0 可商用）當身體與動作來源，換頭、換裝、換色做出多種族；寵物用程式生成。已實測可下載、可播走／跑／坐／被打／慶祝／互動。缺「打字、講話」動作，要自己補。截圖：`research_kaykit.png`（現成骨架）、`research_procedural.png`（純程式生成，像積木玩偶，不採用為主方案） |
| Claude 串接 | 事件掛鉤（hooks）可自動送出「派了誰、開始、結束、回報摘要、Token 用量」；本機可包成外掛兩行安裝，雲端靠專案內設定檔 |
| 系統架構 | 獨立專案＋獨立子網域；後端用 Cloudflare Worker＋Durable Object（即時推送）；登入沿用現有會員系統；資料不走公開靜態檔 |
| 組織制度 | 45 個 Agent 分 12 個部門，各配種族與暱稱；S～F 績效用絕對門檻；三方稽核互相迴避 |

已知限制（如實寫）：
1. 子 Agent 之間不會真的互相對話，「會議內容」是用派工內容與回報摘要演出來的。
2. 現成角色是冒險者造型（頭盔、巫師帽有稜角），要換成辦公室服裝與圓潤的頭才合格。
3. 手機實際流暢度還沒實機量過。
4. 雲端對話送資料到新網址，可能要先放行網路白名單，開工第一天先測。
5. 目前沒有任何逐件派工的起訖時間與 Token 紀錄，績效要等紀錄機制上線後才有數字。

## 五、技術方案摘要

- 前端：three.js，角色用 glTF 骨架動畫，卡通漸層材質、柔和光、圓角家具；不使用 SVG 畫角色。
- 後端：Cloudflare Worker＋每個組織一個 Durable Object（SQLite＋WebSocket）。
- 資料進來：hooks 自動上報，逾時 2 秒就放棄、失敗先存本機稍後補送，不影響工作。
- 權限：寫入端每專案一把金鑰；觀看端 Google 登入，預設只有擁有者。
- 資料表：組織、專案、部門、角色、任務、事件、會議與發言、佈告、績效、Token 用量、佈局、寵物。

## 六、組織與績效（摘要，細節待 Andy 確認後另存 `org.md`）

- 12 部門：資料、量化研究、產業研究、前端工程、設計與繪圖、社群媒體、影音製作、比比動畫、商務與上架、法遵與資安、營運與部署、監察與稽核室（直屬 Andy）。
- 評分：品質 30%、完成率 25%、速度 15%、Token 效率 15%、可靠度 10%、協作主動 5%。
- 等第：S ≥95、A 85–94、B 75–84、C 65–74、D 50–64、E 35–49、F <35 或回報不實兩次。當週少於 3 件標「樣本不足」不給等第。
- 處置：D 重點栽培（改提示詞、補規則）、E 降載／拆職責／補人、F 汰換（需 Andy 點頭）。
- 「人太少還是能力問題」：同時在手超過 3 件或等待佔 40% 以上→補人；錯誤集中同一類→補規則；補過兩週仍差→換模型或汰換。
