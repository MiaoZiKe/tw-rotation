## 一、績效怎麼算成等第

### 1.1 等第與指標（沿用 `org.md`，只補算法）

等第〔既有〕：S ≥95｜A 85–94｜B 75–84｜C 65–74｜D 50–64｜E 35–49｜F <35 或回報不實兩次。用絕對門檻，不做強制比例。

| 面向 | 權重〔既有〕 | 對應擁有者列的指標 | 0–100 換算〔提議〕 | 誰提供資料 |
|---|---|---|---|---|
| 品質 | 30% | 品質退件率（顯示用 = 1 − 首次通過率） | 首次通過率×100，擁有者每退件一次再扣 10，下限 0 | `reviewer` |
| 完成率 | 25% | 完成率 | 有完成證據件數 ÷ 已到期派工件數 ×100（還沒到期的進行中件不算分母） | `inspector` |
| 速度 | 15% | 準時率＋時間效率 | 準時率×100 佔 8/15；工時比（實際÷預估的中位數，≤1 得 100、>2 得 0、中間線性）佔 7/15 | `resource-auditor` |
| Token 效率 | 15% | Token 效率 | 實際÷預算：≤1 得 100、≥2 得 0、中間線性（1.5 倍是 `token_policy` 的「先停」線，得 50） | `resource-auditor` |
| 可靠度 | 10% | 回報不實扣分、卡住 | 100 − 25×卡住逾 60 分鐘次數 − 50×回報不實次數，下限 0；另外「不實一次當週最高 C、兩次 F」照舊封頂〔既有〕 | `inspector` |
| 協作與主動 | 5% | — | 交接齊全率與主動抓到別人問題的件數（每件 +20，上限 100） | `reviewer`（`org.md` 沒指定，這項是提議） |

說明：「準時率」是這次新增的指標，我把原本「速度」拆成兩半（8＋7），總權重不變。

### 1.2 週期、樣本、資料不足

| 項目 | 規則 |
|---|---|
| 計算週期〔既有〕 | 每週一評上一個完整週（週一～週日，台北時間）；擁有者說「審查」即時評近 7 天 |
| 樣本不足〔既有〕 | 當週派工件 <3 → 標「樣本不足」，不給等第 |
| 四週滾動〔提議〕 | 單週 <3 件但近 4 週合計 ≥3 件 → 用 4 週滾動算，等第旁標「4 週」。避免像法遵這種本來就低頻的角色永遠沒有等第 |
| 未量測〔既有〕 | 某面向沒資料 → 標「未量測」，權重按比例分給其他面向，不准補猜 |
| 資料太缺〔提議〕 | 「未量測」的權重合計 ≥40% → 整體不給等第，標「資料不足」 |
| 難度加權〔提議〕 | 件數按 `token_policy` 的任務分級加權：查檔／普查／格式轉換 ×0.5、撰寫／一般前端／測試修正 ×1、審稿／跨檔架構／法遵資安 ×1.5。完成率與品質都用加權件數 |

### 1.3 部門等第〔提議〕

部門分數 = **70% 成員分數加權平均 ＋ 30% 部門指標**。

| 部分 | 算法 |
|---|---|
| 成員加權平均（70%） | 只計有等第的成員；權重 = min(該成員當週件數, 10)，避免一個人包辦整個部門的分數；主管也計入（主管的個人等第由別人評，部門等第由 hr-officer 算，符合「主管不評自己部門」） |
| 部門指標（30%） | 逾期未結件比例 40%｜排隊等待佔工時 30%（這項偏「人力」訊號）｜跨人交接齊全率 30%。資料由 `inspector`（逾期、交接）與 `resource-auditor`（排隊）提供 |
| 部門樣本不足 | 有等第的成員 <2 位，或有等第的成員 <半數 → 部門標「樣本不足」，設備維持上週等級，不升不降 |
| CEO | 不屬於任何部門，不進部門平均，另列一列（見第八節） |
| 稽核室 | 四人互評後照同一公式算部門分數 |

補強建議沿用 `org.md` 的判斷流程：排隊佔工時 ≥40% 或同時在手 >3 件＝**人力問題（補人、拆職責）**；退件集中同一類＝**規則問題（補提示詞）**；補過兩週仍 D 以下＝**能力問題**。部門招牌小旗與總表上的「原因」就是這個判斷的結果，所以「人力吃緊」不會被寫成「表現差」。

## 二、個人獎勵＝配件

### 2.1 現況（讀過程式碼）

- 角色配件機制在 `site/office/play/species.js` 的 `addAccessories`，現有 `glasses hat crown bow tie scarf badge`，每個物種用 `anc` 欄位宣告掛點（`hat / bow / chest / neck / glasses`），沒有掛點的配件 `canWear` 會直接略過。
- 全員 `roster.json` 已有的配件：badge 39、glasses 18、tie 11、bow 11、hat 9、scarf 2。這些是**部門識別**（同部門同色），所以本設計**不動它們**，等第配件另外疊加。
- 物種移動方式（`move`）有 `walk`、`hop`、`slide`、`float` 四類；掛點齊全程度因物種不同。具體哪些物種屬於下面的哪一種體型，要等角色負責人確認〔待確認〕。

### 2.2 不准擋的規則〔提議〕

| 禁區 | 規則 |
|---|---|
| 臉（正面 ±40° 錐形區） | 任何配件不得進入。眼鏡只換**鏡框顏色**（`face.st.glasses`），不加模型 |

| 座位與尋路 | 配件不增加碰撞體；桌上物件放在桌面後側 40% 區，不擋螢幕與鍵盤 |
| 遠景 | 小於 0.1 m 的配件（星章、字章）在遠景距離分級時隱藏，只留大形狀與腳下光圈，大形狀由現有距離分級（LOD）負責 |

### 3.3 效能預算與「只換材質」清單〔提議〕

事實：`scripts/uitest_sections/20261113_office_char.py` 有斷言「47 隻同場：繪製呼叫 ≤330、三角面 ≤400k、JS 更新 ≤6 ms/幀」，場景已貼近上限。我沒有量過現在實際用了多少，所以預算先抓「獎勵系統合計新增」的上限，**實作時要用這個斷言驗**：

| 項目 | 預算 |
|---|---|
| 新增繪製呼叫 | 合計 ≤ +20（腳下光圈 1、字章圖集 1、光暈 1、地面獎盃/彩帶/寵物個位數、披風與光環依角色距離分級，遠景不畫） |
| 新增三角面 | ≤ +20k |
| 新增真實光源 | 0 |
| 新增貼圖 | 字章與招牌小旗各用**一張共用圖集**，不做每人一張 |

只換材質顏色、不加模型的升級：桌牌（銅銀金）、眼鏡框、緞面領巾、桌面木色與側條顏色、地毯顏色與邊條、花盆顏色、招牌顏色與邊框顏色、螢幕發光條顏色。這些全部用既有 Part 的顏色參數就能做，建議**優先做**。

| 問題 | 做法〔提議〕 |

### 7.2 CEO 也要被評〔提議〕

CEO 的工作不是「交件」而是「接住擁有者交辦、派人做完、如實回報」，所以指標與一般 Agent 不同：

|---|---|---|---|
| 交辦完成率與證據 | 30% | 擁有者交辦事項中，有完成證據（網址／commit／截圖／posted 紀錄）並已結案的比例；沒證據的不算完成。依據 `CLAUDE.md` 2026-10-29「交辦的事一律做完、要有完成證據」 | `inspector`，讀 `docs/confirm_ledger.md` 與回報 |
| 被退件與重複提醒 | 20% | 100 − 10×擁有者退件次數 − 5×同一件事被提醒第 2 次起的次數，下限 0 | `inspector`（對照擁有者原話與帳本） |
| 回報如實 | 20% | 回報與實際狀態逐條比對；不實一次當週最高 C、兩次 F〔既有規則〕。包含「還沒部署就說好了」「沒親眼看卻說看過」這類 | `inspector` |
| 派工效率與 Token | 15% | 派工單填齊模型與預算欄位的比例；子任務超過 1.5 倍預算未停的次數；CEO 自身 Token 對預算 | `resource-auditor` |

| 主動與維修閉環 | 5% | 壞掉／資料缺漏自己發現並修好、不等擁有者的件數；排程監工有沒有按時叫醒並處理 | `inspector` |

| 等第與門檻 | 同一套 S～F，不另訂 |
| 顯示 | 總表置頂一列，不進部門平均；點開看六個面向的小分數與扣分原因 |
| 3D 呈現 | CEO 保留固定識別（皇冠、領帶、識別證、放大體型），等第配件**疊加**：A 起有銀環、銀披風、銀框眼鏡；S 起金環、光環、金披風（皇冠不換，光環在皇冠上方 0.12 m，名牌再上移）。CEO 辦公室（`ceo_desk`、`rug_1`、立燈、植栽、門牌）依 CEO 等第照 L1～L5 同一套規則升降（CEO 桌尺寸與 L4／L5 的雙屏、獎盃櫃也照部門規則，上限放寬為 1.9 m），降級緩衝同部門（連續 2 週）。D 以下：桌上待辦堆疊＋琥珀桌燈，同第四節，**不羞辱** |

## 八、資料格式
