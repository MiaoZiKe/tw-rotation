# AI Office 工作流程（擁有者 2026-11-15 指示）

擁有者原話：「先規劃，規劃過程中分細項，針對細項找專業人員進行處理，最後討論、驗證，找使用者情境使用。」

起因：11-14～15 連續發生「做好了卻看不到」「真人操作沒燒起來」「改完點不了員工」——每一件都是各組只驗自己的、用程式內部函式驗，沒有人用擁有者的方式從頭操作一次。

## 五個步驟（每一批都照做）

| 步驟 | 做什麼 | 誰 | 產出 |
|---|---|---|---|
| 1 規劃 | 把擁有者這一批的話逐句列出，寫成「要達成的使用者體驗」，不是寫技術做法 | CEO | 本文件下方的批次表 |
| 2 分細項 | 每一項拆成可以單獨交件、單獨驗收的細項；標出彼此會不會改到同一個檔案 | CEO | 細項表（含負責人、檔案範圍、驗收方式） |
| 3 專業人員處理 | 每個細項派給對應專長的人（建模→character-modeler、物理動效→canvas-motion-engineer、介面互動→frontend-ui、情緒演出→animation-director、手機→mobile-ui、細節貼心→delight-designer）；同一檔案同時只給一人 | 各專業 | 程式＋自己的驗收段落 |
| 4 討論 | 各細項交件後，CEO 召集相關的人看整合後的版本：有沒有互相打架（例如 A 加的提示擋住 B 的點擊）、哪裡體驗不一致，決定修什麼 | CEO＋相關專業 | 整合問題清單與修正 |
| 5 驗證＋使用者情境 | ① 用「線上同樣的打包流程」（壓縮版、不含 data）重建整頁；② 由**沒參與實作的人**（reviewer／inspector）照「使用者情境劇本」用真滑鼠、真鍵盤、真手機尺寸從頭操作；③ 全部驗收段落一次一段跑完；④ 全過才推預覽，並更新左下角版本標記 | reviewer（情境測試）＋CEO | 情境測試報告（截圖逐步）、驗收條數 |

## 使用者情境劇本（每批至少跑這幾條；新功能要加進來）

1. **第一次進來**：打開預覽網址 → 重新整理兩次 → 看左下角版本號 → 看得懂畫面在做什麼。
2. **點員工**：滑鼠停在任一位員工上 → 點一下 → 出現資訊卡 → 點狀態格、看任務 → Esc 回俯視。
3. **移動視角**：快速拖曳移動、長按後拖曳轉角度、滾輪縮放、雙擊地面前往。
4. **操控**：選一位 → 方向鍵走、連按兩次跑、空白鍵跳、走到同事旁按 E、F 揮手、V 角色視角、Esc。
5. **多選**：Ctrl＋點三位 → 群組面板 → 一起回座位 → Esc。
6. **物理**：拎起一位丟向椅子 → 椅子翻倒 → 等同事扶起；拎起丟進營火 → 燒焦 → 等恢復；用方向鍵走進營火。
7. **情緒**：對剛被丟過的人點選與摸頭 → 有戒心；看資訊卡心情列。
8. **夜晚**：時間切到夜晚 → 室內開燈、屋外窗光路燈營火。
9. **績效與開除**：開績效總表 → 排序、展開部門 → 開除一位 → 遊民區看得到 → 重新聘用。
10. **接入**：連接我的 Claude → 一個畫面兩個複製鈕 → 換一組。
11. **手機（390×844）**：上述 1、2、3、5、9 用觸控做一次。

## 推上線的關卡（缺一不可）
- 情境劇本全部跑過，有逐步截圖；任何一條失敗就不推。
- 用壓縮後的打包版驗，不是只驗原始碼。
- 版本標記更新；推完 deploy_wait 兩個站都 ✅；告訴擁有者要看的版本號。

## 2026-11-15 晚補：完成一項就推預覽（擁有者：「我看連結你有更新嗎，我沒看到變化」「避免下次發生」）
事故：11:50 之後做完、驗完的東西（互動小房間修好、入口頁建立新辦公室、使用次數上限）一直留在開發分支，跟其他人的半成品混在一起，等「整批整合」才推，擁有者七個小時看不到任何變化。
規矩：
1. **一項做完、自己的驗收過、CEO 看過截圖 → 一小時內推上預覽**，不等其他項目。
2. 開發分支常混著別人的半成品，所以推預覽一律「從目前預覽版疊上這一項的檔案」：`git worktree add <暫存> <預覽版 commit>` → `git checkout <完成那筆 commit> -- <這一項的檔案>` → 打包版跑這一項的段落 → 更新 build.js 版本號 → 推 preview/office → deploy_wait 兩行 ✅ → 告訴擁有者版本號與要看哪裡。
3. 每次回報進度時，第一行寫「預覽網址目前是哪一版、幾點推的」；超過 2 小時沒推新版，要寫明原因。
4. 「整合＋獨立驗收員情境測試」照做，但它是在預覽版上再驗一次，不是推預覽的前提；情境測試發現的問題用下一版修。
