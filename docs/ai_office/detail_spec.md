> 撰寫：產品設計總監｜性質：只定體驗，不改任何產品程式碼、不 commit、不 push。
> 依據：擁有者 11-13 四段原話（額度與睡覺、接入教學要有圖與紅框、辦公室內對話窗、不標價錢）；`plan.md`、`org.md`、`account_model_eval.md`、`rewards_design.md`、`pets_zodiac_design.md`、`andy_ui_rules.md`；讀過 `site/office/world.html`、`world/js/ui.js`、`world/js/pilot.js`（只讀）。
> 標示規則：**【我方】**＝我們自己的伺服器或前端就能決定，不依賴 Claude 端；**【待實測】**＝要靠 Claude 端的事件或欄位，我沒有實證它拿得到；**【可得】**＝依 `account_model_eval.md` 1.2 的掛鉤事件摘要，推測可得，但**仍屬摘要轉述，也要實測**。凡是標【待實測】的，演出照寫（資料到了才亮），但**資料沒到時畫面不得假裝有**。
> 全文遵守三條底線：①畫面上**不出現任何價格、付費、升級、方案名稱字樣**，只顯示可用上限；②**不亂猜數字**，拿不到就顯示「未提供」；③結論、數字、誰負責什麼一律照實，演出只是包裝（沿用 `plan.md` 第九節）。

## A. 狀態對應演出總表（核心）

### A.0 共用約定

**狀態層（供前後端對齊，不是程式碼）**：每個辦公室同一時間只有一份狀態——
`quota`（剩餘比例、重置時間、資料時間、來源是否可信）、`link`（接入連線：正常／安靜／訊號不明／中斷）、`sessions[]`（每個工作階段的狀態）、`agents[]`（每位同事的狀態＋帽子）、`flags`（等核准、等回答）、`clock`（日夜、週末、節日）。3D 與介面只讀這份狀態，不直接讀事件。

**門檻（全部可調，預設值如下）**

| 名稱 | 預設 | 用在哪 |
|---|---|---|
| 安靜 | 該工作階段 5 分鐘無事件 | CEO 改為「待命」姿態 |
| 離座 | 10 分鐘無事件 | CEO 起身去茶水間（仍標「待命中」，不寫「已離開」） |
| 發呆 | 子 Agent 進行中且 3 分鐘無工具事件 | 抓頭 |
| 卡住 | 同上 10 分鐘 | 看時鐘＋汗滴；60 分鐘沿用 `org.md` 的績效「卡住」計次 |
| 訊號不明 | 整個接入 30 分鐘完全無事件，且當天曾有事件 | 見 A.5 |
| 斷線 | 有心跳機制才成立：3 分鐘無心跳【待實測】 | 見 A.5 |
| 額度預警 | 剩 20%、10% | 見 A.1 |
| 資料過舊 | 額度資料超過 15 分鐘未更新 | 電力表指針半透明 |

**同時演出預算**：同畫面「大動作演出」（走動、舉手、道具動畫）最多 6 件同時進行，其餘改為頭上小圖示＋名牌狀態字，事件照記不丟。避免 10 位子 Agent 同時被派時整間亂成一團，也保護手機效能。

**介面文字原則**：一句話、口語、繁體中文；不出現英文事件名、不出現「hook」「session」；時間一律台北時間或使用者所在時區並標明；不放價格、付費、升級、方案、Plus、Pro、免費等字。

**聲音原則**：預設靜音（F 節可開）。下表「聲音」欄只是「開了之後才播」；任何聲音都要有對應視覺，不能只靠聲音傳達狀態。

**優先級**：必做＝第 1、2 批要有；加分＝第 3 批以後。

### A.1 使用者的 Claude 用量額度（電力）

資料來源總註：Claude 端是否提供「剩餘比例」與「重置時間」給我們，**我沒有實證**。可能路徑有：狀態列（statusline）資料、工作階段的限額錯誤訊息、掛鉤的通知事件。三條都【待實測】。實測前，A.1 的「常態顯示」可能整段拿不到，所以**把「拿不到」當成一種正式狀態來設計（Q7）**，而不是例外。

## B. 辦公室內對話窗

### B.1 定位

擁有者原意：在辦公室裡就能「像現在這樣」跟當前專案的 CEO 對話。體驗目標：**輸入框就在辦公室旁邊，送出後看得到 CEO 起身接話**。技術通道【待實測】，這裡只定體驗與最低要求。

### B.2 版面

**桌機（≥ 1100）**：右側欄是**單一容器**，頂端用分段鈕（`.seg`）切換「對話｜資訊卡｜佈告欄」。點角色自動切到資訊卡；資訊卡內「對他說話」鈕切到對話並指名。預設**收起**成右緣 48px 窄條（G1），窄條顯示未讀點與目前狀態字；展開寬 360px，3D 畫面讓出寬度。這樣「資訊卡、佈告欄、對話」不會三個面板疊在一起，也不新增標題（B1：容器不另加標題，分段鈕就是標題）。

**平板（641–1099）**：同桌機，展開寬 320px，疊在 3D 畫面上（半透明底，不縮放畫面）。

**手機（≤ 640，390 為準）**：底部抽屜三段——
- 收合：高 48，只顯示最後一則訊息一行＋狀態點；
- 半開：高約 50vh，上半仍看得到 3D 角色；
- 全開：90vh。
抽屜把手 ≥ 44px 高；半開時隱藏操控搖桿（避免誤觸）；鍵盤升起時抽屜貼著鍵盤上緣，輸入框不被遮；用 `safe-area` 讓出底部橫條。客服鈕固定右下角的規則（F4）不變，抽屜收合時客服鈕在抽屜上方。

### B.3 對話對象

| 項目 | 做法 |
|---|---|
| 預設對象 | 當前專案的 CEO（頭像＋暱稱＋狀態字在輸入框上方一行） |
| 指名某位同事 | 兩種入口：①資訊卡「對他說話」；②操控模式靠近他按 E（沿用現有「溝通」鍵）。輸入框上方出現晶片「給 〈暱稱〉」，可按 × 取消 |
| 指名的真實意義（必須講實話） | 子 Agent 只在被派工的那段時間存在，**沒有可以直接對話的通道**。所以「指名」＝在訊息前附「請轉達給 〈暱稱〉」交給 CEO，CEO 決定如何派。「?」裡寫清楚這件事；3D 上演出 CEO 走到該同事旁邊轉達 |
| 其他人是否可見 | 對話只在該專案辦公室內，擁有者可見；邀請他人唯讀時，預設看不到對話窗內容（隱私，見 H） |

### B.4 訊息樣式與狀態

| 元素 | 樣式 |
|---|---|
| 使用者訊息 | 靠右氣泡，主色 |
| CEO 回覆 | 靠左氣泡，左側 CEO 小頭像（沿用 `ava` 縮圖），支援換行、項目符號、程式碼區塊（等寬、可複製） |
| 系統訊息 | 置中小字（「CEO 派給 阿版：…」「額度恢復」） |
| 狀態圖示（訊息右下） | 寄出中 → 已排隊 → CEO 已收到 → 處理中 → 已回覆；每個狀態同時有**圖形與文字**，不只靠顏色 |
| 時間 | 每則顯示 HH:MM；跨日加日期分隔線 |
| 長訊息 | 超過 8 行收合「展開」，不撐版 |

### B.5 送出後的演出

| 步驟 | 3D 演出 | 前提 |
|---|---|---|
| 送出 | 輸入框氣泡飛向 CEO；CEO 抬頭 | 立即（前端） |
| 已排隊（CEO 還沒收到） | CEO 桌上多一張便條紙 | 立即 |
| CEO 收到 | CEO 看向鏡頭、點頭；便條紙被拿起 | 需要「已送達」回報【待實測】 |
| 處理中 | CEO 打字、必要時派工（走 A 節的演出） | 沿用事件 |
| 回覆 | CEO 對鏡頭說話，頭上冒對話泡泡 | 需要回覆內容【待實測】 |

沒有「已送達」回報時，狀態停在「已排隊」，**不得自己改成「已收到」**。

### B.6 回覆顯示

- 有逐段文字事件：逐段長出（上限每秒刷新 4 次，避免閃爍）。
- 只有最終訊息：先顯示「CEO 正在整理…」三點動畫，完成後整則出現。
- 工具細節（讀檔、跑測試）不放進對話，放在辦公室演出與日誌，對話窗只留人話。
- 動作減量時三點動畫改為靜態「整理中」。

### B.7 附件與圖片

| 項目 | 規格 |
|---|---|
| 入口 | 輸入框左側迴紋針；手機可拍照或選相簿；桌機可貼上、拖放 |
| 限制 | 圖片 PNG／JPG／WebP，單張 ≤ 5MB，一則最多 4 張；其他檔案類型第一版不收 |
| 預覽 | 縮圖列在輸入框上方，可移除；送出後在氣泡內顯示縮圖，點開放大 |
| 能不能真的送進 Claude 工作階段 | 【待實測】；實測前**不顯示迴紋針** |
| 隱私 | 圖片存在我方伺服器的保存期與同意文字，列入 H |

### B.8 歷史紀錄

- 每個專案各一份，預設保留近 30 天，可由擁有者清除。
- 往上捲載入更早；捲動位置在新訊息進來時不被拉走（若使用者已經往上看，新訊息只在底部出現「N 則新訊息」鈕）。
- 標示「這裡是辦公室對話窗的紀錄，不是 Claude 本身的完整對話」，放在「?」。

### B.9 多專案切換

- 頂列專案切換：≤ 5 個用分段鈕，超過用共用下拉（C2、C3 規則）；每項右側有狀態點（工作中／等你核准／休息中／訊號不明）。
- 每個專案的對話、草稿、未讀獨立保存；切換時草稿不丟（存在本機）。
- 未讀以**琥珀小點**表示（不用紅色，紅留給緊急）。

### B.10 離線、不在線、排隊

| 情境 | 畫面 | 行為 |
|---|---|---|
| CEO 工作階段在線 | 狀態字「在線」 | 正常 |
| 工作階段安靜（S2 以上） | 「待命中」 | 照常送，狀態「已排隊」 |
| 工作階段不在線／已結束 | 輸入框上方灰橫幅「CEO 目前不在線（最後上線 HH:MM）。訊息會先排隊」 | 可寫可送；上限 20 則；超過 24 小時未被領取則標「已過期」，使用者可重送 |
| 睡覺中（額度用完） | Q9 橫幅 | 同上 |
| 接入中斷 | E3 橫幅 | 輸入框停用並說明原因（不是讓人白寫） |
| 送出失敗（我方伺服器） | 氣泡尾端「沒送出・重試」 | 保留文字 |
| 首次送出提醒 | 「CEO 處理這則訊息會用到你的 Claude 額度」一次性、可勾選不再提示 | 不出現價格字樣 |

**排隊如何被領取屬技術問題【待實測】**：體驗上的承諾只有一句——訊息排隊保存，CEO 下次醒來第一個處理；不承諾即時。

### B.11 與鍵盤操控模式的按鍵衝突

現有操控鍵（`pilot.js`）：W／A／S／D 與方向鍵移動、Space 跳、E 溝通、F 揮手、Esc 放開；輸入框聚焦時已自動停用（`typing()` 判斷）。

| 規則 | 說明 |
|---|---|
| 輸入框聚焦時 | 所有遊戲鍵失效（沿用 `typing()`），Space、WASD 都是打字 |
| 聚焦輸入框的全域鍵 | 沒有操控角色時：`Enter` 或 `/` 聚焦輸入框；**操控中**：`Enter` 不攔截（避免和遊戲互動衝突），改用 `E` 靠近同事開啟對話並指名 |
| Esc | 輸入框內第一次：失焦；第二次（已失焦）：放開操控（沿用） |
| 送出鍵 | 桌機 `Enter` 送出、`Shift+Enter` 換行；**中文輸入法組字中（`isComposing`）按 Enter 是選字，不送出** |
| 手機 | 送出用右側按鈕；`Enter` 為換行 |
| Space 在按鈕上 | 沿用現有規則（按鈕被焦點時 Space 是點擊，不是跳躍） |

### B.12 對話窗對技術的最低要求

| 項目 | 最低要求 | 說明 |
|---|---|---|
| 送出到 CEO 收到 | 理想 ≤ 10 秒；可接受 ≤ 30 秒（以「已排隊」呈現）；超過 30 秒仍排隊就顯示排隊 | 不承諾即時；使用者要知道這不是聊天軟體 |
| 回覆顯示 | 最終訊息必須拿得到；逐段串流是加分 | 沒有最終訊息，就整個對話窗不放輸入框 |
| 必要事件 | 使用者送出提示（UserPromptSubmit）、回合完成並帶最後訊息（Stop）、通知（權限／提問／閒置）、工具前後（PreToolUse／PostToolUse）、工作階段起訖 | 【可得，待實測】 |
| 入站通道 | 一條能把文字（與圖片）交給「已在執行的工作階段」的辦法 | 【待實測】；若只能在 CEO 下次主動輪詢時領取，B.10 的排隊文案就是正式體驗 |
| 在線判斷 | 要能判斷「工作階段是否還活著」 | 無心跳則只能推算，文案保持「待命中」，不寫「在線／離線」兩個絕對字眼 |
| 資料量 | 事件不含提示詞全文與程式碼 | 對話窗訊息是**使用者主動送出**的內容，與事件上報分開處理與同意 |

## C. 接入教學（流程圖＋真實截圖＋紅框）

### C.1 形式

- 一頁式教學，頁內分段鈕「電腦版｜雲端版」（`.seg`），預設電腦版。放在「接入」頁；頁標已有，卡內不再重複標題（B1）。
- 頂部一條**流程圖**：五個方塊橫排（手機改為縱排），每個方塊＝一步，點方塊捲到該步；目前所在步高亮，完成的步打勾（形狀＋顏色）。
  **登入 → 取得接入碼 → 安裝 → 驗證成功 → 建立辦公室**
- 每一步一張卡，卡內順序：①一句話說這步要幹嘛 ②**一張真實截圖（紅框標欄位）** ③欄位表 ④成功長相 ⑤失敗長相與排除。說明文字長的收進「?」。
- 每步右下一顆「完成這步」；整頁有一個進度條。沒做完離開，下次回來停在上次那步（本機記憶，讀不到就從頭）。

| 規則 | 內容 |
|---|---|
| 真實 | 只用實測時在真實畫面截的圖；**現在先定版位與檔名，不畫假的介面圖，不用 AI 生成或手繪仿圖冒充**。尚未實測的步驟，版位顯示灰底「待實測後補圖」，不放示意圖 |
| 標註 | 要填的欄位：**紅色實線框**（3px，圓角 4px，外擴 3px）＋左上角**編號圓章**（白字紅底）；要按的鈕：紅框＋右下角小手指箭頭；不要動的欄位：不標。圖旁欄位表用同編號對應 |

### C.3 各步骤（欄位值待實測後填）

| 步 | 做什麼 | 截圖 | 欄位表（填什麼；實測後補實值） | 成功長相 | 失敗長相與排除 |
|---|---|---|---|---|---|
| 1 登入 | 用 Google 登入辦公室網站 | g1-login：登入鈕紅框 | 無需填；要按「用 Google 登入」 | 右上顯示信箱縮寫；流程圖第 1 格打勾 | 彈窗被瀏覽器擋 → 允許彈出視窗；登入後回到空白 → 清除網站資料重來 |
| 2 取得接入碼 | 網站顯示專屬接入碼與指令 | g2-code：接入碼區紅框＋「複製」鈕紅框 | 〈接入碼〉：由系統產生，按複製；**不要貼到聊天或公開地方** | 顯示碼與「複製成功」；碼旁倒數有效時間【有效期待定】 | 重新產生會讓舊碼失效，畫面要明說；碼過期 → 重新取得 |

| 3B 安裝（雲端版） | 在網頁版 Claude Code 的環境設定填三處 | g3-install-cloud-net／-secret／-script：每個表單一張，欄位紅框 | 三個表單各列「欄位名｜要填的值｜不用動的欄位」。**表單名稱以實測當下的畫面為準**（依 `CLAUDE.md` 規則：給步驟前先對過畫面，畫面上沒有的按鈕不准寫） | 環境頁出現已存的項目 | 白名單沒加 → 事件送不出去；金鑰填錯格 → 重填；腳本貼不完整 → 重貼 |
| 4 驗證成功 | 開一個 Claude 工作階段，等網站收到第一筆消息 | g4-verify：網站「等待第一筆消息」區紅框；Claude 端要開的位置紅框 | 在 Claude 端隨便說一句話即可 | 網站出現綠勾形＋「收到第一筆消息」，並跳出「發現新專案：〈名稱〉」 | 等超過 2 分鐘仍無 → 自動出現「測試連線」與排除清單 |
| 5 建立辦公室 | 把發現的專案變成辦公室 | g5-create：「創立辦公室」鈕紅框＋「自動建立」開關紅框 | 專案名稱可改；是否自動建立 | 進入新辦公室，只有 CEO（見 E4 空狀態） | 座位或辦公室數已到上限 → 顯示 D 節的文案，不丟資料 |

### C.4 「測試連線」鈕

- 位置：接入頁每一步的右上角，以及 E2／E3 橫幅內。
- 行為：我方伺服器等待最多 30 秒，收這個接入碼的下一筆事件；同時請使用者在 Claude 端隨便說一句話。
- 結果三種：**收到**（顯示來源是電腦版還是雲端版、延遲幾秒、哪一個專案）；**沒收到**（逐項檢查清單：接入碼是否有效、是否曾經收到過、最後一次消息時間，並依電腦版／雲端版給不同的排除步驟）；**收到但欄位不全**（列出缺哪些資料，例如沒有專案名稱）。
- 不得顯示「連線成功」除非真的收到事件。

### C.5 常見錯誤排除（每條「現象｜原因｜怎麼辦」，做成「?」內的清單；原因欄**待實測**驗證後才寫死）

| 現象 | 可能原因 | 怎麼辦 |
|---|---|---|
| 網站一直沒收到消息 | 外掛沒啟用／雲端網路白名單沒加／接入碼貼錯 | 依「測試連線」的檢查清單逐項 |
| 收到消息但沒有子 Agent 動畫 | 外掛範圍的子 Agent 掛鉤在某些版本不觸發【待實測】 | 提示更新 Claude Code 版本；改用專案層級設定備案 |
| 公司網路連不出去 | 防火牆擋 | 請管理員放行我方網址（顯示網址） |
| 換了電腦／新增雲端環境 | 每個環境各裝一次 | 雲端版依環境數重複第 3B 步 |
| 辦公室出現多個重複專案 | 專案識別名稱不同 | 在專案頁「合併」 |

### C.6 完成後

流程圖五格全勾 → 顯示一句「接好了。在 Claude 隨便派一個工作，回來看看同事動起來」，並自動導向 E 節的空狀態。

## D. 額度與上限的呈現（不出現價格）

### D.1 鐵則

- 畫面上**不得出現**：價格、NT$、付費、升級、訂閱、方案、Plus、Pro、免費、試用到期、解鎖付費。
- 只呈現**「可用上限」與「目前使用量」**，例如「辦公室 1／1」「座位 3／3」。上限用盡時用「已滿」的中性語氣，不暗示可以買。

| 情境 | 畫面與文案 |

### D.4 辦公室數用完

| 情境 | 畫面與文案 |
|---|---|
| 發現新專案但辦公室已滿 | 專案列出現灰色專案項「〈專案名〉」，標「待安排」；點開文案：「辦公室已滿，這個專案的消息仍有保存，輪到時會補上」；可在已有的辦公室之間**輪流換上場**（規則由擁有者定，見 H） |

| 沒有任何金額、升級鈕 | 沒有 |

### D.5 擁有者本人不受限

- 擁有者帳號（站主）**不顯示上限計數**，頂列改為小章「站主」；座位、辦公室數都顯示實際用量，不出現「／上限」。

### 最容易被忽略、卻決定質感的十個細節

1. **資料新鮮度永遠看得到**：頂列連線燈滑過就顯示「最後一次收到消息 HH:MM」。使用者信不信這間辦公室，取決於他知不知道畫面有多新。
2. **睡覺必須附「何時醒」**：只演睡覺沒有恢復時間，使用者會以為壞掉。拿不到時間要明說「未提供」。
3. **不亂猜數字**：額度、進度、剩餘時間，沒有就顯示「未提供」，寧可空，不可假。
4. **補送回放要壓縮**：離線期間累積的事件若逐一演，使用者會看到十分鐘的亂跑；快轉 5 秒加一句「補上 N 件事」是專業感的分水嶺。
5. **演出預算**：同時大動作 ≤ 6 件，其餘改小圖示。沒有預算，十位同事同時動的辦公室就是一團亂，也撐不住手機。
6. **分頁標題與 favicon 就是第二個螢幕**：等核准時標題前綴「(1) 」、favicon 加琥珀點，使用者切到別的分頁才知道 CEO 在等他。
7. **離開分頁再回來的「補課」**：分頁在背景時暫停動畫，回來先顯示「你不在的時候發生了 N 件事」，而不是看一場追趕的狂奔。
8. **中文輸入法的 Enter**：組字中按 Enter 是選字，被誤送出一則半截訊息，是中文使用者最討厭的缺陷。
9. **錯誤文案要像人話**：「接入碼失效了」「圖片太大了」，不出現錯誤代碼、不出現英文字（I1）。
10. **第一個三秒就有動靜**：載入完成第一畫面，CEO 就在呼吸、翻文件、窗外有天色；空辦公室也有生命感，而不是一張靜止圖。
