# 比比單位：效率與資源規則

適用 `leaf_bite`、`bubble_react`、`plane_react`、`yarn_tumble` 與之後同類批次。CEO 派工與整合，專家分檔交付，QA 驗收；CEO 不重做已指派工作。

1. **最小上下文派工**：新專家用 `fork_turns="none"`，只傳角色、目標、負責檔案、已定規格、必要參考路徑與驗收條件。遵守入口規範，長文件先定位相關段落，不整批複製歷史對話。
2. **一檔一位寫入者**：角色不可同改一檔。跨角色改動由 CEO 指定接手順序；共用入口與整合檔由指定負責人統一更新。
3. **先鎖規格再生圖**：動畫師與工程師先統一總時長、接觸格／毫秒、角色比例、腳底線與道具錨點，企劃確認語意後交插圖師。沿用核准母版；不因重畫擅改檔名、待機、客服與網站行為。
4. **退件最多兩輪**：QA 每輪列明失敗幀、偏差與修正目標，退回原負責人局部修正。兩輪仍不過就記錄阻塞與替代方案，交 CEO 決定，其他獨立項目繼續；不默默重生整批。
5. **機械檢查交給腳本**：檔案數、尺寸、幀數、逐幀時長、透明度、檔案大小與雜湊由腳本輸出一次清單。LLM 讀差異與異常，人工逐格審角色一致性、接觸與動作；不反覆讀全部檔案盤點。
6. **獨立寫入最多 2–3 路**：以不共用輸出檔為前提；整合與驗收保留單一負責人。同批素材不因每張完成就重跑全站資料抓取或重部署。跑受影響檢查，正式交付仍完成既定必要關卡；資料管線真的有變才重建資料。
7. **資源數字如實報**：記錄生圖請求數、每次起訖、重試原因、驗收輪次與交付檔數。沒有實際計量就寫「Token／USD 未計量」，不可由回覆長度猜費用，不宣稱已節省百分比。不自動切換模型。

## 四張 4×4 圖的排程

「12–20 分鐘」先視為原排程估計，不能當作本輪實測。可安全縮短的是獨立請求的等待與錯誤擴散：

- 先完成四動作共用規格；第一張優先做接觸風險高的 `leaf_bite`，驗嘴部接觸、角色比例、腳底與回待機。合格就保留作正式素材，不額外做拋棄式試圖。
- 共用外觀與座標通過後，同一插圖負責人並行呼叫獨立內建生圖，先跑兩張，再依工具支援與資源狀況補第三張；不為並行額外開 Agent，不讓多路覆寫同一輸出。工具不支援時順序完成，不換未授權服務。
- 一張返回即可切圖與局部 QA，與其他生圖等待重疊。接觸失敗只退該動作；首張外觀不合格則先修共用提示與參考，再擴展其餘三張。
- 並行不保證縮短總時間，排隊或限流可能抵銷收益。用本輪記錄更新剩餘時間區間；未實測前不承諾新分鐘數，也不宣稱降低 Token 或費用。

交付回報固定三段：**改了哪些檔案／怎麼驗證／已知限制**。預計與完成分開寫。
