你現在遇到的問題，其實不是 Claude Code 不會製作 GIF，而是它把「繪製角色」當成程式幾何圖形問題，而不是角色動畫製作問題。

例如，它可能會使用 SVG 畫圓形身體、三角形耳朵、黑色圓點眼睛，再用 CSS `transform` 做上下移動。雖然程式能執行，但最終成品容易變成另一隻角色，失去你原始 LOGO 的毛茸茸輪廓、臉型、腮紅、手腳比例與呆萌感。

要改善品質，核心是讓 Claude Code 改採：

原始 LOGO 素材 → 角色拆件 → 骨架控制 → 表情替換 → 逐格動畫 → 情境道具 → 專屬科技圖卡 → Reels 影片合成。

有一點需要先區分：Claude Code 可以透過程式保留原始角色、組合精緻素材、製作高品質 2D 動畫及資訊圖表；但單靠繪圖程式，不能保證像圖片生成模型一樣，自動創作任何角度、任何新姿勢的精緻插畫。因此，這份提示詞會優先要求它重用你的原始素材，不得隨便重畫角色，只有確實需要新姿勢時，才進行局部補繪與向量化。

下面這份是專門寫給 Windows + Claude Code 的完整製作指令。你可以整包複製到 Claude Code，它會按照你現有的專案與題材執行。

# 第一部分：理解我的原始 LOGO

## 1.1 先辨識原始角色

請掃描目前專案中的 LOGO、PNG、GIF、分鏡與相關素材。

找到我提供的「8 格跳躍動作」原始 LOGO。

角色具有以下視覺特徵：

- 主體是奶油白色、圓滾滾、蓬鬆的毛球。
- 整體輪廓近似圓形，但不是完美的幾何圓。
- 頭部和身體是一體的，沒有明顯脖子。
- 外側毛髮具有不規則的小波浪與自然尖角。
- 左右各有一隻小巧、偏圓的耳朵。
- 耳朵內側帶有粉橘色。
- 眼睛是小巧、黑色、圓潤的點狀。
- 嘴巴小巧，帶微笑與伸出的粉色小舌頭。
- 臉頰左右有大面積蜜桃粉腮紅。
- 四肢短小且偏粉橘色。
- 身體沒有突出的四肢結構。
- 黑色輪廓略帶深咖啡色調。
- 呆萌、療癒、沒有攻擊性。
- 角色不能被畫成一般倉鼠、小狗、兔子或熊。

它不是一隻普通的白色卡通動物，而是我的固定品牌 IP。

## 1.2 建立角色標準模型

請從原始圖片建立 Character Model Sheet，內容包括：

- 正面自然站姿
- 正面蹲姿
- 壓縮姿勢
- 跳躍姿勢
- 微側身姿勢（有可信素材時才製作）
- 表情特徵
- 手腳位置
- 耳朵位置
- 身體輪廓曲線
- 毛髮細節
- 色彩規範

請先從原圖偵測實際比例，不要憑空估計。

設定相對座標系統：

- 原始角色可視範圍：0～1
- 身體中心為動畫控制基準
- 左耳、右耳、左右眼、嘴巴、腮紅、雙手、雙腳分別設置 Landmark
- 建立可重複使用的 Anchor Points

例如：

- `body_center`
- `left_eye`
- `right_eye`
- `mouth_center`
- `left_ear`
- `right_ear`
- `left_hand`
- `right_hand`
- `left_foot`
- `right_foot`
- `prop_anchor`
- `ground_anchor`

所有座標必須依照實際素材計算與校準。

## 1.3 嚴禁的角色錯誤

以下屬於嚴重設計失敗：

- 直接使用 ellipse 畫一個白色圓形取代身體。
- 用兩個圓或三角形隨便製作耳朵。
- 用簡單幾何圖形重建整隻角色，卻沒有保留原本毛髮輪廓。
- 每張 GIF 的臉型都不同。
- 跳躍時角色突然變瘦、變高或改變物種。
- 手腳直接從身體旁邊飄出來。
- 手拿道具時，手與道具沒有實際接觸。
- 表情改變時，眼睛、腮紅與嘴巴整體位置錯亂。
- 動畫中途角色的線條粗細明顯改變。
- 因 SVG 重畫而失去原圖的可愛感。

若重繪結果明顯不如原始素材，必須停止使用該方案，改採原圖拆件與局部補繪。

# 第二部分：Claude Code 應該如何繪製高品質角色

## 2.1 不要直接用 SVG 重畫完整角色

優先採用：

**Original Asset → Segmentation → Layer Separation → Rigging → Keyframes → Rendering**

執行順序：

### A. 原始素材處理

使用 Python Pillow、OpenCV 等影像處理工具：

1. 讀取原始 LOGO。
2. 若是多格分鏡，辨識格子並切割。
3. 去除背景與分鏡文字。
4. 生成透明 PNG。
5. 保留原本抗鋸齒效果。
6. 建立乾淨的邊緣 Alpha Mask。
7. 統一角色大小及定位。
8. 製作標準角色素材庫。

所有動作素材應建立在相同座標系統上。

每個輸出素材先使用 512×512 透明畫布。

如果原圖解析度不足，可使用高品質縮放，但不可以宣稱單純放大就會補回不存在的細節。

### B. 角色分層

依實際素材建立：

- Body Base
- Fur Outline
- Left Ear
- Right Ear
- Eyes
- Mouth
- Blush
- Left Arm / Hand
- Right Arm / Hand
- Left Foot
- Right Foot
- Props
- Effects
- Shadow

注意：原圖若為單一平面影像，不能假設每個部位都能直接無損分離。

請使用遮罩、局部修補、可信的手工路徑與原始影像複製，完成必要拆件。

不要直接刪掉原始像素，使身體留下破洞。

### C. 如果需要新增姿勢

優先順序：

1. 使用現有 8 格動作素材。
2. 使用現有完整身體姿勢，修改局部表情。
3. 利用局部旋轉、變形與遮罩製作新姿勢。
4. 補畫手部、道具或短距離身體輪廓。
5. 只有當上述方法不足時，才手工建立新的 SVG Bézier 路徑。

SVG 應用於：

- 手部和腳部局部補繪
- 表情替換
- 麥克風
- 指示棒
- 晶片
- 晶圓
- 光纖
- PCB
- 圖表
- 裝飾元件

不要讓 SVG 取代原始角色的完整美術表現。

### D. 圖層合成順序

依動作需要調整，但基本順序為：

1. Ground Shadow
2. Rear Limbs
3. Body
4. Facial Features
5. Front Limbs
6. Handheld Props
7. Foreground Effects

道具若位於手掌後方，請加入相應的遮擋層。

必須產生拿住物品的視覺效果，而不是把道具貼在角色旁邊。

# 第三部分：建立可重複使用的毛球 GIF 動作庫

## 3.1 GIF 製作規格

預設規格：

- 512×512
- 透明背景
- 30 格動畫
- 預設 12 FPS
- 時長約 2.5 秒
- 可無縫循環
- 保留自然的角色比例
- 輸出 GIF、APNG 或 Animated WebP
- 同時保留透明 PNG 影格

GIF 的邊緣若因透明色與色盤限制產生鋸齒，請另提供 APNG 或 WebP 高品質版本。

## 3.2 動畫必須使用 Keyframe

不得只有：

`translateY()`、`scale()`、`rotate()` 三種簡單變化。

需要包含：

- Anticipation：預備動作
- Main Action：主要動作
- Follow Through：後續慣性
- Squash & Stretch：擠壓與拉伸
- Secondary Motion：次要動作
- Settle：落地與回穩

例如跳躍：

| 影格    | 動作        |
| ----- | --------- |
| 01–05 | 正常站立、輕微預備 |
| 06–09 | 身體下蹲、壓縮   |
| 10–14 | 向上跳躍      |
| 15–18 | 空中停留      |
| 19–23 | 下落        |
| 24–27 | 落地壓縮      |
| 28–30 | 回復自然姿態    |

變形以保留角色特徵為優先，不可過度拉長毛球。

動畫請使用 Ease In / Ease Out 或自訂緩動曲線。

## 3.3 必須製作的動作類型

### GIF 01：主持開場

情境：科技節目開場。

動作：

1. 毛球從畫面下方探頭。
2. 眨眼。
3. 跳入舞台。
4. 落地後輕微壓縮。
5. 抬起一隻手打招呼。
6. 嘴巴作簡單說話動畫。
7. 回到自然站姿。

用途：Reels 開場、品牌介紹。

### GIF 02：正式講話

情境：介紹科技新聞。

動作：

- 身體微微晃動。
- 嘴巴至少具有閉嘴、微張、張嘴三種狀態。
- 自然眨眼。
- 左右手做小幅度解說手勢。
- 偶爾側頭強調關鍵字。

不可只讓整隻毛球上下浮動。

### GIF 03：疑問與思考

情境：提出問題。

動作：

- 身體稍微傾斜。
- 一隻手靠近臉頰。
- 眼睛轉向旁邊。
- 頭頂出現問號。
- 問號逐漸放大。
- 毛球停頓後露出理解表情。

### GIF 04：驚訝

情境：發現重大科技突破。

動作：

- 突然縮小身體。
- 眼睛睜大。
- 嘴巴變成驚訝的 O 形。
- 雙手微微舉起。
- 身體向後彈。
- 驚嘆號跳出。

### GIF 05：指向標題

情境：介紹文章重點。

動作：

- 毛球看向右側。
- 抬起右手。
- 手掌指向指定文字。
- 身體跟著微微傾斜。
- 目光維持在目標。
- 停留後自然收手。

指向時必須讓手從角色身體延伸，不能出現獨立漂浮的手掌。

### GIF 06：拿麥克風主持

情境：科技節目主持人。

動作：

- 毛球握住麥克風。
- 麥克風靠近嘴巴。
- 嘴巴連續變化。
- 另一隻手進行解說。
- 身體有自然主持節奏。
- 偶爾眨眼。

### GIF 07：拿教學指示棒

情境：講解晶片或數據。

動作：

- 毛球站在白板旁邊。
- 一隻手握住指示棒。
- 指示棒移向晶片圖示。
- 毛球看著指示位置。
- 點一下重點。
- 回頭看觀眾。

### GIF 08：展示科技產品

情境：介紹 HBM、GPU、CoWoS、晶圓。

動作：

- 從身後拿出物品。
- 雙手接住。
- 把物品展示在胸前。
- 微笑。
- 道具閃出細微光芒。
- 收回物品。

道具大小必須符合毛球比例。

### GIF 09：解說圖表

情境：介紹科技產業趨勢。

動作：

- 毛球指向數據圖表。
- 長條圖依序上升。
- 毛球的眼睛追蹤長條圖。
- 出現驚喜表情。
- 手指指向最終數據。

### GIF 10：哭哭／失望

情境：市場下跌、產品失敗。

動作：

- 眼睛變成委屈表情。
- 嘴巴微微向下。
- 身體緩慢塌下。
- 眼角出現小淚珠。
- 雙手垂下。
- 最後恢復自然。

### GIF 11：興奮／慶祝

情境：重大突破、好消息。

動作：

- 先蹲下預備。
- 向上跳躍。
- 雙手抬起。
- 眼睛瞇起。
- 身邊出現星星。
- 落地回彈。

### GIF 12：結尾追蹤

情境：影片結束。

動作：

- 毛球指向追蹤按鈕。
- 按鈕有放大效果。
- 毛球眨眼。
- 雙手拿出愛心。
- 向觀眾揮手。
- 回到第一格形成循環。

## 3.4 動作設計補充

每個 GIF 必須具備：

- 至少一個主要身體動作。
- 至少一個表情變化。
- 至少一個與場景相關的次要動作。

不能把不同 GIF 都做成相同跳躍動畫，再更換道具。

請先建立動作描述、關鍵影格與姿勢轉換，再執行渲染。

每組 GIF 都輸出：

- 30 張原始 PNG 影格
- GIF
- APNG 或 WebP
- 一張 30 格 Contact Sheet
- 動作設定檔

建立以下可重複使用的科技素材：

技術相關素材需要保留可辨識的實體結構。

技術正確性優先於裝飾性。

## 4.3 插畫品質

禁止只使用：

- 矩形
- 圓形
- 直線
- 預設 emoji
- 單色 ICON

來完成整套科技插畫。

請為科技物件建立可重用的詳細 SVG：

- 多層結構
- 圓角與精細邊緣
- 局部高光
- 接點與焊球
- 金屬與封裝材質區分
- 適度陰影
- 清楚的外部輪廓
- 合理的透視角度
- 可供動畫控制的分層結構

可以使用線性漸層、遮罩、裁切路徑、Bézier Path 和局部細節繪製。

但不可以因為增加光效而讓整體變成不符合品牌的 3D 科幻風。
