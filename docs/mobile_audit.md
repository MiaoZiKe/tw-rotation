# 手機／桌機落差稽核（`docs/mobile_audit.md`）

> 起因（Andy 2026-09-23 逐字）：「另外我發現電腦看跟手機看完全不同，幫我依據手機改版頁面，
> 後續還會在更新 先改一版吧」。
>
> 這份是**改版之前的證據**，不是改版之後的說明。先量、再改；沒有量到的東西不寫進來。

## 怎麼量的

用 Playwright 把**每一個路由**在兩個裝置各開一次、各截一張整頁圖：

| | 寬 | 高 | `is_mobile` / `has_touch` | 截圖 |
|---|---|---|---|---|
| 手機 | 390 | 844 | 是（DPR 2） | `/tmp/mobile-audit/<頁名>_m390.png` |
| 桌機 | 1440 | 950 | 否 | `/tmp/mobile-audit/<頁名>_d1440.png` |

路由：`#overview`、`#flow`、`#industry`、`#industry/semiconductor`、`#stock/2330`、
`#themes`、`#themes/ai_server`、`#season`、`#delivery`、`#heatmap`、`#market`（11 個）。

每一頁另外量四件事，結果存 `/tmp/mobile-audit/probe.json`：
① 可見的功能地標（`h3/h4/button/.tab/.pill/table/.seg>button/.nbsw>*`）——
兩邊各一份，**差集就是「某一邊有、另一邊沒有」**；
② 畫面上真實字級 < 12px 的節點；③ 觸控目標 < 32px 高或 < 24px 寬的可點元素；
④ 橫向可捲容器（`overflow-x:auto` 且 `scrollWidth > clientWidth`）與整頁是否橫向溢出。

## 先講結論

**整頁橫向捲軸：11 個路由 × 兩個寬度全部是 0**（`scrollWidth == clientWidth`）——
這一項既有的規矩守住了，不是問題所在。

Andy 說的「完全不同」量得出來的形態有三種，**嚴重度由高到低**：

1. **功能在手機上被裁掉、完全點不到**（G1、G2）—— 這是他抱怨的主因。
2. **同一件事在手機上要滑三倍的距離**（G3、G10）—— 資訊密度差太多，看起來像另一個網站。
3. **看得到但點不準、看不清**（G4～G6）—— 字破 12px 下限、觸控目標太小、可左右滑卻沒有提示。

## 落差清單（16 項）

### ★★★ 一定要修（功能在手機上消失）

**G1　頂欄右半邊在手機被整個裁掉：主題切換與「今日事件」點不到**
- 量到：390px 時 `.topbar` 的 `scrollWidth = 528`、`clientWidth = 390`，
  而 `@media (max-width:820px)` 給了 `.topbar{overflow:hidden}`。
  子元素的實際位置：`#themeBtn` x=384～419（只露出 6px）、`#evToggle` x=427～518（**完全在畫面外**）。
- 後果：**「明亮／深色」與「今日事件」這兩個功能在手機上不存在**。
  桌機的今日事件是常駐右側欄（1440px 量到寬 340px、一直看得到），
  手機版的 `aside` 是 `position:fixed` 的抽屜、**唯一的入口就是被裁掉的那顆「事件」鈕**。

**G2　底部分頁列 8 顆放不下，最後兩頁在畫面外，而且看不出可以滑**
- 量到：390px 時 `#tabs` 的 `scrollWidth = 549`、`clientWidth = 390`。
  各分頁的右緣：總覽 51／資金流向 127／產業與個股 217／熱力圖 279／題材 328／
  **市場明細 404（被切一半）／季節性 467（畫面外）／交付清單 543（畫面外）**。
- `.tabs` 有 `overflow-x:auto`，所以技術上滑得到，但
  ① 手機不顯示捲軸 ② `justify-content:space-around` 讓它看起來「剛好排滿」＝ 沒有任何提示。
- 後果：**「季節性」與「交付清單」兩個完整的分頁在手機上等於不存在。**

**G3　總覽的大盤三張圖：桌機一列三張，手機直立三張要滑 1331px**
- 量到：390px 時 `#m3 .m3-grid` 高 1331px（三張卡各 433／433／437）；
  1440px 時同樣三張並排成一列。
- 後果：手機上要滑過三個整頁畫面才看得到第一個 KPI 數字；
  桌機上「三個指數互相對照」這件事在手機完全做不到（一次只看得到一張）。
  整頁高度：總覽手機 9832px vs 桌機 3306px（**2.97 倍**）。

### ★★★ 明文規矩被破（既有標準）

**G4　手機字級破 12px 下限，8 個頁面都有**
- 量到（畫面上的真實 `font-size`，不是宣告值）：

| 頁 | < 12px 的節點數 | 最小 |
|---|---|---|
| 交付清單 | 170 | 11.0px |
| 季節性 | 76 | 11.5px |
| 單一產業鏈 | 74 | 11.0px |
| 總覽 | 19 | 11.0px |
| 資金流向 | 16 | 11.0px |
| 個股 | 10 | 11.5px |
| 產業地圖 | 9 | 11.5px |
| 市場明細 | 4 | 11.0px |

- 來源：`site/index.html` 裡有 **50 餘處**寫死 `font-size:11px` / `11.5px`
  （`.segcard .sco .code`、`.dlv-*`、`.stage li .m`、`.chainsw button em`、`.facets button em`…）。
  桌機上 11px 勉強可讀，390px 的手上讀不到。

**G5　觸控目標普遍不足 44×44px**
- 量到（390px，`main` 內可點元素的實際外框）：

| 元素 | 實測 | 數量 |
|---|---|---|
| 底部分頁 `.tab` | 45×**32** | 8 |
| `.btn.small`／`.pill`／`.seg>button` | 約 60×**23～29** | 每頁數十顆 |
| 表格／卡片裡的個股連結 `a.lk` | 60×**18～22** | 總覽 18、市場明細 23 |
| 勾選框 `input[type=checkbox]` | **13×13** | 資金流向 8 |

- 後果：手機上很容易點錯隔壁那一顆 —— 尤其是族群晶片列與個股連結。

**G6　橫向可捲的容器沒有任何「這裡可以左右滑」的提示**
- 量到（390px，`clientWidth → scrollWidth`）：

| 容器 | 在哪一頁 | 寬度 |
|---|---|---|
| `#chainSwitch`（產業鏈分頁） | 產業地圖、單一產業鏈 | 362 → **1151** |
| `#dgPick`（剖析圖選單） | 單一產業鏈 | 324 → 507 |
| `#dgTools`（3D 設定列） | 單一產業鏈 | 306 → 416 |
| `#stockTabs`（個股分頁） | 個股 | 362 → 510 |
| `.tw.cap-lg`（明細表） | 市場明細 | 322 → 543 |

- 這些都設了 `overflow-x:auto`（做法是對的，符合「不准整頁橫向捲」），
  但手機不顯示捲軸，使用者不會知道右邊還有東西 —— 例如 `#chainSwitch` 有 **8 條產業鏈**，
  手機上只看得到前 3 條。

### ★★ 手機上「控制項在、被控制的東西不在」

**G7　產業鏈頁：剖析圖手機預設收合，但它的設定列還留在畫面上**
- 390px 量到：`#dgFold` 顯示「展開剖析圖 ▾」（圖是收的），
  但 `#dgPick`（族群總覽／晶圓代工／矽晶圓／HBM…）與 `#dgTools`
  （3D 立體／拖曳：轉動／重設視角／動畫：開）**照樣顯示且可點**。
- 後果：點了「重設視角」畫面什麼都不會變 —— 因為圖根本沒展開。
- ⚠ **手機預設收合是刻意的**（DECISIONS：不收合的話一進產業鏈就吃到 1000px 高的圖），
  這一項要修的是「設定列跟著一起收」，不是把收合拿掉。

**G8　個股頁的繪圖工具列整排丟到手機上**
- 390px 量到：`.drawbar` 在 `@media (max-width:760px)` 被攤平成橫向兩列、
  約 20 顆鈕（游標／線／箭頭／水平線／框／文字／垃圾桶 ＋ 6 個色塊 ＋ 4 種線型 ＋ 還原／關閉），
  每顆 20×20 ～ 30×24px。桌機是圖表左側的直排工具列。
- 後果：手機上位置與方向都跟桌機不一樣（G 第 1 條判準：位置要對應得起來），
  而且 20×20 的按鈕在手指下幾乎點不準。

**G9　今日事件：桌機常駐側欄 vs 手機抽屜**
- 這個做法本身是對的（手機收進抽屜是允許的），**問題只在入口被 G1 裁掉**。
  G1 修好，這一項自動解決。列出來是為了記錄「抽屜是刻意的，不要改回常駐側欄」。

### ★★ 資訊密度（手機要滑太久）

| 頁 | 手機 390 | 桌機 1440 | 倍數 |
|---|---|---|---|
| 交付清單 | 11349 | 4005 | **2.83** |
| 總覽 | 9832 | 3306 | **2.97** |
| 季節性 | 5837 | 3309 | 1.76 |
| 個股 | 4412 | 2478 | 1.78 |
| 資金流向 | 4222 | 2811 | 1.50 |
| 產業地圖 | 2111 | 1147 | 1.84 |
| 市場明細 | 1894 | 1439 | 1.32 |
| 題材細節 | 1931 | 1619 | 1.19 |
| 熱力圖 | 1198 | 950 | 1.26 |
| 題材 | 1101 | 950 | 1.16 |
| 單一產業鏈 | 2622 | 4293 | 0.61（手機收合了兩張圖，見 G7） |

- 「1.5 倍以內」是單欄化的自然結果，可以接受。
  **2.8～3.0 倍的那兩頁（交付清單、總覽）才是要處理的** ——
  總覽的主因就是 G3（三張圖 1331px）。

### ★★ 其他

**G11　`#dgTools` 在窄畫面自己變成一條可捲的列，但它是「設定」不是「內容」**
- 設定列被捲到看不見時使用者不會去找它（跟 G6 同一個根因，但這一條是設定不是導覽，優先度較低）。

**G12　產業鏈頁的分層關聯圖手機預設收合、留了「展開關聯圖 ▾」**
- 量到 390px `#relFold` 顯示「展開關聯圖 ▾」，桌機顯示「收合圖 ▴」（預設展開）。
- **這是刻意的**（同 G7 的理由）。展開後關聯圖需要能左右滑 —— 併進 G6 一起處理。

**G13　市場明細的表格在手機用 `.tw.cap-lg` 橫向捲（322 → 543）**
- 做法正確（不准整頁橫向捲），缺的一樣是提示（併入 G6）。

### ✅ 已經做對、不要改回去的

**G14　總覽「今日候選」表格 → 手機換成卡片**
- 390px 量到 `#candTable` 的 `.tw` 是 `display:none`、`#candCards` 是 `display:grid` 且有 **30 張卡**。
  **資訊沒有被刪掉，只是換了呈現**，符合判準。

**G15　資金流向的桑基圖在手機少「代表股」那一層，而且標題寫明了**
- 桌機標題：「資金去向 …：台股 → 產業鏈 → 族群 → 代表」
- 手機標題：「資金去向 …：台股 → 產業鏈 → 族群（畫面太窄…」
- **在原地留了說明**，符合判準 1 的「不是靜靜不見」。

**G16　剖析圖在手機不壓縮、改成左右滑**
- `.dgwrap{overflow-x:auto}` ＋ `.dgwrap svg{min-width:940px}`。
  這是對的（壓到 360px 標籤會只剩 3px），一樣只差 G6 的提示。
