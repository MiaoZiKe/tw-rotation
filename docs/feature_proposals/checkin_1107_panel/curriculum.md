## 1. 寫作共同規格（4 位寫手都照這個）

| 項目 | 規定 |
|---|---|
| 長度 | 入門 800～1,100 字；進階 1,100～1,500 字 |
| 結構 | 一句結論 → 三個重點 → 一個歷史案例 → 常見誤用 → 這跟你有什麼關係 → 來源（至少 2 個獨立來源）、資料日期、信心度 |
| 圖表 | 每篇至少 1 張圖（沿用 `articles.js` 的 chart／flow／stack／steps／compare 區塊），有數字就圖表化 |
| 案例 | 只准「已發生的歷史」，標明日期區間；不寫「接下來會怎樣」 |
| 事實 | WebSearch 摘要是線索不是事實；數字與括號對應（中文名（英文名））一律用不同關鍵字二次查證 |
| 語言 | 繁體中文，專有名詞第一次出現寫「中文（原文）」 |
| 比比 | 文章內不放比比（11-02 規定貼文不放比比；站內長文跟著不放） |
| 文末 | 固定「本文為教育說明，不構成任何買賣建議」＋ 資料來源 |

**案例欄裡的日期與數字是我憑記憶列的方向，寫手一律要先查證再用；查不到就換案例，不准照抄。**

## 7. 文章包設計

### 選擇：跨領域混搭，每包固定 1 技術＋1 籌碼＋1 總經＋1 產業，共 4 篇

**理由：**

1. **留存**：依領域分包的話，使用者拿到整包都是不感興趣的領域，簽到動力降低；混搭讓每個月都有「喜歡的那一篇」。
2. **學習順序**：入門與進階同包混搭，前期（P1～P6）以入門為主，後期（P9～P14）進階比例上升，天然形成難度曲線。
3. **互相呼應**：每包刻意搭一個主題（見表），讀完能把技術、籌碼、總經、產業串成同一個市場故事，符合本站「資金面→基本面→技術面→事件面」判斷順序。
4. **工作分工**：4 領域對應 4 位寫手，每包 4 篇剛好每人一篇，交稿與審稿可以按包同步進行。
