# Token 用量節省規則與監控（2026-11-27 Andy）

Andy 原話：「改善做法 全部幫我處裡最好，並且需要安排時時監控，異常使用量需要有專人優化 找問題 和提醒」。
起因：11-27 15:26～18:28 同時開 7 個子聊天室，3 小時燒約 618 美元（每小時約 200 美元，舊做法的 7 倍），週額度快見底。
花費 9 成以上是「快取讀取」：每做一步都要把整段前文重讀一次，前文越長、步數越多就越貴。

## 一、五條省錢規則（所有頻道、所有 Claude 都適用）
1. **一支片（一個主題）一個新聊天室，做完就收**：子聊天室交件後不接下一個主題；下一個主題開新聊天室。前文目標 ≤15 萬 token。
2. **交接只給精簡說明**：新聊天室開工只讀 `ai-mp4/docs/channels/tech-child-brief.md`（一頁）＋該片規格；不整份讀 CLAUDE.md 以外的大文件，需要時再查特定段落。
3. **少看大圖、少印長輸出**：審片抽關鍵格、縮小到 ≤540 寬再看；縮圖總表一張就好；指令輸出只印最後幾行（`| tail`），不把整份 log、JSON 印進對話。
4. **主聊天室（頻道聊天室）前文超過 25 萬 token 就交接換新**：寫交接檔（進行中、待辦、各子聊天室 id），開新聊天室接手，舊的停用。
5. **同時最多 3 個子聊天室**（蓋過 11-27「全部一起開」那批的例外）。要更快只能由 Andy 明講才放寬。

## 二、時時監控（專人：用量監工）
- 排程：每 2 小時一次（台北 10:13～02:13），開一個新聊天室跑「用量監工」，只做量測與提醒，不改產品。
- 量什麼：所有自己帳號的聊天室（list_sessions mine），逐個 get_session 讀 usage.cost_usd、context_usage.used_tokens、狀態；和上次快照（本檔「三、快照」）比。
- 異常門檻（任一條成立就算）：
  - 單一聊天室兩次量測間每小時 > 30 美元；
  - 單一聊天室前文 > 25 萬 token 且還在工作；
  - 同時工作中的子聊天室 > 3 個；
  - 全帳號兩次量測間每小時 > 80 美元；
  - 週額度狀態出現 allowed_warning 以上（rate_limit_info.status）。
- 異常時做的事：
  1. 找原因：讀該聊天室最後 20 則事件（list_events，只取 assistant／result），判斷是前文太長、重複看大圖、迴圈重試、等待中空轉，還是同時開太多。
  2. 提醒：send_message 給該聊天室（一句話：哪條超標、建議怎麼改，例如「交接換新」「停止抽大圖」），同時通知主控（主聊天室）。
  3. 記錄：在本檔「四、異常紀錄」加一列（時間、聊天室、指標、原因、處理）。
- 沒有異常：只更新快照，不發訊息、不打擾任何人。
