## 0. 開畫之前要先簽掉的三件事

### 0-A　要不要 3D —— 結論：**不做真 3D**

| 這張圖要講的事 | 轉一圈會多理解嗎 | 判定 |
|---|---|---|
| **風由上往下吹、穿過高架地板、再回到上面** | **不會，而且轉了更糟。** 垂直層流的全部意義就是「方向」與「樓層先後」，那是剖面上的一組箭頭 | **2D 垂直剖面（本圖核心）** |
| **機台在潔淨室、泵浦與 local scrubber 在下一層** | **不會。** 那是樓層的上下關係 | 2D 剖面 |
| **化學品從儲槽送到機台** | 不會。那是一條有方向的線 | 2D 路徑 |
| **廢氣先就近處理、再進主系統** | 不會。那是順序 | 2D 路徑 |
| **廢水依水質分類再處理** | 不會。那是分岔 | 2D 路徑 |
| **FFU 的覆蓋率** | **會一點點**（覆蓋率是天花平面上的比例） | **2D 俯視小格**（天花格子圖，塗色的是 FFU），比 3D 清楚 |

反面成本三條：
1. 本圖六個資訊點全部是「方向」與「先後」，3D 的透視只會讓樓層互相遮擋。
2. 廠房尺度（數十公尺）與管路尺度（公分）差三個數量級，3D 渲染時管路會消失。
3. `semiconductor` 這條鏈已經有一個 3D 場景（`SCENES.semiconductor`）。

**什麼條件下才該回頭加 3D**（寫死）：

> 只有當這張圖要新增「**整座廠房的平面配置與機台區塊的空間關係**」（哪一區是黃光、哪一區是蝕刻、
> 晶圓怎麼在區間傳送）時才重開這一段、改規格書、重新簽。
> **而且比較好的做法是另開一張「廠區平面」圖，不是把這張改成 3D。**

### 0-B　這張圖與 S1／S3／S4 的交界（寫死）

| 邊界 | 這張圖 | 那張圖 |
|---|---|---|
| **製程** | **不畫任何製程步驟**（不畫黃光、蝕刻、CMP 的動作） | `foundry_process.md`（S1） |
| **材料本身** | **只畫「化學品怎麼被送到機台」這條路**，不畫材料是什麼 | `fab_material.md`（S3） |

## 1. 這張圖要回答什麼問題

**「潔淨室的風從哪來、往哪去？化學品與特殊氣體怎麼送到機台？廢氣廢水怎麼處理？台股這九家各自包到哪一段？」**

使用者看完要能自己講出這四句：

1. **潔淨室的風是「從天花板往下吹、穿過地板、再從側邊回到天花」的一個閉合循環。**
   吹風的是**風機濾網機組（FFU）**，它把風打過 HEPA／ULPA 濾網才送進潔淨室（§7-A1）。
2. **機台不是孤島，它有三個接點**：上面接風、側面接化學品與特殊氣體、下面接廢氣與廢水。
   而**接到機台的最後那一段叫「二次配（hookup）」** —— 那是廠務端與設備端之間的銜接工程（§7-A3）。
3. **廢氣要先就近處理，再進廠區主系統。**
   機台旁的**局部廢氣處理設備（local scrubber）**先用燃燒水洗、電漿、催化等方式處理，
   之後才排進廠區的排氣系統做二次處理（§7-A4）。
4. **台股這九家不是同一件事。**
   有人做無塵室與機電統包（漢唐、亞翔、聖暉、洋基），
   有人做特殊氣體與化學品的管路與供應系統（漢科、朋億、信紘科），
   有人做設備 OEM ＋ 代理 ＋ 廠務整合（帆宣），
   有人做**氟塑料內襯的管道、儲槽與 ISO Tank**（上品）（§7-A6、§7-D2）。

**這張圖的成敗**：Andy 指著剖面上任何一段管路，要能說出
「這一段在送什麼、往哪個方向、**台股哪一家在做這一段**」。第三句講不出來，圖就白畫。

## 3. 層別／順序（★ 可判定的條目）

### 3-A 氣流（最常錯的一組）

- **A1**　★★★ **潔淨室裡的主氣流方向是「由上往下」。**
      箭頭朝上＝把整個垂直層流的概念畫反了，**直接退回，不進二輪**。
- **A2**　★★★ **FFU 的濾網必須畫在風扇的「下方」（出風側）。**
      濾網畫在風扇上面＝送進潔淨室的是還沒過濾的風，**直接退回**。
      驗法：量兩個元素的 y 座標，濾網的 y 必須大於風扇的 y（SVG 座標往下為大）。
- **A3**　★★ **氣流必須是閉合循環**：下行穿過高架地板 → 從側牆（或回風道）往上 → 回到 FFU 層。
      只畫下行、沒有回路＝讀者以為風是一次性的。
- **A4**　★ **機台方塊的三個接點要分開畫**：**上面接風、側面接化學品／氣體、下面接廢氣／廢水**。
      三條線從同一個點出去＝讀者分不出誰是誰。
- **A5**　**MAU 的線要接到迴風側（與迴風混合），不是直接接進潔淨室。**
      MAU 送的是外氣，直接吹進潔淨室＝把「外氣要先處理再混合」這件事畫掉了（§7-A2、§7-B1 降信心）。
- **A6**　**高架地板必須畫成有孔的**。畫成一塊實心板＝風下不去。

### 3-B 化學品與特殊氣體

- **B1**　★★ **方向是「儲槽 → 主系統 → 二次配 → 機台」，一路往機台走。**
      箭頭反了＝變成機台在供應儲槽。
- **B2**　★ **「二次配（hookup）」必須被標出來，而且是在 sub-fab 與機台之間的那一段。**
      把它畫在儲槽那一端＝名字的意思就錯了（那是「主系統」）（§7-A3）。
- **B3**　**儲槽／鋼瓶櫃在主系統層（⓪），不在潔淨室裡。**
- **B4**　**ISO Tank／槽車接收站畫在最外側**（它是從廠外進來的那一端）。

### 3-C 廢氣

- **C1**　★★★ **local scrubber 必須在「機台」與「廠區排氣主系統」之間，而且靠近機台（在 sub-fab）。**
      畫成「機台 → 主系統 → local scrubber」＝順序整個反了，**直接退回**。
      它叫「**局部**」廢氣處理，意思就是**就近處理**（§7-A4）。
- **C2**　★ **廢氣路徑的終點是煙囪（往廠外）**，而且中間經過主系統的二次處理。
- **C3**　廢氣不可以跟廢水共用同一條線或同一個顏色。

### 3-D 廢水

- **D1**　★★ **「依水質分類（分流）」必須在「處理」之前。**
      先處理再分類＝把不同水質混在一起處理，實務上不成立（§7-A7）。
- **D2**　★ **回收再利用是一條「折回來」的支線**（回到廠內），不是終點。
      沒有回收支線＝把廠務最重要的一件事（水回收）畫掉了。
- **D3**　處理槽要畫**至少兩個**（分流之後是多條線），不是一個。

### 3-E 圖例與標示帶

- **E1**　★ 四條路徑**各有自己的顏色與方向箭頭**，圖例上四條都列得出來。
- **E2**　★ 承包範圍標示帶的四段**必須各自對到剖面上的區域**（用色塊或引線），
      不是只列在底下一排文字。
- **E3**　★★ **每一段都要列得出公司代號與名稱**，而且**九檔全部都要出現在某一段上**。
      有公司沒有被標到任何一段＝讀者會以為它不做這行（§7-D2）。

## 4. 識別特徵 ＋ 最常見的畫錯

### 4-A 一定要有的識別特徵

- **FFU**：**上半風扇、下半濾網**，一排掛在天花。
- **層流**：**一整排朝下的箭頭**，穿過有孔的高架地板。
- **sub-fab**：機台**正下方**有泵浦與 local scrubber。
- **二次配**：從 sub-fab **往上接到機台側面**的細管。
- **廢水**：**先分流、再處理、有一條折回來的回收支線**。
- **標示帶**：**四段，九檔全部有位置**。

### 4-B 最常見的畫錯

| # | 畫錯的樣子 | 為什麼是錯的 | 對應審查 |
|---|---|---|---|
| 1 | **層流箭頭朝上** | 垂直層流的定義就是由上往下 | **A1（紅線）** |

## 8. 2D 的驗收條件

- **結構**（`mechanical-engineer` 簽）：照 §6 的 A／B／C／D／E／M／H 七組逐條。
  **A1（氣流朝下）、A2（濾網在風扇下方）、C1（local scrubber 在機台與主系統之間）是紅線**。
- **視覺**（`art-director` 簽）：字級全圖 ≥ 12px，實測畫面真實字級在
  **1440 / 1100 / 900 / 800 / 390** 下都 ≥ 12px；深淺主題各驗一次。
  ★ **四條路徑的顏色必須在四個配色下兩兩量得出色差**（這張圖的資訊全在「哪條線是哪條」）。
  `art-director` 要指定四個 token 並量測；**不可以借用語意色**（`--dg-err`／`--dg-warn`／
  `--dg-cold`／`--dg-hot`），那四個在四個配色下刻意不被覆寫，借用會混淆語意。
- **互動**（`_uitest.py` 真的操作）：
  1. **驗「只有一個 `data-seg`」**：`svg.querySelectorAll('[data-seg]').length === 1`
     且它的值是 `fab_equipment`（反向驗收，證明沒有偷掛錯環節）；
  2. 點 **「廠務工程整合」** → 小卡列出 **6196 帆宣**，且**名單裡沒有 3413 與 3680**（`cos` 真的生效）；
  3. 點其他零件 → **沒有小卡**，但**畫面上的承包範圍標示帶看得見公司名**；
  4. **九個代號逐一在圖上找得到**（E3 的機器版）；
  5. **800px 與 390px** 下可左右滑、無文字重疊、無整頁水平捲軸；
  6. 切到「休閒」配色 → 四條路徑仍兩兩分得出來、語意色沒被覆寫。
- **效能**：不新增函式庫、不新增 CDN；動畫只有一個 rAF，頁面切走要停。
- **不畫**任何真實公司的產品外觀、logo、包裝、商標。

## 9. 給 `tech-illustrator` 的實作邊界

- **先把六層的樓層線與四條路徑畫出來**，再補設備方塊。
  這張圖的資訊**全部在路徑上**；設備只是路徑的節點。
- **FFU 用一個 `for` 迴圈畫一排**，每個 FFU 是**兩個疊起來的 `rect`**：
  上面是風扇、**下面是濾網**（用不同 `fill`）。
  **把「下面那個是濾網」寫在同一行程式裡**，A2 就不可能畫反。
- 層流箭頭用 `for` 迴圈畫一整排朝下的 `path`，**y2 > y1 寫死在函式裡**（A1 的程式層面保險）。
- 迴風用一條繞過兩側的 `path`，**終點要真的回到 FFU 那一排的進風側** —— A3 最常見的失敗是「畫到一半就停」。
- 四條路徑用**四個不同的 `class`**（`.air` / `.chem` / `.gas` / `.water`），
  顏色寫在 CSS 的 `--dg-*` 裡，**不要在 `path` 上寫 inline `stroke`** ——
  inline 贏過 CSS，配色切換時會有一條不跟著變。
- **local scrubber 畫在機台正下方那一格**，而且**它的 x 要跟機台對齊** ——
  對不齊讀者就看不出「它服務的是這一台」。
- 承包範圍標示帶用四個色塊 ＋ **引線接到剖面上對應的區域**（E2）。
  **九個代號寫在一個陣列裡、用迴圈印**，這樣 E3（九檔全部出現）在程式層面就成立。
- 顏色一律走 `--dg-*`，不准寫死 `#xxxxxx`。這張圖**幾乎沒有 `data-seg`**，
  所以 `var(--c)` 用不到 —— 需要 `art-director` 指定一組本圖用的 `--dg-*`
  （風、化學品、廢氣、廢水各一色，外加樓層、設備、潔淨室底色）。
- **`data-part` 一律要寫**（沒有 `data-seg` 時 `stampParts` 自動補的 key 會退化成「`null` ＋ 序號」）。
  建議命名：`ff_ffu` / `ff_filter` / `ff_flow` / `ff_raised` / `ff_return` / `ff_mau` / `ff_tool` /
  `ff_pump` / `ff_scrubber` / `ff_exhaust` / `ff_cds` / `ff_gds` / `ff_hookup` / `ff_tank` /
  `ff_iso_tank` / `ff_waste_split` / `ff_waste_treat` / `ff_reclaim` / `ff_integrate` /
  `ff_band1` … `ff_band4`。
- 動畫：只做一件事 —— **一顆空氣粒子沿著「FFU → 潔淨室 → 高架地板 → 側牆 → 回到 FFU」跑一圈**。
  那正好把 A1 與 A3 一次講完。**不要讓四條路徑同時動**（會變成閃爍的麵條）。
  靜止時所有箭頭仍看得見。
- **SVG 的 `<style>` 裡（含註解）一律不准出現角括號。**
