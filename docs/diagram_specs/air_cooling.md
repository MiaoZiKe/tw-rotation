## 0. 要不要 3D —— 判斷與理由（★ 這一段要先被簽掉）

**結論：不做真 3D。`SLOTS` 的 `scene` 留 `null`。**

⚠ 這張圖是**三張裡最有 3D 誘惑的一張**（風扇會轉、扇葉是三維曲面），
所以判準要比另外兩張更嚴格地逐項對。判準照 AGENTS.md §11：
「3D 只有在『轉一圈真的能多理解一件事』時才用」。

| 這張圖要講的事 | 轉一圈會多理解嗎 | 判定 |
|---|---|---|
| 扇葉有傾角／扭曲（不是平板） | **一點點**，但 2.5D 等角把「葉片是斜的、靠斜面把空氣往後推」已經講完了。真 3D 多出來的是「從別的角度看也是斜的」——那不是新資訊 | 2.5D 等角即可 |
| 軸流 vs 離心的氣流方向差別 | 不會。要講的是「**進氣與出氣的夾角是 0° 還是 90°**」，那是**兩個箭頭的關係**，2D 剖面最清楚；3D 裡氣流箭頭會被殼體擋住 | 2D 剖面對照 |
| 軸承四型（含油／滾珠／流體動壓／磁浮） | 不會。四者的差別**全部在剖面裡**：有沒有滾珠、有沒有油膜、有沒有磁隙。真 3D 轉到任何角度看到的都是一根軸 | 2D 剖面四格 |
| 風壓—風量曲線與工作點 | **不會，而且 3D 根本畫不了**。這是一張 X-Y 圖 | 2D 曲線圖 |
| 扇葉數與噪音（BPF） | 不會。這是「轉速 × 葉片數＝一個頻率」的算術，用頻譜示意圖表達 | 2D 示意圖 |
| 風扇牆的排列與 N+1 備援 | 不會。這是**幾個一排、壞一個還能不能撐**的計數問題 | 2D 平面 |
| 反轉雙轉子（counter-rotating） | 不會。關鍵是「前後兩組葉片**旋向相反**」，兩個反向的弧形箭頭就講完了 | 2D 剖面 |
| 散熱鰭片＋熱管＋VC 的組裝關係 | **一點點**。鰭片是三維的一疊薄片，等角圖已足夠 | 2.5D 等角 |

**唯一一個「3D 可能有用」的候選**是「**整櫃氣流路徑**（前進後出、冷熱通道、風扇牆位置）」——
但那是**機櫃級的空間關係**，`three3d.js` 既有的 `ai_server` 機櫃場景
（`dg3d_standard.md` 的 16 個零件）本來就在處理那一層，再做一個是重複。

反面成本三條：
1. 3D 的風扇要好看就要畫扭曲葉面（曲面細分），多邊形數會暴增；
   而 AGENTS §11 明講「**特徵比多邊形數重要**」。
2. 3D 在手機吃力（AGENTS §11 明列）。
3. 每多一個 3D 場景就多一組 WebGL context 與 rAF 迴圈要管（`dispose3D()` 那條既有的坑）。

**⚠ 特別警告一種「假的 3D 理由」**：
「風扇會轉，所以做成 3D 讓它轉起來比較生動」——**這不是理由**。
「轉起來」是**動畫**，2D／2.5D 一樣做得到（本規格書 §9 就指定了一個旋轉動畫），
跟「要不要真 3D」是兩件事。**把動畫需求當成 3D 理由，就是 MLCC 那次事後補簽的同一個坑。**

**什麼條件下才該回頭加 3D**（寫死）：
> 只有當這張圖要新增「**整櫃或整台伺服器內部的三維氣流場**」（冷熱通道、擾流、迴流死角）
> 這一類**空間流場**資訊，**而且**確認既有的 `ai_server` 3D 機櫃場景無法承擔時，
> 才重開這一段、改規格書、重新簽。
> 「風扇會轉所以要 3D」「看起來比較立體」**都不算理由**。

## 1. 這張圖要回答什麼問題

畫面上要印出這三個問題（`q` 欄位取前兩個）：

1. **「伺服器風扇跟家用風扇差在哪？」**（答案：**風壓，不是風量**）
2. **「都上液冷了，為什麼一櫃還要幾百顆風扇？」**
3. **「軸承是什麼、為什麼它決定了風扇的壽命與噪音？」**

使用者看完要能自己講出這四句：

1. **伺服器風扇賣的是「推得過去」不是「吹得多」**：
   要穿過密排鰭片、儲存背板、GPU 隧道這些高阻抗的路徑，
   **靜壓（static pressure）比風量（CFM）重要**。家用電風扇前面沒有東西擋，所以完全相反。
2. **軸流與離心是兩種氣流幾何**：軸流的進氣與出氣**同一個方向**（沿著軸）；
   離心是**沿軸進、轉 90° 出**。要高靜壓、路徑又彎的地方就用離心。
3. **軸承決定壽命與噪音**：含油最便宜但先變吵、滾珠耐久、流體動壓幾乎沒有機械噪音、
   磁浮沒有機械接觸。**機房裡一顆風扇壞掉要有人去換，所以壽命是錢。**
4. **液冷不是把風扇變成零**：冷板只貼在最熱的那幾顆上，
   電源、記憶體、VRM、光模組這些仍然靠氣流；所以液冷機櫃裡**還是有幾百顆風扇**。

**這張圖的成敗**：Andy 指著圖上任何一個零件，要能說出
「這一塊變好會讓什麼變好、代價是什麼」。講不出這句，圖就白畫。

## 3. 層別／流向順序（★ 最常錯，四組全部寫死）

### 3-A 氣流路徑（由前到後，這是主圖的主軸）

```
 機殼前面板（進氣，冷空氣）
   │
 風扇牆（N+1，多顆並排）
   │
 導風罩／風道（把氣流圍成一條路）
   │
 散熱鰭片組 ←── 熱管／VC ←── 晶片底座
   │
 其餘元件（記憶體、VRM、電源、光模組）
   │
 機殼背面（排氣，熱空氣）
```

**硬規則（違反其一就退回）**：
- **氣流方向全程單向、由前到後**，圖上不准出現往回吹的箭頭
  （除非那一格明確標成「迴流死角」的反例）。
- **風扇牆在鰭片之前**（先吹風、再過鰭片），不可以畫成鰭片在風扇前面。
- **進氣端的氣流顏色比排氣端冷**，而且**同一條氣流的顏色要沿路漸變**，不是兩段跳色。
- **熱的方向（晶片 → 底座 → 熱管／VC → 鰭片）與氣流方向是垂直交會的**，
  不是同一條線。畫成同一條線＝讀者會以為熱是被「吹」出來的。

### 3-B 風扇本體（由內到外）

1. **軸／軸承**（四型之一）
2. **馬達**（定子線圈在內、轉子磁鐵在輪轂內壁）
3. **輪轂**
4. **扇葉**（從輪轂長出來，**有傾角**）
5. **扇框**（四角鎖孔）

**硬規則**：
- **扇葉一定從輪轂長出來**，不可以畫成扇葉懸空、中間沒有輪轂。
- **馬達一定在輪轂裡**，不可以畫在扇框上。
- **軸承一定在軸與輪轂之間**，四格剖面**用同一根軸畫**（不然比不出差別）。
- 四型軸承的辨識特徵**不准互換**：
  含油＝軸與襯套**直接接觸**；滾珠＝**看得到鋼珠**；
  流體動壓＝軸與襯套之間**一層油膜**且襯套上**有溝槽**；磁浮＝兩者之間**有可見空隙**。

### 3-C 軸流 vs 離心（兩格對照，這一段最常被畫反）

| | 進氣方向 | 出氣方向 | 兩者夾角 |
|---|---|---|---|
| **軸流（axial）** | 沿著轉軸進 | **沿著轉軸出** | **0°** |
| **離心／鼓風（centrifugal／blower）** | 沿著轉軸進 | **從側面（徑向）出** | **90°** |

**硬規則**：
- 離心那一格**必須畫出側面的出風口**（蝸殼／出風管），
  而且**出氣箭頭與進氣箭頭夾 90°**。畫成同向＝不過。
- 兩格的進氣箭頭**都要沿軸**（兩種都是沿軸進氣）。把離心畫成側面進氣＝不過。
- P-Q 曲線圖上，**離心那條線的靜壓端要高於軸流**、
  **軸流那條線的風量端要大於離心**（§7-A3）。兩條線畫成一樣、或反過來＝不過。

### 3-D 底部流程列（由左到右，5 格）

1. **進氣**：前面板濾網／開孔
2. **推動**：風扇牆（N+1）
3. **導引**：導風罩／風道
4. **交換**：鰭片 ＋ 熱管／VC（熱從這裡進到空氣裡）
5. **排氣**：後方出風

**硬規則**：格 2（風扇）一定在格 4（鰭片）**之前**。
格 4 要標一行「**這一格才是熱真正交給空氣的地方；風扇只是把空氣推過來**」——
這是整張圖最容易被誤解的一點（很多人以為「風扇在散熱」）。

## 4. 一定要有的識別特徵

看到這些才認得出這是伺服器氣冷，而不是一台電風扇加幾片鐵：

- **扇葉有傾角、而且數得出片數**（建議畫 7 或 9 片，**並在標註裡寫明「片數為示意」**）。
- **輪轂佔的比例明顯**（伺服器風扇的輪轂比家用風扇大，因為馬達要有力）。
  ⚠ 這一條是**外觀常識**，沒有查到可引用的比例來源 → 只畫、**不標數字**（§7-C）。
- **四型軸承剖面並排，而且用同一根軸**；四個的差別一眼看得出來。
- **反轉雙轉子的兩組葉片旋向相反**（用兩個反向弧形箭頭標出來）。
- **離心那一格有側面出風口**。
- **P-Q 曲線圖上有「系統阻抗曲線」與「工作點」**——
  只畫風扇曲線不畫系統曲線，就講不出「工作點」這件事，整張圖的立論就缺一半。
- **風扇牆是一排（不是一顆），而且其中一顆被標成備援**。
- **鰭片是一疊等距薄片**，而且圖上**至少有兩種鰭距**（疏／密）可以對照。
- **熱管／VC 的剖面看得出內部是空的**。
- **混合散熱對照格**：冷板貼 GPU、氣流掃過其餘元件。
  **沒有這一格，「為什麼還要風扇」就沒有畫面上的答案。**

一律引線拉到外側文字框，**不壓在零件上**，畫面上真實字級 ≥ 12px。
主標題：`氣冷：風扇賣的是「推得過去」，不是「吹得多」`

| 指到哪個零件 | 文字寫什麼（標題／副標） |
|---|---|
| 扇葉（2） | **扇葉有傾角**／靠斜面把空氣往後推。葉片數與角度決定了同一顆馬達能推出多少風、產生多少噪音 |
| 輪轂與馬達（3、4） | **馬達藏在輪轂裡**／伺服器風扇的轉速可以到每分鐘上萬轉，馬達要撐得住連續運轉 |
| 軸承・含油（5a） | **含油軸承（sleeve）**／最便宜，軸直接在襯套裡轉。潤滑油會耗損，所以是四型裡**最早變吵**的 |
| 軸承・滾珠（5b） | **滾珠軸承（ball）**／兩圈鋼珠把軸撐起來，壽命明顯長於含油，代價是本身有一點滾動噪音。**伺服器與長時間運轉的機器常用這一型** |
| 軸承・流體動壓（5c） | **流體動壓軸承（FDB）**／襯套上刻溝槽，轉起來把油擠成一層壓力油膜，把軸**浮起來**。幾乎沒有機械噪音，而且噪音一生都不太變 |
| 軸承・磁浮（5d） | **磁浮（maglev）**／用磁力把轉子浮起來，**沒有機械接觸**，所以理論壽命最長 |
| 四線接頭（6） | **四線：電源／地／轉速回授／PWM 控制**／轉速回授讓主機知道這顆有沒有在轉（所以壞了會報警）；PWM 讓主機依溫度調速 |
| 反轉雙轉子（7） | **反轉雙轉子（counter-rotating）**／前後兩組葉片**旋向相反**，後面那組把前面那組甩出來的旋轉氣流「扶正」，因此在同樣厚度下能拉高靜壓。常見於機櫃這類又窄又擠的地方 |
| 軸流（8 左） | **軸流（axial）**／進氣與出氣**同一個方向**。風量大，但一遇到阻力就掉得快 |
| 離心／鼓風（8 右） | **離心（centrifugal／blower）**／沿軸進、**轉 90° 從側面出**。同樣尺寸下**靜壓比軸流高**，適合路徑又彎又擠的地方 |
| P-Q 曲線（9） | **風扇不是只有一個「風量」**／同一顆風扇在不同阻力下吹出的量完全不同。**風扇曲線與系統阻抗曲線的交點，才是它真正的工作點** |
| 工作點（9） | **伺服器要的是右上那一段**／密排鰭片、儲存背板、GPU 隧道都是高阻抗，所以**靜壓比風量重要**——這就是伺服器風扇跟家用風扇最根本的差別 |
| 噪音（10） | **葉片數 × 轉速 ＝ 那個「嗡」的頻率**／等距排列的葉片會把能量集中在這個頻率與它的諧波上；把葉片排得不等距，能量就會被攤開成一片而不是一根尖峰 |
| 風扇牆（11） | **風扇牆與 N+1**／多算一顆，壞掉一顆時剩下的補得上。而且可以熱插拔——機房不會為了換風扇關機 |
| 導風罩（12） | **導風罩：把風「圍」到該去的地方**／沒有它，風會走阻力最小的路，繞過最需要散熱的零件 |
| 鰭片（13） | **鰭片才是熱交給空氣的地方**／風扇只是把空氣推過來。鰭越密面積越大，但阻力也越大——**又回到 P-Q 曲線那張圖** |
| 熱管／VC（14、15） | **先把熱從晶片搬到鰭片**／熱管把熱沿一條線送走、VC 把點熱源攤成一個面。兩者內部都是真空腔＋毛細層，不是實心銅（詳見液冷那張） |
| 混合散熱（16） | **上了液冷，風扇不會變成零**／冷板只貼在最熱的那幾顆（GPU／部分 CPU）上；記憶體、VRM、電源、光模組仍然靠氣流。所以液冷機櫃裡**還是有幾百顆風扇** |
| 流程列格 4 | **這一格才是熱真正交給空氣的地方**／風扇只是把空氣推過來 |

## 6. 結構審查清單（`mechanical-engineer` 逐條驗，每條都要判得出過／不過）

> 寫法規則：每一條都是「A 必須在 B 之前」「A 不可以碰到 B」「A 的數量／大小關係必須是 X」
> 這種**看圖就能判定**的句子。**不准出現「要畫得清楚」「要好看」這種驗不動的條目。**

**A 組・氣流與順序**
- A1　風扇牆畫在鰭片組**之前**（氣流先過風扇、再過鰭片）。反過來＝不過。
- A2　氣流箭頭**全程由前到後單向**；唯一允許的反向箭頭是明確標成「迴流死角」的反例格。
- A3　離心那一格的**出氣方向與進氣方向夾 90°**，而且**畫得出側面出風口**。
- A4　軸流與離心**兩格的進氣都沿軸**。
- A5　熱的路徑（晶片 → 底座 → 熱管/VC → 鰭片）與氣流路徑**在鰭片處垂直交會**，
      不是畫成同一條線。
- A6　進氣端與排氣端**用不同顏色（冷→暖）**，而且同一條氣流是**漸變**不是跳色。

**F 組・風扇本體**
- F1　扇葉**都連到輪轂**，沒有懸空的葉片。
- F2　扇葉**有傾角**（不是與旋轉平面平行的平板）。
- F3　馬達畫在**輪轂裡**，不在扇框上。
- F4　反轉雙轉子的兩組葉片**旋向相反**，而且有兩個反向箭頭標出來。
- F5　四線接頭是**四條**，而且標籤寫出四條各是什麼。

**B 組・軸承**
- B1　四型軸承**用同一根軸、同一個比例**畫，並排成四格。
- B2　滾珠那格**看得到鋼珠**；磁浮那格**軸與襯套之間有可見空隙**。
- B3　含油那格**軸與襯套直接接觸**；流體動壓那格**軸與襯套之間有一層油膜**且襯套上**有溝槽**。
- B4　四格的識別特徵**沒有任何一組互換**。

**Q 組・曲線與噪音**
- Q1　P-Q 圖上**同時有風扇曲線與系統阻抗曲線**，而且**交點被標成「工作點」**。
- Q2　軸流曲線的**風量端大於離心**；離心曲線的**靜壓端高於軸流**。畫成一樣或反過來＝不過。
- Q3　P-Q 圖的**座標軸沒有標任何數值**（§7-B1：查不到通用數字，只畫關係）。
- Q4　噪音示意圖上的尖峰落在**「葉片數 × 轉速」那個頻率與它的諧波**上，
      而且標籤寫出這個關係。

**W 組・風扇牆與模組**
- W1　風扇牆是**一排 ≥3 顆**，其中**一顆被標成備援（N+1）**。
- W2　導風罩畫成**把氣流圍起來**的薄殼，不是一塊擋板。
- W3　鰭片組是**一疊等距薄片**，而且圖上**至少兩種鰭距**可以對照。
- W4　熱管／VC 的剖面**看得出內部是空的**（與 `liquid_cooling.md` §6-P1 同一條）。

**M 組・辨識與邊界**
- M1　風扇**沒有被畫成家用電風扇**（沒有保護網罩、沒有立柱、沒有擺頭機構）。
- M2　**混合散熱對照格存在**，而且畫得出「冷板貼 GPU、氣流掃過其餘元件」。
- M3　液冷冷板**只出現在混合散熱對照格**，沒有變成主角。
- M4　圖上**沒有任何廠商 logo、產品外觀、料號或商標**。

**N 組・誠實性（紅線，違反任一條就退回，不進二輪）**
- N1　畫面上**沒有任何良率數字、成本金額、市占率百分比**。一個都不准。
- N2　畫面上**沒有任何風扇規格數字**（轉速、CFM、mmH₂O、dBA）——
      §7-B1 與 §7-C 已經說明這些查到的區間來源等級不夠。
- N3　畫面上同時有「示意圖，非實物比例」與「P-Q 曲線為示意，座標軸不標數值」兩行。
- N4　§7-B 裡標為低信心的每一項，畫面上**都沒有寫成確定的單一數值**
