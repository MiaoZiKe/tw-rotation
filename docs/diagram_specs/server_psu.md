## 0. 要不要 3D —— 判斷與理由（★ 這一段要先被簽掉）

**結論：不做真 3D。`SLOTS` 的 `scene` 留 `null`。**

判準照 AGENTS.md §11：「3D 只有在『轉一圈真的能多理解一件事』時才用」。逐項對：

| 這張圖要講的事 | 轉一圈會多理解嗎 | 判定 |
|---|---|---|
| 降壓的層級（AC → 54 V → 核心電壓） | **完全不會。** 這是**拓樸與數量級**，不是形狀。電壓不是空間 | 2D 階層圖 |
| 54 V 架構 vs 800 VDC 架構的差別 | 不會。差別在「**中間少了哪一級**」，那是兩張並排的階層圖 | 2D 對照 |
| PSU 的外型與熱插拔 | 不會。PSU 就是一個長條盒；轉一圈看到的是盒子的另外五面 | 2.5D 小圖足夠 |
| PSU 後端的卡緣連接器 | 不會。要講的是「它是**卡緣**不是電線」，2.5D 斜視一眼就看得出 | 2.5D 小圖 |
| 匯流排（busbar）是厚銅排不是電線 | 不會。厚薄關係在剖面上最清楚 | 2D 剖面 |
| 板上 DC-DC（多相降壓）長什麼樣 | 不會。要講的是「**一排電感成組排在晶片旁邊**」，那是俯視的排列 | 2D 俯視 |
| BBU 在掉電時撐幾秒、跟 UPS 的分工 | **完全不會。** 這是**時間軸**，不是空間 | 2D 時間軸 |
| 80 PLUS 效率等級 | 完全不會。那是一張表 | 2D 表格 |
| BBU／UPS 掛在電路的哪個位置 | 不會。這是**接在 AC 側還是 DC 側**的拓樸問題 | 2D 階層圖 |

**沒有任何一項通過「轉一圈能多理解一件事」的判準。**
這是三張裡**最不該做 3D 的一張** —— 它的內容本質上是一張**電力系統單線圖**，
而單線圖的價值就在於它把空間拿掉、只留下連接關係。

反面成本三條：
1. `site/three3d.js` 的 `SCENES` 是「零件排開」語彙；把 PSU、匯流排、BBU 排開，
   看到的是**三個方塊**，一個降壓級數都沒講到。
2. 3D 在手機吃力（AGENTS §11 明列）。
3. 每多一個 3D 場景就多一組 WebGL context 與 rAF 迴圈要管（`dispose3D()` 那條既有的坑）。

**什麼條件下才該回頭加 3D**（寫死，避免下次又變成事後補簽）：
> 只有當這張圖要新增「**機櫃背面匯流排與電源架的實體位置、以及銅排的實際體積**」
> 這一類**空間與體積**資訊（例如要讓人「看見」1 MW 機櫃那一大塊銅到底多大），
> **而且**確認既有的 `ai_server` 3D 機櫃場景無法承擔時，
> 才重開這一段、改規格書、重新簽。
> 「電流會流動所以做成 3D 比較生動」**不算理由** —— 流動是動畫，2D 一樣做得到。

## 1. 這張圖要回答什麼問題

畫面上要印出這三個問題（`q` 欄位取前兩個）：

1. **「牆上的電進來，到 GPU 核心的零點幾伏特，中間降壓幾次？每一級是誰做的？」**
2. **「BBU 是什麼？跟 UPS 差在哪？」**
3. **「為什麼要提出 800 V 高壓直流（HVDC）？」**

使用者看完要能自己講出這四句：

1. **電是一級一級降下來的**：交流電進來 → PSU 整成直流的幾十伏特 →
   走機櫃背面的**銅排** → 到托盤上再由**板上 DC-DC** 降到晶片核心要的零點幾伏特。
   **每一級都會損失一點，所以每一級的效率都是錢。**
2. **效率等級（80 PLUS）管的是 PSU 那一級**：從 Gold 到 Titanium，
   差的百分比看起來很小，但乘上整座機房的用電，差距就出來了。
   **CRPS** 則是把 PSU 的**尺寸、連接器與管理介面**標準化，讓不同家的可以互換、熱插拔。
3. **800 V HVDC 要解決的是「銅」與「轉換次數」**：機櫃功率往上爬之後，
   同樣的功率用越低的電壓送，電流就越大、銅排就要越粗。
   把電壓拉高就能用更細的銅送同樣的功率，同時省掉中間幾次 AC／DC 轉換。
4. **BBU 不是小一號的 UPS，兩者位置不同**：
   **BBU 裝在機櫃／伺服器裡、接在直流側**，反應快、撐的時間短；
   **UPS 是機房基礎設施、接在交流側**，撐到發電機起來。**兩者是互補的層級，不是替代。**

**這張圖的成敗**：Andy 指著架構圖上任何一級，要能說出
「這一級在做什麼、台股誰在做、它效率差一個百分點會怎樣」。講不出這句，圖就白畫。

## 3. 層別／流向順序（★ 最常錯，四組全部寫死）

### 3-A 供電路徑（由外到內，這是主圖的主軸）

**現行架構（機櫃內約 50–54 V 直流匯流排）**：

```
 設施側中壓交流電（例如 13.8 kV AC）
   │  ← 變壓器
 機房配電（數百伏特交流）        ←── UPS 掛在這一側（交流側，機櫃外）
   │
┌──────────── 機櫃（虛線框） ────────────┐
│ PSU／電源架：交流 → 直流約 50–54 V      │
│   │                                     │
│ 直流匯流排（厚銅排，沿機櫃背面）  ←── BBU／超級電容掛在這一側（直流側，櫃內）
│   │  ← 電源線組（power whip）           │
│ 運算托盤                                │
│   │                                     │
│ 板上 DC-DC／VRM：約 50–54 V → 晶片核心電壓（約 1 V 以下）
│   │                                     │
│ GPU／ASIC 晶片                          │
└─────────────────────────────────────────┘
```

**硬規則（違反其一就退回）**：
- **降壓不准跳級**：交流不可以直接連到晶片。
  圖上從最左到最右，**每一級都要有一個方塊**。
- **電壓標示由左到右單調遞減**（交流 → 幾十伏特直流 → 零點幾伏特）。
- **匯流排畫得比任何訊號線粗**，而且是**實心厚排**不是圓線。
- **板上 DC-DC 畫成「一排等距元件」**（多相），不是單一個方塊。
  畫成一顆＝看不出「多相」這件事。

### 3-B BBU 與 UPS 的位置（★ 這是這張圖的決定性結構，最常被畫錯）

| | 掛在哪一側 | 在機櫃裡還是外 | 時間尺度 |
|---|---|---|---|
| 超級電容／LIC | **直流側** | 櫃內（電源架／托盤） | 毫秒級（吸收瞬間電流尖峰） |
| **BBU** | **直流側** | **櫃內** | 秒到分鐘等級（§7-B3：來源差異大） |
| **UPS** | **交流側** | **櫃外（機房基礎設施）** | 撐到發電機起來 |
| 發電機 | 交流側 | 廠區 | 長時間 |

**硬規則**：
- **BBU 一定畫在直流側、機櫃虛線框裡面**。畫到交流側或框外＝**直接退回，不進二輪**。
- **UPS 一定畫在交流側、機櫃虛線框外面**。
- **機櫃虛線框一定要存在**，不然「櫃內／櫃外」這個差別就沒有畫面上的依據。
- 時間軸（9）上四者的**順序由短到長：超級電容 → BBU → UPS → 發電機**，
  而且**座標軸不標具體秒數**（§7-B3：三個來源給的數字互相矛盾）。
- **不准把 BBU 畫成「小一號的 UPS」**（同一個符號縮小）——
  它們接的位置不同，符號也要不同。

### 3-C 兩種架構並排對照（★ 不准混成一張）

| | 現行（機櫃內約 50–54 V） | 800 VDC |
|---|---|---|
| 進機櫃前 | 交流 | **直流 800 V**（在機房周界就整流好） |
| 機櫃內的電源架 | **有**（交流 → 50–54 V 直流） | **沒有這一級** |
| 匯流排 | 50–54 V，**粗** | 800 V，**細** |
| 托盤上 | DC-DC → 核心電壓 | DC-DC → 核心電壓（級數可能不同） |

**硬規則**：
- **兩欄並排、各自完整**，中間畫一條分隔線。混成一張＝不過。
- **800 VDC 那一欄的方塊數必須比現行那一欄少**（少掉的就是省下來的轉換級）。
  兩欄方塊一樣多＝這張對照就沒有意義。
- **800 VDC 那一欄的匯流排畫得比現行那一欄細**，
  而且**兩欄的匯流排要用同一個比例尺**，不然粗細比不出來。
- 800 VDC 那一欄要標**時程**，而且時程**要寫成「依公開資料，2027」而不是現在式**
  （§7-A6；`supply_chain.yaml` 的 `hvdc_800v` 節點也是這個口徑：「Vera Rubin 世代硬規，2027 才真正放量」）。

### 3-D 底部流程列（由左到右，5 格）

1. **交流進**：設施配電（＋UPS 在這一格之外）
2. **PSU／電源架**：交流 → 直流
3. **匯流排**：櫃內直流分配（＋BBU 掛在這一格）
4. **板上 DC-DC／VRM**：降到核心電壓
5. **晶片**：GPU／ASIC

**硬規則**：格 1 與格 2 之間要畫一條**分界線**，標
「**這條線的左邊是機房基礎設施（不在這條產業鏈上），右邊才是這條鏈上的東西**」。
這是整張圖在產業鏈上的意義所在（也是 §7-D1 不掛 `data-seg` 的原因）。

## 4. 一定要有的識別特徵

看到這些才認得出這是伺服器電源，而不是一張隨便的方塊流程圖：

- **PSU 是長條盒，前面有把手與風扇孔，後端是卡緣連接器（金手指）**。
  後端畫成一束電線＝認不出是 CRPS 型的伺服器 PSU。
- **PSU 是多顆並排且可抽換**（熱插拔），其中要看得出 **N+1** 的意思。
- **匯流排是厚銅排**，剖面是扁的實心條，**明顯比任何訊號線粗**。
- **板上 DC-DC 是一排等距電感**，沿著晶片一側或兩側排開（多相）。
  這是 VRM 在真實板子上最好認的特徵。
- **機櫃虛線框存在**，而且 **UPS 在框外、BBU 在框內**。
- **兩張架構並排，而且 800 VDC 那一欄少一個方塊、匯流排更細**。
- **時間軸上四段由短到長**，而且**沒有標秒數**。
- **效率等級表只有三列**（Gold／Platinum／Titanium），
  而且**標明是 230 V、50% 負載、以及「冗餘型」或「非冗餘型」哪一套**（§7-B1）。

**三塊固定說明框（這張圖的結論，不可省略）**：

- 左下「**為什麼每一級的效率都是錢**」：
  1. 電從牆上到晶片要經過好幾級，**每一級都有損耗，而且是連乘的**。

  3. 所以資料中心願意為更高的效率等級付更多錢，也願意為了少一次轉換而改整套架構。
