## 0. 開畫之前要先簽掉的三件事

### 0-A　要不要 3D —— 結論：**不做真 3D**

| 這張圖要講的事 | 轉一圈會多理解嗎 | 判定 |
|---|---|---|
| **TSV 貫穿每一層顆粒** | **不會，而且轉了更糟。** TSV 是「一根貫穿的柱子」，這件事只有剖面看得到；透視一進來，第一個被外層 die 擋掉的就是它 | **2D 剖面（這是本圖的核心）** |
| **邏輯晶粒在最底層** | 不會。那是剖面上的上下關係 | 2D 剖面 |
| **微凸塊夾在每兩層之間** | 不會。那是剖面上的一排小點 | 2D 剖面 |
| **混合鍵合沒有微凸塊** | **不會。** 那正是「兩層之間少了一排東西」，剖面對照最清楚 | 2D 兩格並排 |
| **HBM 與 GPU 並排在中介層上** | **會一點點**（平面配置是二維的），但既有的 `semiconductor()` 鏈層級總圖**已經有一個 3D 場景在畫這件事**了 | **2D 系統剖面 ＋ 一個小俯視格** |

反面成本三條：
1. 本圖六個資訊點裡有五個是「剖面上的層與孔」，3D 會把它們全部擋住。
2. `semiconductor` 這條鏈**已經有一個 3D 場景**（`SCENES.semiconductor`，畫的正是 CoWoS 封裝），
   再開一個就多一組 WebGL context 與 rAF 要管。
3. 層厚差好幾個數量級（TSV 直徑是 µm 級、堆疊高度是百 µm 級），3D 渲染時細節會消失在像素裡。

**什麼條件下才該回頭加 3D**（寫死）：

> 只有當這張圖要新增「**一片中介層上多顆 HBM 與 GPU 的平面佈局，以及中介層裡的繞線路徑**」
> 這種**同時需要平面位置與垂直層數**的資訊時才重開。
> **而且那件事既有的 `SCENES.semiconductor` 已經在做了** —— 正確的做法是去補那一個場景，不是在這裡開第二個。

### 0-B　這張圖與既有三張的交界（★ 這一段是這份規格書存在的理由）

## 1. 這張圖要回答什麼問題

**「HBM 為什麼要疊？TSV 跟微凸塊各做什麼？最底下那顆為什麼是邏輯晶粒、而且是台積電做的？台股在這條鏈上到底站在哪裡？」**

使用者看完要能自己講出這四句：

1. **HBM 是「把多顆 DRAM 疊起來、用一根根穿透的孔連成一整塊」。**
   每一顆 DRAM 之間靠 **TSV（穿矽孔）** 上下導通、靠 **微凸塊** 接起來（§7-A1）。
2. **最底下那顆不是記憶體，是邏輯晶粒（base die / buffer die）。**
   它負責對外的介面與控制，上面的記憶體晶粒都透過 TSV 跟它交換資料與控制訊號（§7-A1）。
3. **那顆邏輯晶粒是找晶圓代工廠做的。**
   SK hynix 的 **HBM4 base die 採台積電 12 奈米邏輯製程**；下一代 HBM4E 的 logic die
   正在評估 3 奈米（§7-A3）。**這是台股在 HBM 本體上唯一一個查得到的具名位置。**
4. **台股沒有 HBM 顆粒廠。** HBM 顆粒由 SK hynix、Micron、Samsung 做（§7-A4）。
   台股在這條鏈上的位置是**邏輯晶粒代工、堆疊前的測試（探針卡）、製程設備**（§7-D2）。
   ⚠ **南亞科明確表示看淡 HBM、改押地端 AI 記憶體；力成做的是記憶體封測但明確「非 HBM 本體」**
   —— 這兩句是 `supply_chain.yaml` 自己寫的，**圖上不准把它們畫在 HBM 顆粒上**（§3-D T1）。

**這張圖的成敗**：Andy 指著堆疊裡任何一層，要能說出
「這一層是什麼、**是誰做的**、台股碰不碰得到」。第三句講不出來，圖就白畫。

## 3. 層別／順序（★ 可判定的條目）

### 3-A HBM 堆疊：六條硬規則

```
 ┌ 頂層 core die（上面沒有東西了）
 │ 微凸塊 ── core die ── 微凸塊 ── core die ── …（重複）
 │ 微凸塊
 └ ★ base / logic die（最底下）
      ↓ 對外凸塊 → 中介層
```

- **H1**　★★★ **邏輯晶粒（base die）在整疊的最底下。**
      把它畫在中間或最上面＝**直接退回，不進二輪**。這是 HBM 結構的定義（§7-A1）。
- **H2**　★★★ **TSV 必須貫穿 base die 與其上每一層 core die**，形成一根由下到上連續的柱。
      **只畫在最上層、只畫在最下層、或只畫在某一層＝退回。**
      ⚠ 唯一的彈性：**最頂層 die 的 TSV 畫或不畫都可以**（上面沒有東西要接），
      但**不可以只有最頂層有 TSV** —— 那把整個結構畫反了。
- **H3**　★★ **微凸塊夾在「每兩層 die 之間」**，不是只在最底下一層。
      一疊 N 層 die 就有 N−1 排微凸塊（外加 base die 底下那一排對外凸塊）。
- **H4**　★ **TSV 與微凸塊上下對齊**，形成一條連續的導通柱。
      TSV 畫在 A 位置、微凸塊畫在 B 位置、兩者不對齊＝電氣上接不起來。
- **H5**　★ **core die 每一層的厚度與顏色相同**（它們是同一種晶粒）；
      **base die 用不同的顏色，而且畫得比 core die 厚一點**（H1 的視覺保險）。
- **H6**　★ **至少畫 4 層 core die**（少於 4 層看不出「堆疊」這件事），
      並標「本圖畫 N 層示意；實際層數依世代而定」（§7-B1）。

### 3-B 兩種接合放大格

- **B1**　★ **微凸塊那格有一排凸塊；混合鍵合那格沒有凸塊。**
      兩格都畫凸塊＝這一區就沒有存在意義了。
- **B2**　混合鍵合那格的兩層之間**只有一條接合界線**（銅對銅直接接），不是一層膠。
- **B3**　兩格的 die 用**同一個顏色與厚度**（是同一種晶粒，只有接法不同）。

### 3-C 系統剖面

- **Y1**　★ 由下到上必須是 `載板 → 中介層 → 晶粒`。順序顛倒＝退回。
- **Y2**　★★★ **HBM 堆疊與 GPU 都站在中介層上、左右並排。**
      **把 HBM 疊在 GPU 上面＝直接退回** —— 那是完全不同的封裝架構，而且會讓讀者以為 HBM 是 3D 疊在運算晶粒上。
- **Y3**　俯視小格：**GPU 在中間、HBM 在兩側**，數量對稱。
- **Y4**　中介層裡的繞線要畫得出「**細密、而且連著 GPU 與 HBM**」——
      那是中介層存在的理由。畫成一塊空白的板子＝少了核心資訊。
- **Y5**　★ **區 C 不准畫補強環、模封、載板的內部層數** —— 那是別張圖的範圍（§0-B）。

### 3-D 台股標示帶

- **T1**　★★★ **2408 南亞科與 6239 力成不可以被畫在「HBM 顆粒」或「堆疊封裝」那兩段上。**
      依據是 repo 內 Andy 校訂過的 `supply_chain.yaml`：
      南亞科的 note 明寫「**明確表示看淡 HBM、改押地端 AI 記憶體**」；
      力成的 `tech` 明寫「**記憶體封測（非 HBM 本體）**」。
      把它們畫上去＝在公開網站上宣稱兩家做 HBM，**直接退回，不進二輪**。
- **T2**　★★ **第 ① 段與第 ③ 段必須是紅章，並且寫出「實際上是誰做的」**（R4）。
      只寫「台股沒有」＝留白，讀者會以為漏了。
- **T3**　★ **第 ② 段（base die）必須指名台積電**，並附「來源：產業媒體，2026」與「12nm／HBM4」這個限定，
      **不准寫成「台積電做 HBM」** —— 它做的是**那顆邏輯晶粒**，不是記憶體顆粒。
- **T4**　第 ⑤ 段（製程設備）標**黃章（信心不足）**，因為只有單一來源（§7-B4）。

## 4. 識別特徵 ＋ 最常見的畫錯

### 4-A 一定要有的識別特徵

- **HBM 堆疊**：**最底下一顆不同色的 base die** ＋ **一根根貫穿到底的 TSV** ＋ **每兩層之間一排微凸塊**。
- **混合鍵合格**：**兩層之間什麼都沒有**（只有一條界線）。
- **系統剖面**：**GPU 與 HBM 並排站在中介層上**。
- **台股標示帶**：**至少兩段是紅的**。

### 4-B 最常見的畫錯

| # | 畫錯的樣子 | 為什麼是錯的 | 對應審查 |
|---|---|---|---|
| 1 | **邏輯晶粒畫在最上面或中間** | HBM 的定義就是「多顆 DRAM 疊在最底層的 buffer die 上」 | **H1（紅線）** |
| 2 | **TSV 只畫在最上層那顆** | 那樣下面的顆粒就沒有導通路徑，整疊是斷的 | **H2（紅線）** |
| 3 | TSV 只畫在 base die 上 | 同上，上面的 core die 連不出來 | **H2（紅線）** |
| 4 | 微凸塊只畫在最底下一排 | 每兩層之間都要有；只有一排＝上面幾層是浮著的 | H3 |
| 5 | TSV 與微凸塊沒有上下對齊 | 電氣上接不起來，讀者會以為它們是兩套獨立的東西 | H4 |
| 6 | base die 跟 core die 同色同厚 | 讀者分不出「最底下那顆不是記憶體」——本圖第 2 句話就沒了 | H5 |
| 7 | 只畫 2～3 層 | 看不出「堆疊」 | H6 |
| 8 | **HBM 疊在 GPU 上面** | 那是完全不同的架構。HBM 是**並排**在中介層上 | **Y2（紅線）** |
| 9 | 中介層畫成一塊空白的板子 | 中介層的價值就是裡面那些細密繞線 | Y4 |
| 10 | **把南亞科或力成畫在 HBM 顆粒上** | 兩家的既有資料明確排除這件事 | **T1（紅線）** |
| 11 | 台股標示帶全綠 | 把「台股沒有 HBM 顆粒廠」這個最有價值的資訊藏起來了 | T2 |
| 12 | 寫成「台積電做 HBM」 | 它做的是 base die（邏輯晶粒），不是記憶體顆粒 | T3 |
| 13 | 把 CoWoS 的補強環、模封畫進來 | 越界到別張圖，而且會把主角擠掉 | Y5 |

## 9. 給 `tech-illustrator` 的實作邊界

- **先畫堆疊、先把 TSV 那一根柱子從最底畫到最頂**，再補其他三區。
  **TSV 用一個 `for` 迴圈從 base die 底面一路畫到頂層底面**（H2 在程式層面就成立）；
  手刻每一層的 TSV 一定會漏掉一層。
- **微凸塊也在同一個迴圈裡畫**，而且**x 座標用同一個陣列** —— 這樣 H4（對齊）自動成立。
- **base die 用不同的 `fill` 與不同的高度常數**（例如 `H_BASE = H_CORE * 1.4`），
  不要用同一個常數再手動改一個數字（H5 的程式層面保險）。
- 層數用一個常數 `N_CORE`（建議 6），**旁邊的層數說明文字要從同一個常數產生**，
  不要一個是畫的、一個是寫死的文字（改層數時兩邊會分叉）。
- 區 C 的系統剖面**刻意畫小、刻意畫簡單**。
  它只要能被一眼看懂「HBM 在 GPU 旁邊」就夠了 —— **任何多加的細節都會跟既有的 CoWoS 圖打架**（Y5）。
- 台股標示帶的三種章用**形狀 ＋ 顏色雙編碼**（紅＝三角、黃＝方、綠＝圓），
  四個配色下顏色會變、形狀不會。
- 顏色一律走 `--dg-*` / `var(--c)`，不准寫死 `#xxxxxx`。
  ⚠ **base die 的顏色不可以直接吃 `var(--c)`** —— 它掛的是 `foundry` 環節，
  環節色會讓它跟 core die 的 `hbm` 環節色自動不同，**但那是巧合不是設計**。
  請 `art-director` 指定一組本圖用的 `--dg-*`（core 一色、base 一色、TSV 一色、凸塊一色），
  讓色差在四個配色下都守得住。
- **`data-part` 一律要寫**。建議命名：
  `hb_base` / `hb_core` / `hb_top` / `hb_tsv` / `hb_ubump` / `hb_fill` / `hb_outbump` /
  `hb_hybrid` / `hb_interposer` / `hb_sub` / `hb_gpu` / `hb_probe` / `hb_equip` / `hb_stack_pkg` /
  `hb_band1` … `hb_band5`。
- 動畫：只做一件事 —— **一個資料點沿著 TSV 由頂層往下跑到 base die、再橫向跑進 GPU**。
  那正好把這張圖的兩個命題（垂直貫穿、橫向並排）一次講完。
  **不要讓層跑來跑去。** 靜止時 TSV 與凸塊仍看得見。
- **SVG 的 `<style>` 裡（含註解）一律不准出現角括號。**
