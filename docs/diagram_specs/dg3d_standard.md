# dg3d_standard：3D 剖析圖的細緻度與配色標準（圖九，樣板）

> 這是**樣板規格**。Andy 2026-09-19 的順序是「圖九當樣板確認配色與細緻度標準，
> 再量產圖11（MLCC、面板疊層、交換器板卡、輕油裂解、變壓器/GIS…）」。
> 所以這一份不只描述圖九，它同時是後面每一張 3D 圖的**共同驗收條件** ——
> 量產時每張圖再寫一份自己的 `<id>.md`，只寫「零件清單／層別順序／識別特徵／標註」四段，
> 這四項共同條件不用重寫，直接引用這份。

- **id**：`dg3d_standard`
- **放在哪**：`#industry/<chain>` 的 `#dg3d` 場景（`site/three3d.js` 的 `SCENES`）
- **型式**：真 3D（已經是了；這次做的是細緻度與配色，不是換型式）
- **現況**：`ai_server`（AI 伺服器機櫃 NVL72 式，16 個零件）、
  `semiconductor`（CoWoS-L 先進封裝剖面，11 個零件）

## 1. 這張圖要回答什麼問題

「這條產業鏈上，**台股那幾檔到底做的是機櫃裡的哪一塊**，那一塊長什麼樣、在整台機器的哪個位置。」

所以圖九的成敗不是「渲染得漂不漂亮」，而是 **Andy 能不能指著某一塊說「這是欣興做的」**。
三件事都是為這句話服務的。

## 2. 這次要補的三件事（Andy 原話）

### 2-1 走線 / 電流 / PIN 腳的細緻度

現在每個零件都是「一個方塊加一點特徵」，少了三種**讓人一眼認出是電子零件**的東西：

| 要補 | 加在哪 | 識別特徵（缺了就不算做到） |
|---|---|---|
| **PCB 走線** | `kind: 'pcb'`、`'substrate'`、`'backplane'`、`'tray'` | 表面要有蛇行等長線（差動對成雙）、直角一律走 45°、線寬一致；不是隨機亂畫的線 |
| **PIN 腳 / 接點** | `kind: 'balls'`（BGA）、`'optic'`（金手指）、`'psu'`（匯流排端子）、新增 `'conn'` | BGA 要成陣列且看得出球狀；金手指要成排、鍍金色、有倒角；電源端子要看得出螺絲孔或匯流排厚度 |
| **電流 / 訊號流動** | 沿走線跑的粒子 | 只在「動態模式」時跑；靜止時走線本身仍然看得見。方向要對：電源由下往上、訊號由 GPU 往背板、光訊號往前面板 |

**做法限制**：不准為此引入新的 3D 函式庫（`vendor/` 已有 Three.js，Andy 公司網路擋 CDN）。
走線用 `TubeGeometry` 或貼圖皆可；粒子用 `Points` + 一個 shader-less 的位移即可，
**不准掉幀**，頁面切走要停 rAF。

### 2-2 三種配色

Andy 要「三種配色」。定義成三個**具名色票**，由 `art-director` 擁有，
全部寫成 `--dg-*` CSS 變數，**JS 不准寫死任何 `#xxxxxx`**：

| 色票 | 給誰看 | 調性 | 背景 | 主色 | 發光 |
|---|---|---|---|---|---|
| `tech` | 預設 | 深色科技風（現況） | 深藍黑 | 青 | 只給選取中的零件 |
| `soft` | 拿去給客戶看 | 淺底、印得出來 | 米白 | 靛藍 | 無 |
| `calm` | 長時間盯盤 | 低飽和深灰 | 石墨灰 | 琥珀 | 極弱 |

**三種都要在深色與淺色主題下各驗一次**（`applyTheme()` 切換時色票要跟著重算，
這正是目前淺色主題一堆白字白線的根因 —— 顏色寫死在 JS 裡，`refreshPalette()` 換不掉）。
切換鈕要看得見、切了畫面真的變（不是只有變數改了）。

### 2-3 文字框 → 個股晶片

現在標籤是 `<b>零件名</b><i>說明</i>`（`site/three3d.js` 的 `lbl3d`），
**是死的文字**。要改成：說明下面掛一排**該環節的台股晶片**，點了進個股頁。

- 資料來源：`supply_chain.yaml` 的 `companies`，用零件上的 `seg` 去比對 —— **這份資料已經在前端了**
  （`industry.js` 的 `twOf(sc, seg)`），不用新增任何抓取。
- 晶片顯示：`名稱 代號`，最多 4 檔，超過就 `+N`。點晶片 → `A.goStock(code)`。
- 該環節台股掛零（`hyperscaler`、`hbm`）→ 寫「台股無直接對應」，**不要留空**。
- 晶片是 DOM，不是畫進畫布 —— 這樣文字重疊驗得到、也選得起來（現有 `lbl3d` 就是這個理由）。

## 3. 共同驗收條件（量產圖11 時每一張都要過）

這一段是**所有 3D 剖析圖的共同條件**，寫在這裡，後面每張圖的規格書直接引用。

- **結構**（`mechanical-engineer` 簽）：層別／流向順序與規格書一致；每個零件的識別特徵都在；
  相對尺寸沒有離譜；不確定的地方畫面上標「示意圖，非實物比例」。
- **視覺**（`art-director` 簽）：三種色票 × 深淺主題都看得見；字級 ≥ 12px 且縮放不變小；
  **1440px 與 800px 各驗一次**，文字不重疊、不出框；一張圖一個主色；發光只給選取中的零件。
- **互動**（`_uitest.py` 真的操作）：轉得動、可平移、**360 度含底部**（N1 已完成）；
  點零件會選起來且標籤同步；點標籤上的個股晶片真的跳到個股頁；
  動態／靜止切換鈕按了真的停下來／動起來；換色票畫面真的變。
- **效能**：不掉幀；頁面切走停 rAF；不新增 3D 函式庫、不新增 CDN。
- **不畫**任何真實公司的產品外觀、logo、包裝、商標。

## 4. 已知不確定的地方

- NVL72 的**實際內部排列**（托盤數、背板位置）依公開資料，屬**示意**，畫面上要標。
- CoWoS-L 的 **RDL / LSI 厚度比例**是示意，不是實物比例。
- `calm` 色票的琥珀主色與紅漲綠跌**不得混用** —— 漲跌色是 CSS 另一組變數，不在 `--dg-*` 裡。

## 5. 2026-09-26 細緻化：全場共用的四件事（3D 設計專責）

Andy 2026-09-26：「所有的 3D 圖基於現有圖，把細節部分描繪更多，需要更細緻、更貼近當前產品，而非看起來就是個長方塊、隨便拉的管線」。
這一節是**所有場景共用**的引擎層改動（`site/three3d.js`），逐張的細節寫在各自規格書的「§3D-細節」。

| 改動 | 做法 | 成本 |
|---|---|---|
| **倒角** | `box()`／`mboxes()` 一律改成單段 45° 倒角方塊（`chamferGeo`，44 個三角形）；最小邊 < 0.12 仍用直角方塊。稜線在環境貼圖下會亮成一條細線 —— 「這是加工出來的東西」的第一個訊號 | 每顆 +32 個三角形，draw call 不變 |
| **微表面** | `microfy()`：一張程序化 128² 雜訊（R 顆粒／G 髮絲紋／B 玻纖布紋／A 大塊起伏），在 shader 裡依**物件座標三向投影**取樣，擾動法線＋微調粗糙度。金屬（metalness ≥ 0.6）走髮絲紋、陶瓷走燒結顆粒、樹脂／模封走填料顆粒、PCB 走布紋、矽幾乎鏡面、玻璃不加 | 每像素 3 次貼圖取樣；0 draw call、0 三角形；不載任何外部圖檔、不走 CDN |
| **輪廓光** | 同一段 shader 的 Fresnel 邊光：科技模式 +0.06（亮邊）、閱讀模式 −0.05（壓暗，像線稿外框）；token `--dg-rim-k` 可覆寫 | 同上 |
| **流線** | `flowPath()` 管徑從 `r` 降到 `0.3r`（最細 0.06）＋沿路徑 2～6 個方向箭頭（`dir`／`bidir` 決定朝向；交流一正一反）；粒子縮小 | 每條流線 +1 draw call（箭頭是一個 InstancedMesh） |
| **晶粒版圖** | `die` 共用件的頂面改成一張通用示意的版圖貼圖（核心／SRAM／I/O 墊／封環，canvas 產生、灰階、顏色仍由 token 決定）＋金屬封環 | draw call 從 6 降到 4 |

效能上限（本輪起的共同驗收）：每張場景 **≤ 150,000 三角形、≤ 300 draw call**；首次畫圖時間不得比改之前慢超過 30%；
由 `_uitest.py` 的「3D細緻化效能」段落逐張量。版圖是通用示意，不照任何真實晶片畫（AGENTS.md 紅線）。

補充（同日第二批）：

| 改動 | 做法 |
|---|---|
| **流線跟著零件拆開** | 流線掛在哪個零件上，爆炸拆解時就跟那個零件走同一個位移（以前是寫死的世界座標，零件一拆開流線就懸在半空中）；收攏時位移為 0，跟以前一樣 |
| **扇葉** | 機櫃風扇與氣冷轉子：七塊斜放方塊改成彎刀形葉片（葉根窄、葉尖後掠、邊緣倒圓、有攻角），七片烘成一個幾何 |
| **晶圓疊** | 每一片都是帶 notch 的倒角圓片（`notchDiscGeo`，跟晶圓代工那張同一支） |
