# 功能更新公告（site/notices/features.json）

> Andy 2026-10-19：「新增功能需要有通知給其他人」。

## 規則（一條）

**每次把「使用者看得到的新功能」推上 main，同一個 commit 要在 `site/notices/features.json` 加一則。**

- 為什麼放 repo 而不是用管理區發：管理區 `#admin/notices` 要管理者身分登入才能發，推功能的人沒有；
  而且公告跟功能放同一個 commit，功能上線的那一刻公告就一起上線，不會「功能上了、公告忘了發」。
- 不用發的：純修 bug（使用者本來就以為它該這樣）、純資料更新、只動文件或驗收腳本、管理區專屬的功能
  （真的要讓登入會員知道就用 `"aud": "member"`）。
- deployer 推之前會檢查這一條（`.claude/agents/deployer.md` ① 第 4 點）。

## 一則長這樣

```json
{
  "id": "f-20261019-ssd-3d",
  "date": "2026-10-19",
  "aud": "all",
  "title": "新增 SSD 3D 剖析圖",
  "body": "記憶體模組族群新增一張 SSD 3D 剖析圖……\n去看：[SSD 3D 剖析圖](#industry/semiconductor/dg/memory_module)"
}
```

| 欄位 | 必填 | 寫法 |
|---|---|---|
| `id` | 是 | `f-YYYYMMDD-<英文小寫與減號>`，全檔不可重複。不符格式的那則前端直接不收。已讀狀態跟著 id 走 —— **上線後不要改 id**，改了所有人會再看到一次未讀 |
| `date` | 是 | `YYYY-MM-DD`（台北日期），鈴鐺與公告頁照它排序、顯示 |
| `title` | 是 | ≤ 30 字，一句話講「多了什麼／變成怎樣」 |
| `body` | 是 | 給一般使用者看的白話：改了什麼、去哪裡看。換行用 `\n`。**不寫技術細節**（檔名、函式、驗收段落），**不提 Claude／agent** |
| `aud` | 否 | `all`（預設，所有人含訪客）／`member`（登入會員）／`paid`（付費方案與管理者） |
| `pinned` | 否 | `true`＝未讀的人開站時頁首出現橫幅。少用：橫幅會把每一頁往下推，只給「大家一定要知道」的 |

新的一則加在陣列**最前面**（同一天多則時，排前面的顯示在前面）。

## 內文可以放的連結

內文是純文字，前端一律先跳脫（寫 `<b>`、`<script>` 都只會顯示成字）。可以用的連結只有三種：

- `[顯示的字](#路由)` → 站內連結，例如 `[資金流向](#flow)`。**優先用這種**，一般人看不懂 `#flow/rotation`。
- 單獨寫 `#路由` → 原樣當站內連結。
- `https://…` 網址 → 外部連結（開新分頁）。

路由寫之前先在本機點一次，確認那一頁真的存在。

## 前端怎麼吃（給改 notices.js 的人）

- `site/notices.js` 開站抓一次 `notices/features.json`（`cache: no-cache`），跟會員伺服器的公告併成同一份清單（置頂在前、日期新的在前）。
- 鈴鐺只要有任何公告就出現 —— 沒有會員伺服器的環境（訪客、預覽站）也看得到功能更新。手機放在頂欄搜尋鈕右邊（`#m4Tools`）。
- 這類 id 的已讀只存 localStorage（`tw.notice.read`），登入者也一樣，不送 `/v1/notices/read`（會員伺服器不認得這些 id）。
  代價：登入者換一台裝置，功能更新會再顯示一次未讀。
- 驗收段落：`python scripts/_uitest.py --sections 功能公告1019`。它會檢查每一則的 id 格式、標題字數、內文沒有技術字眼。
