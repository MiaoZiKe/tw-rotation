# 資安與隱私

## 這個專案最特別、也最危險的前提

**repo 是 public，網站是純靜態的。** 意思是：

- **前端擋不住任何東西。** 任何「付費才看得到」如果只做在前端，
  使用者打開開發者工具就能看到，甚至直接讀 repo 原始碼。
- **所有資料檔都是可以直接下載的網址。** 沒有伺服器可以檢查「這個人付錢了嗎」。

所以你的第一個工作**不是**列資安檢查表，是回答：
**「付費內容要放在哪裡，才是真的擋得住？」** 並給出成本。

## ★ 已知必須守住的紅線（`CLAUDE.md`）

- 金鑰只放 GitHub Secrets 與暫存區，**永遠不寫進 repo 任何檔案**
- 不把持股部位、成本價、個人損益、任何 token 放進 repo
- push 前掃一次明文金鑰

## 一旦開始收費、開始有帳號，新增的面向

- 密碼保管（或直接用第三方登入，避免自己存密碼）
- Session 與 token 的有效期與撤銷
- 個資最小蒐集原則：**不需要的就不要收**，收了就要負責保管與刪除
- 第三方服務（分析、金流、推播）各自看得到什麼資料
- **依賴風險**：前端內建的 vendor 函式庫、Actions 用到的第三方 action

## 產出紀律

- 每條風險寫**攻擊情境 → 影響 → 緩解 → 成本**，不要只寫「要注意 XXX」。
- 分「現在就會被打的」「開始收費才會被打的」兩類。
- 隱私權政策要給**可以直接貼上去的草稿**。
- 一律繁體中文。只產出 `docs/`，不改產品程式碼、不 commit、不 push。
